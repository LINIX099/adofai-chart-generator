# 13 · TUF 语料 + 真 · EX 标尺

> 起因：「去论坛找找明显通关人数较高的谱面，下载下来看看。」
> 目标：把「真人怎么写谱」的样本从 9 张 / 4365 格扩到有统计意义的量，
> 并且**修掉两个让之前所有对照数据失真的 bug**。

## 一、两个必须先说的 bug

### bug ① 语料速度读错（`speed` 字段不存在 + Multiplier 是累乘）

```python
# 旧写法（tools/_mine_patterns_v4.py 等 4 个脚本）
ev[floor] = float(act.get("speed", 1.0))      # ← SetSpeed 事件里根本没有 speed 字段
```

真实写法：

```json
{"floor":77,"eventType":"SetSpeed","speedType":"Multiplier",
 "beatsPerMinute":100,"bpmMultiplier":2,"angleOffset":0}
```

倍率在 `bpmMultiplier`。所以以前那份「音值直方图」其实是 `travel/180` 直方图，
和速度无关 —— 「人类只用 1/4 整数倍音值」这条结论是拿错尺子量出来的。

而且 **Multiplier 是累乘**。官方 decomp 权威实现（`_decomp\game\scnGame.cs`）：

```csharp
num48 = ((num49 <= 0) ? (bpm3 * num38 * num50) : (num48 * num50));
```

`vendor/adofai_timemodel/angle.py` 里 `current_bpm *= bpmMultiplier` 是同一件事。
**连续两个 2x 是 4x，不是 2x。** 旧代码赋值而不是累乘，也错了。

统一入口：**`tools/_speeds.py`**（两个坑都写在 docstring 里）。同 bug 的还有
`_multipress_runs.py`、`_analyze_multipress2.py`、`_grid_audit.py`。

### bug ② EX 语料一直是**碎片**在当权威

`adofaipumian\ex` 里 71 个 `.adofai`，旧解析器只能吃 11 个，而失败的正是真谱
（`level.adofai`，598KB / 539KB / 271KB / 243KB）。失败原因是**有人手改过的 JSON
缺逗号**：

```
... "eventTag": "" }
    ]
    "decorations":        ← `]` 和 `"decorations"` 之间没有逗号
```

写了个真正的修补器 **`tools/_jsonrepair.py`**（扫 token，见到值起点时看前一个有效
字符，该补逗号就补；字符串后面跟 `:` 就判定为键、不补）。

效果：

| 目录 | 修之前 | 修之后 |
|---|---|---|
| `adofaipumian\ex` | 11 / 71 | **71 / 71** |
| `adofaipumian` 全体 | 500 / 532 | **531 / 532**（剩 1 个是 macOS `._` 垃圾文件） |

修好之后才看清：`ex` 里 71 个文件有 **43 个是 20~70 格的子关卡碎片**。
之前的「EX 权威：9 谱 / 4365 格」就是碎片混着算出来的。

## 二、真 · EX 标尺

**13 张主谱 / 6366 格**（`ex/<n>-EX …/level.adofai`，一张用 `pathData` 没 `angleData` 的排除）。
复现：`python tools/ex_benchmark.py`

| 指标 | 真值 | 旧口径（碎片混算） |
|---|---|---|
| 直线 (180°) | **41.1%** | 45.2% |
| 多押 (Δt≤35ms) | **1.7%** | 2.3% |
| SetSpeed /100 格 | **1.35** | 1.35 |
| Twirl /100 格 | **3.53** | 2.13 |
| Pause /张 | 1.85 | 0.14 |
| midspin 占比 | 0.24% | 0.35% |
| 速度是 2 的幂 | **98.3%** | 99.1% |
| 音值落 1/12 网格 | **96.8%** | 97.4% |
| 单格时长中位 | 285.7 ms | 206.9 ms |

**EX 的风格特征**：极高比例的直线、极少的 Twirl、速度档 98% 是 2 的幂、
音值 97% 落在 1/12 网格。它是「官方关卡重制版」的那种**干净写法**。
用 `1x(57%) + 2x(40%)` 两个档就写完全曲。

## 三、TUF 论坛：API 与下载

论坛是 SPA + 开放 v2 API，OpenAPI JSON 在 `https://api.tuforums.com/openapi.json`。

| 端点 | 用途 |
|---|---|
| `GET /v2/database/levels` | 搜索谱面（`query` / `limit≤100` / `offset` / `page`） |
| `GET /v2/database/levels/{id}/level.adofai` | **直接下谱面** |
| `GET /v2/database/difficulties` | 难度表（P1~P20 / G1~G20 / U1~U20 / Quantum / …） |
| `GET /v2/database/passes` | 通关记录，`count` = 58622 |

坑：**`sort` 参数服务端直接忽略**（传什么都没用，永远按 id 倒序），排序只能在本地做。
所以 `tools/tuf_index.py` 把全库 15277 条拉下来存成 `corpus_tuf/_index.json`（46.7 MB）。

下载脚本：`tools/tuf_pick.py`（选题）→ `tools/tuf_download.py`（16 线程 + 走代理）。

代理：`set TUF_PROXY=127.0.0.1:7897`（默认值就是它；置空则直连）。

### 拿到的东西

`corpus_tuf/` —— **623 张 / 235.7 MB**，分三类：

| 组 | 条件 | 张数 |
|---|---|---|
| `band` | 难度 P3~P7（对齐 EX），clears ≥ 10 | 143 |
| `top` | 全库 clears 前 120（clears ≥ 50） | 118 |
| `clears20` | **全难度 clears ≥ 20** | 364 |

全库 clears 分布：`0` 8341 张 / `1-4` 4591 / `5-19` 1763 / `20-49` 370 / `50-99` 127 / **`≥100` 85**。

> **官方关卡（1-X、2-X、11-X…）TUF 上只有成绩条目，`fileId` 为空，`level.adofai` 一律 404。**
> 所以要拿官谱得去游戏文件里翻。用户已确认：不重要。

### 从这张表读出来的规律

1. **直线占比跟难度无关**，所有档位都稳定在 **28~46%**。它是一条"常量"，不是可优化的目标。
2. **多押、Twirl、SetSpeed 三个才是随难度单调上升的**：
   `多押 4%→28%`、`Twirl 7→27/100`、`SetSpeed 2.6→11/100`。
3. **1/12 网格对齐率随难度单调下降**：`P1 97.6% → P17 64.2% → U4 23.2%`。
   越高难越敢用歪角度。
4. **速度档位分布**：低难是 `1x 63%`，高难是 `4x 27% + 2x 25% + 1x 23%`。
5. **Pause 不随难度走**（0.5~9/张），是曲子里有没有长静音决定的，不是难度属性。

## 五、我们的输出在表里找不到位置

`out/` 重新生成后的三首：`直线 61.3% / 多押 0.0% / SS 4.27 / Twirl 18.11 / 2幂 100% / 1/12格 77.7%`

| 指标 | 我们 | 最近的真人档 | 差距 |
|---|---|---|---|
| 直线 61.3% | — | 最高档是 G7 44.2% / P8 46.0% | **比任何真人谱都直** |
| Twirl 18.11 | ≈ P12~P16（19.8~22.4） | 但那些谱直线只有 28~38% | 组合不成立 |
| 多押 0.0% | — | 最低是 EX 1.7% / P9 2.7% | **真人没有 0% 的** |
| 速度档 | `1x 63% + 0.5x 32%` | EX 是 `1x 57% + 2x 40%`；P5 是 `1x 63% + 2x 17% + 0.5x 5%` | **0.5x 用太多了，2x 几乎不用** |
| 1/12 网格 77.7% | — | EX 96.8% | 我们的角度/音值组合比 EX 更"歪" |

**一句话**：直线按 P8 以上写、Twirl 按 P14 写、多押完全不写、速度只用慢档 ——
这四个指标拼不出任何一个真人档位。

### 具体的病灶（按可操作性排）

1. **0.5x 占 32%**（真人 0.6~5%）。说明求解器把大量音值推到「慢一倍」，
   而真人的做法是**用更短的 travel**（90°、45°）而不是降速。
2. **2x 几乎不用**（我们 2.0%，EX 40%）。高难谱的"快"主要靠 2x + 180°，
   我们全靠缩短 travel 来做快。
3. **多押 0%**：三首样本里一个 Δt≤35ms 的格子都没有。真人最低也有 1.7%。
4. **Twirl 密度跟直线密度不自洽**：我们用 Twirl 去救那些扭转不开的地方，
   于是直线越多 Twirl 也越多（62% + 18/100），而真人正好相反
   （直线越多，说明是简单段，Twirl 越少）。
