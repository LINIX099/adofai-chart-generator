## 二、双押：归到「多轨」那条线（**后期**）

**你的原话：**「双押留给多音轨（社区做法）。如果说一个音轨在一个时间上有多个音，就采成双押，不过它是后续的事情。」

记录要点：

- 冰与火**没有官方双押方块**；社区做法是把同时的多个音写成 `30° · 330°` 一对
  （高 BPM 下 30° 夹角在直线段上就是双押）
- 所以双押应当由**多轨合并**产生：多条轨在同一时刻都有音 → 采成双押
- 也适用于单轨：同一条轨在同一时刻有多个音（和弦）
- **本轮不做**

### 补充：三押、四押也在（用户口径 + 实测）

**用户口径（本轮新增）：**

> 三押、四押也需要留意一下。夹角之间不足 30°（300+ bpm）时，可以直接按多押打
> （此时为**完美无瑕**）。低于 300 bpm 时最好使用 15°。

**实测验证**（295 张谱 / 794 765 层；工具 `tools/_analyze_multipress2.py`）

关键：`settings.bpm` 是**假 BPM**，必须乘上每层累计 `SetSpeed` 才是玩家真正听到的速度。

| travel | 样本 | 有效 BPM 中位 | 有效 BPM < 300 占比 | Δt 中位 | Δt ≤ 35ms |
|---|---|---|---|---|---|
| **15°** | 6 890 | 190 | **93.4%** | **26.3 ms** | 88.1% |
| **30°** | 60 380 | 230 | 70.0% | 43.5 ms | 31.0% |
| 45° | 8 088 | 200 | 68.4% | 75.0 ms | 22% |

- **15°** 几乎只出现在低 BPM（93.4% < 300），Δt 分布极窄（20–30 ms 占 62%）→ 它就是
  「把两个音压成一次按键」的专用写法
- **30°** 在高 BPM 大量出现，但 Δt 尾巴很长（≤35 ms 只有 31%）→ 30° 同时还是一个
  **真实节奏值**，不能一刀切地当多押
- 结论：**你的口径被数据证实** —— 同样的"同时"，≥300 BPM 用 30°（30° @300BPM = 33 ms），
  <300 BPM 降到 15°（15° @190BPM = 26 ms），两者都落在同一个判定窗口里

### 判定口径修正：用 Δt，不用固定角度集合

```
v    = (travel / 180) / speed          ← 音值，单位四分音符
Δt   = v × 60000 / BPM                 ← 这一格到下一格的真实间隔
多押 = Δt ≤ 35 ms                       ← 听感上「同时」
连续 n 个多押 gap → n+1 押
```

好处：`30°·330°` 那种 ±交替的锯齿（vibro）里，330° 那一格的 Δt 很大，会被自动排除；
而 `30° @300BPM` 这种真多押会被自动收进来。**比写死 `{15,30,330,345}` 干净。**

### 角度 ↔ 音值：你这套口径的本质

```
v = (travel / 180) / speed          单位：四分音符（一拍）
30° @ speed1 → v = 1/6 拍   （16 分三连）
15° @ speed1 → v = 1/12 拍
300 BPM 时 1 拍 = 200ms → 30° = 33ms   ← 落在判定窗口里 = 完美无瑕
190 BPM 时 1 拍 = 316ms → 15° = 26ms   ← 同上
```

所以「≥300 用 30°、<300 用 15°」的本质 = **用最小的两个音值去表达"同时按"**。

### 实测：三押 / 四押长什么样（`tools/_multipress_runs.py`）

Δt ≤ 35 ms 的 gap 共 **73 151 个 = 全部层的 9.20%**。

| 连续 gap n | 押数 | 处数 | 谱面 settings.bpm 中位 |
|---|---|---|---|
| 1 | 双押 | 30 214 | 320 |
| 2 | **三押** | **3 929** | 900 |
| 3 | **四押** | **1 514** | 1 010 |
| 4~8 | 5~9 押 | 1 373 | 2 021 |

**同向 vs ±交替**（n=2 时）：同向 3 773 处 vs 交替 156 处 → **真多押 96% 是同向**。
（±交替那族是锯齿 / vibro，Δt 判据已经自动把它们排除掉了）

**典型角度写法：**

| 押数 | 头部写法 |
|---|---|
| 双押 | `30°`(14946) · `15°`(4215) · `9°`(2980) · `45°`(1148) |
| 三押 | `90°·90°`(1411) · `15°·15°`(678) · `30°·60°`(450) · `30°·30°`(161) |
| 四押 | `30°·60°·90°`(365) · `1°·1°·1°`(134) · `90°·180°·90°`(94) |

> ⚠️ **假阳性警告**：谱面里有一批 `settings.bpm = 1000 ~ 10000` 的跳跃 / 加速谱，
> 它们的**每一格** Δt 都 ≤ 35 ms，于是整段都被算成"多押"（连 `180°·180°·180°`
> 都进来了）。所以多押判定还要补一条：**该段前后必须各有一格正常间隔**。

### 顺带：改成按音值挖之后（`tools/_mine_patterns_v4.py`）

| | v3（按 travel 挖） | v4（按音值挖 · 网格 1/12） | v4（网格 1/6） |
|---|---|---|---|
| 直线 | 37.8% | 37.8% | 37.8% |
| 多押 | 16.4%（写死角度集） | 7.0%（Δt 判据） | 7.0% |
| 需要模板 | 45.8% | 55.3% | 55.3% |
| **60 模板覆盖率** | **42.3%** | 29.1% | 33.1% |

结论：按音值挖更"真实"，但真实谱面的角度不干净（大量 `11/12`、`13/12` 这种毛刺，
就是手工谱随便拖出来的角度），覆盖率反而**更低**。
→ **模板 key 必须先做音值吸附（容差 ±1/12）**，否则模板会被毛刺冲散。

**对当前口径的影响：**

1. 节奏型挖掘里排除**多押 gap（Δt ≤ 35 ms）**
2. 单轨生成不产生多押（`merge_ms` 会把挨得近的音合并成一次按键）
3. 因此模板库里不会出现多押族 —— 两边口径一致
4. 多押本身（含三押、四押）留给**多轨**那条线

## 五、为什么模板里只需要设计 Twirl

```
travel = 180° × (Δt / 参考音值) / 速度档      ← 节奏一确定就锁死
转角   = ±(travel − 180°)                    ← 只有符号自由 = Twirl
朝向   = heading₀ + Σ 转角                    ← 长直线朝哪个方向，全靠这个
```

所以「节奏型适配」和前面讨论的**「朝向规划」是同一件事**：
模板 = 对某个节奏型，规定 Twirl 摆在哪 → 于是长直线落在设计过的朝向上。
