# 32 · 三处体检：闭合图形 / 方块位置偏移 / 双押偏移

> 用户 2026-10 三条怀疑：
> 1. 「我**严重怀疑**：**闭合图形限制，完全没生效**」
> 2. 「**方块位置偏移的选项可以开局为关闭了**」
> 3. 「我怀疑：**双押偏移没有被按照公式修复回去**」
>
> 结论：**第 1 条怀疑成立（真 bug，已修）**；**第 2 条是需求，已改默认**；
> **第 3 条只对了一半**（角度双押恒零偏移；中旋双押确实有 ≤1.8ms 的系统偏移，已归零）。
> 审计工具：`tools/_closed_ab.py`、`tools/_dp_offset_audit.py`。

***

## 1. 「闭合图形」完全没生效 —— ✅ **成立，是 UI 取值错位**

### 1.1 根因：全仓**唯一**一个「combo 存真值、却按下标解」的字段

`sidecar/schema.py`：

```python
CLOSED_LABELS = ("更不倾向", "不干预（默认）", "更倾向")
CLOSED_VALUES = (-1, 0, 1)

options=_opts(CLOSED_LABELS, CLOSED_VALUES)     # ← 存的是**真值** -1/0/1
```

`sidecar/session.py`：

```python
closed_figure_bias = CLOSED_VALUES[clamp(int(st["closed_bias_index"]), 0, 2)]
#                                    ↑ 这里按**下标**解
```

于是界面三档实际产生：

| 用户点 | state | 实际 bias | 期望 |
|---|---|---|---|
| 更不倾向 | −1 → clamp 0 | **−1** | −1 ✔（碰巧对） |
| 不干预 | 0 | **−1** | 0 ✘ |
| 更倾向 | 1 | **0** | +1 ✘ |

⇒ 三档只出 `{-1, −1, 0}` 两个值，而且标签全错位。**用户看到的就是「没生效」。**

**另外**：schema 的 `default=1` 在旧取值下会让下拉框**默认停在「更倾向」**上，
可实际生效的是 `0`（不干预）—— 连初始状态都是自相矛盾的。

### 1.2 修法：与同组 `*_index` 对齐（value = 下标）

```python
options=_opts(CLOSED_LABELS, (0, 1, 2))        # 0/1/2 = 下标，正是 session 要的
```

修完（`tools/_closed_ab.py`，**直接从 schema 选项里取值**，不再手写）：

| 曲目 | 更不倾向 | 不干预 | 更倾向 |
|---|---|---|---|
| Automaton 直线率 | **53.4%** | 49.7% | 47.2% |
| Automaton 自然格 | 525 | 580 | **617** |
| FallenEra 直线率 | **59.1%** | 57.0% | 56.3% |
| FallenEra 自然格 | 374 | 375 | **400** |
| MemoryLocked 自然格 | 110 | 111 | **141** |
| MemoryLocked Twirl | 32 | 32 | **17** |

三档产物哈希**两两不同**，单调、无违规。

### 1.3 回归护栏（`tests/test_sidecar.py`，+2 条）

1. **全仓扫描**：凡是 key 以 `_index` 结尾的 combo，其选项 `value` 必须是
   `0..n−1` —— 这类「存真值按下标解」的错位以后一律报警；
2. 闭合图形三档 UI 标签必须映射到**三个互不相同**的 bias `[-1, 0, 1]`。

> 顺带澄清：核心层的「闭合限制」本身是**好的** ——
> 三首样本的**自然段 `Σtravel − 180n ≡ 0 (mod 360)` 全部成立，0 个不闭合**
> （`tools/_dp_offset_audit.py` C 段）。
> 另外「激进路径」上 MemoryLocked 的 bias 0/1 产物哈希相同 —— 不是 bug：
> 决策层级确实变了（rung1 129 → 141 格），但那 12 格的两个来源恰好画出同样的
> `travel/k`，属于巧合性同产物。

## 2. 「方块位置偏移」开局为关闭 —— ✅ **已改默认**

用户口径：「方块位置偏移的选项可以**开局为关闭**了」。

`use_position_track` 默认 **True → False**（`SolveParams` / `schema` / `ladder` 同步）。
它只写渲染事件（`PositionTrack`），**不碰 angleData / bpm / travel ⇒ 时序零影响**，
所以关掉是纯观感选择 —— 由用户自己按需打开。

- `tests/golden/off_hashes.json` **重冻（7 → 9 个用例）**：
  基线记的是「当前默认参数下的产物」，默认变了就跟着重冻（与 `pause_min_beats`
  1→4 那次同一处置）；另补两条**显式钉死**的用例
  （`use_position_track: True` / `False`），保证以后无论默认怎么飘，
  「开 / 关」两条路径都还被守着。
  实测两条哈希确实不同（`1a444710…` vs `ed44b9a4…`）⇒ 开关是通的。
- e2e 那条从「默认开」改成「**默认关** → 打开后确有错开 → 关回归零」四段式。

## 3. 「双押偏移没按公式修回去」 —— ⚠ **对了一半**

### 3.1 先说准：`docs/16` 那套公式**不需要**被触发

`core/dp_offset.py`（`angleOffset` 推迟 / `Pause` 补拍）是**死代码**，这是**有意的**：
两条双押路径的 `Σtravel` 都守恒 ⇒ **净偏移恒为 0**，永远到不了 `tol_ms = 20ms`
的触发线（`docs/24` §8 已记录）。

### 3.2 但确实有个**没被修回去**的东西：中旋的 `old2new` 指错了格

`tools/_dp_offset_audit.py` A 段 —— 「插入前后**每个主音**的时刻差」：

| 曲目 | 写法 | 最大 | 非零个数 | >1ms | **改之前** |
|---|---|---|---|---|---|
| FallenEra | angle | +0.000 | 0 | 0 | |
| FallenEra | midspin | **+0.926** | 80/80 | 0 | ← 每个主音都偏晚 |
| Automaton | angle | +0.000 | 0 | 0 | |
| Automaton | midspin | **+1.802** | 120/120 | 1 | |
| MemoryLocked | angle | +0.000 | 0 | 0 | |
| MemoryLocked | midspin | **+0.833** | 27/27 | 0 | |

根因**不是时长**，而是**映射**：`dp_midspin.apply` 里

```python
old2new[i] = len(new)        # ← 指向「被吃掉 Σs 的原格」
```

那一格的 entry 是 `t_k + Σs·mpd`，比主音原来的 `t_k` **晚** Σs·mpd。
`docs/16` 的公式管的是「本格时长差多少」，**管不了这个**（它压根不是时长问题）。

**修法**：主音压在**第一个折返格 X** 上（X 的 entry 就是 `t_k`）：

```python
old2new[i] = pairs[-len(ss)][0]      # 第一个 X
```

修完三首样本全部 **±0.000 ms**（B 段预览与实际修法一致）。

### 3.3 结论

- **角度双押**：本来就是精确 0（拆法 Σtravel 守恒，onset 压在薄格上）；
- **中旋双押**：修完之后也精确 0；
- **公式本身仍然不用启用** —— 只要没有哪条插入法真的引入了「格时长」差。
  哪天真出现会累计偏移的插入法，`plan_corrections()` 就直接接上（单测一直在跑）。
