# 16 · 双押偏移回正公式（源码反推 + 实测对齐）

> 用户口径：**偏移时值容忍它累计，总计超过 20ms 之后，找一个 SetSpeed 事件或
> 暂停节拍事件，计算后回正所有偏移。**
>
> 本文把「怎么算」钉死，并给出**与第三方权威反解器实测对齐**的结果。
> 实现：`core/dp_offset.py`；测试：`tests/test_dp_offset.py`。

## 1. 游戏时间模型（两处独立来源互相印证）

### 1.1 每格时长 = 沿角度轴积分

| 来源 | 结论 |
|---|---|
| 反编译 `scrMisc.GetTimeBetweenAngles` | `travel = GetAngleMoved(entry, exit)/π × (60/bpm)/speed` |
| 本项目 `vendor/adofai_timemodel/angle.py:538-543` | `contrib = (Δangle/180) × (base_bpm/seg_bpm)`，逐段累加 |

即：

```
dt = ∫ (dAngle/180) · (60000 / seg_bpm)        [ms]
```

没有速度事件时整格一段 ⇒ `dt = (travel/180)·(60000/bpm)`，与现有
`core/solve.times_from_chart` 完全一致。

### 1.2 `SetSpeed.angleOffset` = 「沿本格再走多少度才生效」

| 来源 | 关键行 |
|---|---|
| `vendor/adofai_timemodel/angle.py:465` | `abs_angle = cum_angle[floor] + angleOffset` |
| 反编译 `scnGame.cs:1204-1247` | 按 angleOffset 把该格切成两段、各用各的 BPM，再折算等效 speed |
| 反编译 `scnEditor.cs:2437` | 编辑器拖动事件时用「移动的角度」写进 `angleOffset` |

所以是**绝对角度**意义：

```python
abs_angle = cum_angle[floor] + angleOffset      # 事件生效的绝对角度位置
```

### 1.3 `Pause.duration` = 「额外几拍」

`scrFloor.cs:417`：

```csharp
public double entryTimeAfterExtraBeats
    => entryTime + conductor.crotchetAtStart * (double)extraBeats / (double)speed;
```

`crotchetAtStart = 60/base_bpm`、`speed = bpm/base_bpm` ⇒ 额外时长 `= 60000·d/bpm` ms。
`scnGame.cs:1140`：`floor.extraBeats += item["duration"]` —— 就是**加法**，所以
数学上 `d` 允许是**任意实数**（含负）。

## 2. 回正公式

### 2.1 首选：推迟一个**已有** SetSpeed 的 `angleOffset`

本格 travel `A`、变速前 `b_prev`、变速后 `b_new`、`angleOffset = φ`：

```
dt(φ) = (φ/180)·(60000/b_prev) + ((A−φ)/180)·(60000/b_new)
```

相对默认写法（`φ=0`，整格 `b_new`）的**修正量**：

```
Δ(φ) = (φ/180) · 60000 · (1/b_prev − 1/b_new)          [ms]        ← 用它回正
```

反解：

```
φ = Δ · 180 / (60000 · (1/b_prev − 1/b_new))      ∈ [0, A]
```

**容量与符号**（很重要）：

| 本格事件 | Δ 的符号 | 最大修正量 |
|---|---|---|
| 提速 `b_new > b_prev` | **只能加长**（Δ ≥ 0） | `(A/180)·60000·(1/b_prev − 1/b_new)` |
| 减速 `b_new < b_prev` | **只能缩短**（Δ ≤ 0） | 同上（负值） |

★ **只有本格自己的时长变化，后面每一格都不动** —— 这是它能当回正用的根本原因。
（实测见 §3：其它格差 0.0000 µs。）

### 2.2 兜底：`Pause`

```
d = Δ · bpm / 60000                     [拍，可为负]
```

- 不改速度 ⇒ **不破坏「速度档只用 2 的幂」**
- 任意符号都能修，不受 §2.1 的容量限制
- 代价：多一个事件；`d` 是分数拍（游戏接受，可读性差）

### 2.3 不使用：新插一对 SetSpeed

在没有事件的格上新插「本格 `[φ,A]` 用新速 + 下一格恢复旧速」，也能只改本格时长，
但**多两个速度事件**，与「人类谱不会到处 SetSpeed」的红线冲突，默认不用。

## 4. ⚠ 硬约束：**uniform parity 下**插入奇数格会让下游整体翻 180°

`angleData` 的递推是：

```
a_i = a_{i-1} + 180 − travel_i
```

把一个「1 格」拆成 k 格、总 travel 不变、且**全程 parity 不变**时，下游 `a` 的漂移是：

```
Δa = 180·(k − 1)   (mod 360)
```

于是：

| 构造 | 时间 | 下游 angleData |
|---|---|---|
| 拆成 **2** 格 `[θ, T−θ]`（插 1 格） | 不变 ✓ | **+180°** ✗ 整条下游点对称翻转 |
| 拆成 **3** 格 `[t₁,t₂,T−t₁−t₂]`（插 2 格） | 不变 ✓ | 不变 ✓ 但多了 2 次按下 |
| 中旋 `[X(s), 999, 原格(T−s)]` | 不变 ✓ | 不变 ✓ 且**只有 2 个不同的按下时刻** |

**推论**：

1. **在 parity 不变的前提下**，「只多一次按下 + 零时长偏移 + 零几何变化」做不到 ——
   几何要求 `k` 偶、按下次数要求 `k=2`，而 `Δa = 180(k−1)` 要求 `k` 奇。
2. 中旋双押之所以「完好」，正是因为 `999` 那格**贡献了 +180 的链项却不花时间**，
   一次性凑齐了「k=3 的链 + 2 个按下时刻」。
3. BUGJI 的 `180−a / carry` 角度写法出现「角度偏差 / 延迟累积」
   （其 README 已知问题 #8/#9），根因就是这个 **+180**。

> ⚠ 上表的 `Δa = 180(k−1)` **只在 parity 全程不变时成立**。
> **Twirl 可以翻转 `Δa` 的符号** —— 这正是下面 §4.1 的解法。

## 4.1 ★ 解法（已验证）：把 Twirl 放在成对的**第 1 格**

> 用户提问：*「如果第二个应该为下游角度的双押，在第一格放置旋转事件，会发生什么？」*

**答案：能抵掉 +180 —— 但只在被拆格的 `travel = 90° 或 270°` 时成立。**

### 推导

Twirl 在**该格起把 `ccw` 翻转**，于是每格的 `Δa = ±(180 − travel)` 可自由选符号 ——
这就是缺的那一维。把 `[θ, T−θ]` 的第 1 格（薄格）加 Twirl，parity 从它起变 True：

```
thin  : Δa = θ − 180
second: Δa = (T−θ) − 180
成对合计 = T − 360 ≡ T
原单格   = 180 − T
```

⇒ 第 2 格 `angleData` 变成 `a_prev + T`，而原格是 `a_prev + 180 − T`。
相等 ⟺ **`2T ≡ 180 (mod 360)`** ⟺ **`T = 90°` 或 `270°`**（与 θ 无关）。

| 被拆格的 travel `T` | 第 2 格 angleData | 等于原格？ |
|---|---|---|
| **90° / 270°** | `a_prev + T` | ✅ **完全相等** |
| 180°（普通直线） | `a_prev + 180` | ❌ 差 180° |
| 120° | `a_prev + 120` | ❌ 差 120° |

### 实测（本会话验证，脚本见交付说明）

```
T= 90 θ=15 | 1 Twirl: 第2格==原格 True, 下游一致 False
           | 2 Twirl: 第2格==原格 True, 下游一致 True   ★ 完全等价
T= 90 θ=30 | 2 Twirl: 第2格==原格 True, 下游一致 True   ★ 完全等价
T=270 θ=15 | 2 Twirl: 第2格==原格 True, 下游一致 True   ★ 完全等价
T=270 θ=30 | 2 Twirl: 第2格==原格 True, 下游一致 True   ★ 完全等价
T=180 θ=30 | 2 Twirl: 第2格==原格 False（差 180°）
```

### 推荐构造（取代 §4 的 A/B/C）

**把双押插在 `travel = 90°`（或 270°）的格子**（= 八分音符 / 半拍格），
构造 `[θ(Twirl), T−θ]`：

1. **只多 1 次按下**（薄格 `θ` = 15°/30°，按 cbpm 选）
2. **零时长偏移**（`θ + (T−θ) = T`）
3. **第 2 格原样继承原格的下游角度**（`T=90/270` ⇒ 成对 `Δa` == 单格 `Δa`）
4. 若在下游**第一格再补一个 Twirl**（把 parity 拨回）⇒ **整条下游逐格一致**，
   几何 100% 等价

> 这也解释了中旋为什么成立：`999` 那格 = 「贡献 +180 链项却不花时间」，
> 与这里的 Twirl 是**同一个自由度的两种用法**。
> **T=180 的普通直线格不行** —— 第 2 格会停在 180° 上，正是 BUGJI 踩的坑。

## 4.2 双押缺口的**两种等价编码**（`patterns/正常情况.adofai` vs `反向思维.adofai`）

用户给了两份实物谱做对照，反解器口径下**有效 travel 完全相同**：

```
有效 travel = [0, 30, 150, 180, 180, 180, 30, 150, 180, …]
beatList    = [0, 0.167, 0.833, 1, 1, 1, 0.167, 0.833, 1, …]      ← 两份一致
```

| | angleData（第 2 个缺口） | 原始 travel | Twirl | 有效 travel |
|---|---|---|---|---|
| **正常情况** | `180 → 330 → 0` | `[30, 150]` | 无 | `[30, 150]` |
| **反向思维** | `180 → 30 → 0` | `[330, 210]` | **@成对第 1 格** | `[30, 150]` |

即：`[θ, T−θ]` **不加 Twirl** ≡ `[360−θ, 360−(T−θ)]` **在成对第 1 格加 Twirl**。

### 等价条件（已实测）

| 下游 | 两份是否一致 |
|---|---|
| **全直线（travel 180）** | ✅ heading 与 angleData 逐格一致 |
| **含转弯格（如 90°）** | ❌ 不一致 —— 反向版 parity 翻转暴露，下游被 **mirror**（heading 180 vs 0） |

**⇒ 等价 ⟺ 下游是 parity 不变的（全 180 直线）。** 这与 §4.1 的结论同源：
`travel = t`（parity 正）≡ `travel = 360 − t`（parity 翻）。

### 对 P3 的意义

双押缺口有**两种可互换的编码**，选哪种取决于：

1. **下游是否全是直线** —— 不是就必须留意 mirror（要么补第二个 Twirl 拨回 parity，见 §4.1）；
2. **Twirl 落点是否与 SetSpeed 冲突** —— 社区硬规则「Twirl 不能与 SetSpeed 同格」，
   所以当缺口第 1 格正好是变速格时，用「正常写法」（不加 Twirl）更省事；
   反之若下游某处本就该有 Twirl，用「反向写法」可以顺手把 parity 拨回。

### ★ 高密度使用时：反向写法的重叠率极低（已实测）

> 用户口径：*「反向写法更适合读（大比重使用情况下重叠率极小）。」* —— **实测成立。**

构造：`gap` 格直线 + 一个缺口，重复 24 次（θ=30°）；两种写法混同一套「有效 travel」。

```
有效 travel（两种写法相同）= [180, 180, 180, 30, 150, 180, 180, 30, 150, …]
⇒ 节奏 / 时长**完全一致**，只差几何
```

| T | gap | 正常：重叠对数 / 最近距 / 宽度 | 反向：重叠对数 / 最近距 / 宽度 | 反向/正常 |
|---|---|---|---|---|
| **180°** | 1 | 444 / **0.000** / 1.0 | 24 / 1.035 / 24.0 | **5.4%** |
| 180° | 2 | 744 / **0.000** / 1.0 | 48 / 1.035 / 24.0 | 6.5% |
| 180° | 4 | 1308 / **0.000** / 1.0 | 95 / 1.035 / 24.0 | 7.3% |
| 180° | 8 | 2412 / **0.000** / 1.0 | 187 / 1.035 / 24.0 | 7.8% |
| **90°** | 3 | 570 / **0.000** / 6.7 | 48 / 1.035 / 41.9 | 8.4% |
| 90° | 8 | 858 / **0.000** / 16.7 | 48 / 1.035 / 161.9 | 5.6% |

（「重叠对数」= 非相邻格对距离 < 1.75R 的数量；一格外长 2.0）

**机制**（逐步转角，gap=3）：

```
正常   turn = [0, 0, 0, −150, −30, 0, 0, −150, −30, …]
                缺口₁=−180      缺口₂=−180        ← 每个缺口转角合计恒 −180（同向）
反向   turn = [0, 0, 0, −150, −30, 0, 0, +150, +30, …]
                缺口₁=−180      缺口₂=+180        ← 交替
```

- **正常写法**：parity 全程不变 ⇒ 每个缺口都朝**同一侧**翻 180° ⇒ 轨道原路折返 ⇒
  最近距 **0.000**（格子精确落在彼此身上）、宽度塌成 1 格。
- **反向写法**：每个缺口第 1 格一个 Twirl ⇒ parity 交替 ⇒ 相邻缺口的 180° 翻转
  **方向相反** ⇒ 轨道逐段朝另一侧铺开 ⇒ 宽度随缺口数线性增长，最近距稳定 > 1.0。

**⇒ 高密度双押必须用反向写法**，否则谱面会退化成一条自我重合的线。
（这也就是用户说的「更适合读」：铺开的谱面才读得清。）

## 5. 已实现的回正器

`core/dp_offset.py`

```python
flat_duration_ms(travel, bpm)
split_duration_ms(travel, phi, bpm_prev, bpm_new)
delta_ms(travel, phi, bpm_prev, bpm_new)          # Δ(φ)，回正用
solve_angle_offset(travel, bpm_prev, bpm_new, want_delta_ms)   # 反解 φ
defer_capacity_ms(travel, bpm_prev, bpm_new)      # 容量（带符号）
pause_beats_for(want_delta_ms, bpm)               # 反解 Pause 拍数

plan_corrections(floors, deltas_ms, *, base_bpm, tol_ms=20,
                 mode="auto"|"set_speed"|"pause") # 累计 → 超阈值 → 回正
```

行为：

- 逐格累加 `deltas_ms[i]`（每次轨道双押新引入的偏移，如 +1/12 拍）
- `|累计| ≥ tol_ms`（默认 **20ms**）时，在当前格安排一次回正把累计打回 0
- `mode="auto"`：本格有 SetSpeed 就用 `angleOffset`（零额外事件）；
  否则退 `Pause`。两者都不可行则计入 `dropped`
- 返回 `OffsetPlan`（含 `peak_ms` / `residual_ms` / 每处的前后偏移）

实测（300bpm，每次 +1/12 拍）：

```
无 SetSpeed 谱：回正 20 处 · 峰值 33.3ms · 残余 0.0ms · 放弃 0
```
