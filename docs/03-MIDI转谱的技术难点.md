# 03 · 只做「MIDI → .adofai」的话，技术难点到底在哪

> 前提：**不用中旋（999）、不用 Twirl（拐角换向）**，只出「单行星 + 角度 + 逐层 SetSpeed」的谱。
> 下面全部结论都有实测或源码支撑，探针在 `_probe\`。

---

## 0. 一句话结论

**难的不是"转换"，是"编谱"。**

| 部分 | 难度 | 说明 |
|---|---|---|
| MIDI 解析（tempo map / 多轨 / running status） | ★☆☆☆☆ | 一天的事 |
| `.adofai` 读写（JSON + 尾逗号容错） | ★☆☆☆☆ | 半天 |
| 4K 下落式预览 | ★☆☆☆☆ | 现成的，解耦一下就能用 |
| 时间模型（角度↔时长） | ★★☆☆☆ | **已验证**，公式已知 |
| **① 时值↔几何被锁死** | ★★★★☆ | 数学问题，有硬解 |
| **② 物量守恒（层数=按键数）** | ★★★★☆ | 结构性约束 |
| **③ 采音/编谱判断** | ★★★★★ | 音乐问题，**没有唯一正确答案** |
| ④ 量化与 tempo map | ★★★☆☆ | 工程问题 |
| ⑤ 不打结的几何规划 | ★★★★☆ | 搜索/优化问题 |

**MIDI→ADOFAI 不是格式转换，是编曲改编。** 转换部分很简单，编谱部分没有标准答案——
这也是为什么市面上没有"一键完美"的工具。所以工具的价值应该落在
**「可调的编谱策略」+「立刻能看见结果的预览」**，而不是追求一键出神谱。

下面是逐条拆解。

---

## 难点 ①：时值和转角是同**一个**自由度，而且被锁死

这是整个项目最核心、也最容易被低估的一点。

### 数学推导（2 行星、无 Twirl、无 MultiPlanet）

```
exit_j   = (90 − a_j) mod 360          # a_j = angleData[j]
entry_j  = exit_{j−1} + 180
travel_j = mod(exit_j − entry_j, 360)  = mod(a_{j−1} − a_j − 180, 360)
航向 h_j  = exit_j                      # 行星离开第 j 格的方向 = 该格到下一格的朝向
=>  Δh_j = h_j − h_{j−1} = travel_j + 180   (mod 360)      ← 无 Twirl
    若该层有 Twirl：Δh_j = 180 − travel_j
```

**探针实测**（`_probe\probe_turnlock.py`，拿 7 张真实谱验证）：
该恒等式在全部非中旋层成立；唯一"不符"的层数 = 该谱的中旋数（因为中旋的角行程被并入前一格，属预期行为）。
`main.adofai` 8479 层里恰好 947 处不符 = 947 个中旋。**恒等式成立。**

### 推论：无 Twirl 时，「时值」直接决定「转角」

| 音值 | 角行程 | 转角 | 几何 |
|---|---|---|---|
| 1/1 | 720° | 180° | 回头，游戏强制成 2 拍 |
| **1/2** | **360°** | **180°** | ⚠️ **回头重叠**（第 n+2 格砸回第 n 格） |
| 3/8 | 270° | +90° | 左转 90° |
| **1/4** | 180° | 0° | **直线** |
| 3/16 | 135° | −45° | 右转 45° |
| 1/6 | 120° | −60° | 右转 60° |
| **1/8** | 90° | −90° | 右转 90° |
| 1/12 | 60° | −120° | 右转 120°（尖） |
| **1/16** | 45° | −135° | 右转 135°（很尖） |
| 1/24 | 30° | −150° | 右转 150°（刺） |
| 1/32 | 22.5° | −158° | 几乎回头 |

（基准 BPM = 四分音符拍速）

**读法：**
- **想"直线"就必须是 1 拍**；想"直角"就必须是 1/8 或 3/8 拍。
- **长音（≥1/2 拍）几何上必然回头重叠** → 不做任何处理会出废谱。
- **短音（≤1/16）必然是 ≥135° 的尖角** → 连打会变成刺猬，且极易自交。

→ **"时值对"和"谱好看"是同一个旋钮，不能分开调。** 想同时满足，**唯一的旋钮是局部 BPM（SetSpeed）**，
外加一个**免费的符号自由度**（Twirl）—— 见下一节。

## 难点 ②：【已按你的澄清修正】不做中旋 + 不做回头方块，**Twirl 可以用** —— 这是最优解

> 我上一版误读成"连 Twirl 也禁用"，得出"代价最大"的错误结论。
> 澄清后（**允许 Twirl，只禁中旋 999 和回头方块**），这个问题**大幅简化，并且有干净解。**

### Twirl 到底做了什么 —— 一句话：**免费翻转转向符号**

```
无 Twirl：Δh_j = travel_j + 180
有 Twirl：Δh_j = 180 − travel_j
```
两者**互为相反数**。物理上：行星绕该格扫过的角度就是 `travel_j`（由时值决定），
**Twirl 只决定它是顺时针扫还是逆时针扫** —— 不占时间、不占比、零成本。

### 于是模型变干净了

| 量 | 由谁决定 |
|---|---|
| **转角大小** | `\|turn_j\| = \|travel_j − 180°\|` ← **完全由时值决定** |
| **转角符号** | `s_j = ±1` ← **Twirl 自由选，零成本** |
| 时值 | `travel_j = Δt_j × bpm_j / 333.3333` ← Δt + 局部 BPM(SetSpeed) |

```
heading_{j+1} = heading_j + s_j × (travel_j − 180°)
tile_{j+1}    = tile_j + 2R × u(heading_j)
```

**"回头方块" ⟺ turn ≈ 180° ⟺ travel ≈ 0° 或 360°。** 这是唯一要守的红线。

### 角度-时值表（符号可任选）

| 音值 | travel | \|转角\| | 几何 |
|---|---|---|---|
| **1/4** | 180° | 0° | 直线 |
| **1/8** | 90° / 270° | 90° | 直角（左右任选） |
| 3/16 | 135° / 225° | 45° | 45° |
| 1/12 | 60° / 300° | 120° | 120° 回折 |
| **1/16** | 45° / 315° | 135° | 锐角回折 |
| 3/8 | 270° | 90° | 直角 |
| 1/6 | 120° / 240° | 60° | 60° |
| **1/2** | **360°** | **180°** | ⚠️ **回头方块** |
| 1/1 | 720°≡0° | **180°** | ⚠️ **回头方块** |

**红线位置一目了然：只有「时长 = 2 拍或更长」的层会变成回头方块。**
处理办法简单到离谱：**给这些层插一个 SetSpeed 把局部 BPM 减半**，
travel 从 360° 变回 180°（直线），时间不变，几何修好。

### 顺带得到一个"全直线"的平凡解（用来验证管线，不是用来交付的）

每层都取 `travel = 180°` ⟹ `bpm_j = 60000 / Δt_j(ms)`：
```
Δt=500ms → bpm=120      Δt=100ms → bpm=600      Δt=333ms → bpm=180
```
**全谱直线、零自交、时间精确。** 无聊但可行 —— 拿它来跑通管线、验证双射校验，
是极好的**第一版回归基准**（如果连直线都错，说明时间模型写错了）。

### 真正要做的：在可行解里挑"好看"的那个

| | |
|---|---|
| **目标** | 转角落在 [−135°, +135°]，且尽量贴近"常见时值↔常见角度" |
| **变量** | 每层 Twirl 符号 `s_j ∈ {±1}`；必要时每层的 SetSpeed |
| **约束** | 不自交；不出现回头方块 |

**这是一个每层二选一的序列决策问题** —— 贪心带前瞻就够，不需要复杂搜索。

### 同值连打不再是死结

上一版"四个 1/8 必然绕成闭环"是**禁用 Twirl 的结论**。允许 Twirl 后：
`s_j` 交替 ±1 → heading 在 −90°/+90° 之间摆 → **锯齿，不闭环**。✓
（注意：若 `s_j` 全同号，8 个 1/16 会绕成闭合八边形 —— 所以 `s_j` 的规划是必须做的，不能偷懒。）

## 难点 ③：物量守恒 —— 层数 = 按键数，不能靠插层消耗时间

ADOFAI 里 **每一个 floor 都是一次必须按下的操作**，没有"空层"这种东西。

由此产生的三条硬约束：

1. **长度由角度表达，不能靠"等一会儿"。**
   想表达一个 2 拍的等待，不能插两个空层，只能
   ① 拉大角度（→ 回头重叠），或 ② 局部降 BPM（→ 层数不变）。
   → **SetSpeed 不是可选优化，是必需品。**

2. **MIDI 同时响的 N 个音只能变成 1 次按键。**
   ADOFAI 单行星、单键、一层一按。三个音同时响 = 你只能选一个（或合并成一次）。
   → **和弦的"编配"是必须做的取舍，不是 bug。**

3. **采音必须"稀疏化"而不是"全采"。**
   样本 MIDI 的 note-on 量：
   | MIDI | note-on | 轨 |
   |---|---|---|
   | `FallenEra.mid` | 2510 | 3 |
   | `MemoryLocked.mid` | 7267 | 6（含鼓轨 ch9） |
   | `Automaton_Waltz.mid` | 2353 | 2 |

   `MemoryLocked` 若全采 = 7267 层的纯刺猬。真实可玩谱面中位数是 **2107 层**。
   → **必须过滤/稀疏化**，而这需要音乐判断。

---

## 难点 ④：采音/编谱判断（**真正的 90% 难点**）

同一个 MIDI，采不同的东西出来的是**两张完全不同的谱**：

- `MemoryLocked.mid` 有 6 轨 + 鼓轨。**采旋律？采鼓点？采和声骨架？** 出谱面目全非。
- 同时音合并时**保留哪个音**（最高音？最响？骨干音？）—— 决定整条旋律线走向。
- 连打的**稀疏化阈值**（16 分连打保留几个？）—— 决定难度是 12 还是 18。
- 力度（velocity）**用来过滤还是用来当"重音标记"**。
- 弱起、切分、装饰音、琶音**怎么折叠到网格上**。

**这部分没有数学解，只有策略。** 生成器水准的差异几乎全在这里。

→ 结论：**采音层必须是可交互、可调、可实时试听对比的**，不能是写死的算法。
这正是你提的 4K 下落式预览最有价值的地方 —— **它把这个主观判断变成"能立刻听见看见"的闭环**。

---

## 难点 ⑤：量化与 tempo map

- MIDI 有 swing / rubato / tempo drift，不能假设恒定 BPM。
- 需要：**tempo map 分段 + 网格量化**。
- 网格越细 → 越准但越密（物量爆炸）；越粗 → 越稀但越不准。
- 量化误差必须小于判定窗口，否则高手一眼看出"音画不同步"。
- **`FallenEra.mid` 是 180 BPM 恒定**，`Automaton_Waltz` 185 恒定 —— 都是好样本；
  但 `MemoryLocked` 有 6 轨，需要真正处理声部。

---

## 难点 ⑥：不打结的几何规划（需要搜索，不是公式）

有了 `travel` 序列 → `Δh` 序列 → 就能算出**全部 tile 的坐标**：

```
tile_0 = (0,0)
tile_{i+1} = tile_i + 2R · u(h_i)
```

- **自交/重叠检测**：任意两个非相邻 tile 的距离 < ~2R 即视觉重叠。
- 这是一个「**在满足时值约束的解空间里搜索一个不重叠解**」的问题。
- 由于难点 ② 里 **Twirl 提供了每层转角的二选一自由度**，
  **这变成一个约束满足/最优化问题**（每层一次二选一），可以用贪心/DP/局部搜索解。
- ⚠️ **4K 下落式预览看不到这个**（它只显示"什么时刻按哪个键"）。
  必须配一个**平面的角度路径图**才能看打结 —— 这两个预览是互补的。

## 我建议的最小可行方案（**禁中旋 999、禁回头方块、Twirl 允许**）

```
MIDI
 └─① 解析：tempo map + 多轨
      └─② 采音：选声部 → 同时音合并 → 密度过滤 → 稀疏化      ← 可交互，核心难点
           └─③ 量化：网格 + 局部微调
                └─④ 基准 BPM：让"最常见时值" = 1 拍 = 直线（通常直接取 MIDI tempo）
                     └─⑤ 逐层求解：
                          · travel_j = Δt_j × bpm_j / 333.3333
                          · 符号 s_j ∈ {±1} ← Twirl 自由选（零成本）
                          · turn_j = s_j × (travel_j − 180°)
                          · 【红线守卫】禁止 turn ≈ ±180°，即 travel ≈ 0° 或 360°
                            触发时：该层 SetSpeed 把局部 BPM 减半 / 重排 / 微调
                          · 目标：|turn| ≤ 135°，且贴近"常见时值↔常见角度"
                     └─⑥ 角度回代：a_j = a_{j−1} − 180 − travel_j  (mod 360)
                          └─⑦ 几何校验：tile 坐标自交检测 → 回⑤ 调 s_j
                               └─⑧ 写盘 .adofai + 渲染 ogg
                                    └─⑨ 双射校验：用同一 parser 反解，误差 < 1 帧
                                         └─⑩ 预览：4K 下落式（验采音） + 平面路径（验打结）
```

**⑤ 和 ⑦ 是整个工程的技术核心**，也是唯一需要"想办法"的地方；其余都是工程活。

## 最终诚实的判断（按你的实际约束重写）

- **"MIDI 转 ADOFAI"在格式层面不难，在编谱层面很难。**
- **你的约束选择是最优的**：
  - **禁中旋 999** → 完全可以做到。它唯一的作用是"0 拍同瞬间"，而我们本来就要把同瞬间音**合并成一次按键**。
  - **禁回头方块** → 只是一条**数值红线**（`travel ≉ 0°/360°`，即时长 ≉ 2 拍），
    触发时插一个 SetSpeed 把局部 BPM 减半即可，代价近乎为零。
  - **允许 Twirl** → 这是关键。它给了每层**免费的转角符号二选一**，
    于是「同值连打必闭环」「长音必回头」这两个死结**同时解开**，且不增加任何时间/物量成本。
- 于是整个问题被压成一个**每层二选一的序列决策 + 一条数值守卫**：
  - 转角**大小**由时值决定（改不了，也不用改）
  - 转角**符号**由 Twirl 自由选（免费）
  - 时值由 Δt + 局部 BPM 决定（SetSpeed 是唯一旋钮）
- **Twirl 是全局有状态**（一次 Twirl 翻转其后所有层），所以实现上要维护一个 `ccw` 状态机 ——
  这是唯一的"小心机"，但只是一个 over 二值变量，不难。
- 真的会咬人的只剩三件：**①时值↔几何锁死、③物量守恒、④采音判断**。
  前两件现在都有确定算法，**第三件（采音）才是真正的瓶颈**，只能靠"可交互 + 实时预览"来兜。

> **所以下一步我建议先做"采音台"而不是"生成器"**：
> 一个能把 MIDI 摊开、让你试听、勾选声部、调稀疏化阈值、并**立刻用 4K 下落式画出采音结果**的东西。
> 采音定了，剩下的都是算术。
