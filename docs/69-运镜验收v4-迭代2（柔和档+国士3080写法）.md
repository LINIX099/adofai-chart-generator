## 4. 不许静默：本轮所有的补位 / 抬升

国士原文大量使用「不改这一维」的写法（`relativeTo: null`、`position: [null,null]`、
`zoom: null`），而本项目**不许留空**（`docs/64` §8.6.5：`zoom: null` 会被读成 0 ⇒ 黑屏）。
所以 `resolve_state()` 把国士的镜头序列**跑一遍状态机**，把空位补成实际值：

| 补了什么 | 条数（国士全长 1097 条里） |
|---|---|
| `relativeTo` 为 null | **315** |
| `position` 为 null / 半 null | **497** |
| `rotation` 为 null | **289** |
| `zoom` 为 null | **40** |
| `zoom ≤ 0`（原样搬会黑屏） | **30** —— 按「不改」处理 |

另外：**28 条**换算后缩放 < `ZOOM_LO = 100`，**抬到 100**
（国士原文有 `zoom 25 / 12 / 1 / 0` 这种「怼到脸上」的值，既是甩尾又贴着红线）。

**原有 action 一条没改** —— `MoveCamera` 是**插**进去的，原事件相对顺序不动
（`tools/apply_camera_gs.py::write_level` 的稳定插入）。

## 9. 新调度：三层合成，一条事件同时带三层

**为什么不能"一层一条"**：ADOFAI 的一条 `MoveCamera` 会把**所有**维度补间到它自己的
目标值 ⇒ 「一条只管缩放、另一条只管位置」是行不通的。所以每条事件都要同时给出三层的结果。

| 层 | 怎么算 |
|---|---|
| **漂移 · 位置** | 基准位 + `1.0·sin(2πt/13s) + 0.5·sin(2πt/7.3s)`（x）/ `0.8·sin(2πt/11s) + 0.4·sin(2πt/6.1s)`（y）<br>⇒ x 峰峰 **3.0 格** / y 峰峰 **2.4 格**，**13 / 11 秒一个来回** |
| **漂移 · 旋转** | `4°·sin(2πt/17s) + 2°·sin(2πt/9s)` ⇒ **±6°** 量级 |
| **呼吸 · 缩放** | `220 ± 45`（15 秒慢基线）再 `×(1 ± 0.11)`，**逐条交替** ⇒ 实得 `156 ~ 293` |

**网格**：每 `8` 拍一条、每条 `16` 拍（`DUR = 2 × STEP`）⇒ **任意时刻都有两条补间在跑**
⇒ 镜头**永远在动、永不静止**。补间的目标取**它自己中点时刻**的漂移值 ⇒ 整条链子连起来
是一条平滑轨迹。

**ease 全部 `InOutSine`** —— 零过冲、零硬切。
