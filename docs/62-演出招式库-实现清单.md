### 1.4 🆕 轨道底噪 / **泛白**（`RecolorTrack`，QE 的做法）—— 用户问：「这怎么写出来的？能复用吗？」

**结论：能，纯原版事件、零 mod、只改渲染。** 一条事件就能罩住一大片轨道。

**QE 实际怎么写**（`scam.adofai`，floor 273 那条，与反向 QE 同段）：

```json
{"floor":273, "eventType":"RecolorTrack",
 "startTile":[0,"ThisTile"], "endTile":[1000,"ThisTile"], "gapLength":0,
 "duration":0, "ease":"Linear", "angleOffset":0, "eventTag":"",
 "trackColorType":"Glow", "trackColor":"9c9c9cff", "secondaryTrackColor":"585858ff",
 "trackColorPulse":"Forward", "trackPulseLength":114,
 "trackColorAnimDuration":0.5, "trackStyle":"Standard", "trackGlowIntensity":40}
```

★★ **原理（从反编译读出来的，不是猜的）**：

| 环节 | 出处 | 公式 |
|---|---|---|
| 范围事件 | `ffxRecolorFloorPlus.cs:83` | `for (i = start; i <= end; i += 1 + gapLength)` 逐格套用 ⇒ **一条罩 1000 格**，`gapLength:1` 就是隔一格 |
| `Glow` 着色 | `scrFloor.cs:1251-1255` | `t = (1 − cos(2π·(Time.time + off) / animDuration)) / 2`；`color = Lerp(color1, color2, t)` ⇒ **在这两色之间余弦往返呼吸** |
| 逐格相位 `off` | `scrFloor.cs:1856-1861` | `Forward`：`(1 − (seqID % pulseLength)/pulseLength) · animDuration`；`Backward` 是它的镜像 |
| 静态着色 | `scrFloor.cs:1827-1828` | `Glow` 那一刻还会 `SetColor(white)` + `floorRenderer.color = color1` |

⇒ **每格的相位按「绝对格号 % 带长」错开** ⇒ 沿轨道形成**一条向前扫的色带**。
`pulseLength` = 带长（QE：**10 密集涟漪 / 114 长带**），`animDuration` = 呼吸周期秒
（QE：`0.4` 快闪 ~ `2` 慢呼吸）。**"轨道历史泛白"就是这条带扫过已经走过的格**。

**各 `trackColorType` 的差别**（`scrFloor.cs:1249-1272`）：

| 类型 | 行为 | 观感 |
|---|---|---|
| `Glow` | 余弦往返 `Lerp(c1,c2,t)` | 柔和呼吸 —— **泛白用这个** |
| `Blink` | 线性锯齿 `Lerp(c1,c2,(num%dur)/dur)` | 不往返，锐利闪 |
| `Switch` | 半周期硬切 `num%dur < dur/2 ? c1 : c2` | 硬跳变 |
| `Rainbow` | `HSVToRGB(num/dur % 1, S, V)` | 色相轮转 |
| `Single`/`Stripes` | `TweenColor(color1, duration, ease)` | 一次性过渡（`startOfColorChange == -1` 直接 return） |

**复用注意 4 条**：
1. **它是状态，不是一次性动作** —— 写下去就一直保持到被下一条覆盖
   （`specialColor1/2/Type/Pulse/PulseLength/AnimDuration` 都是 `scrFloor` 的字段）。
   ⇒ **成对写**：开一条 + 收尾一条 `restore`（`Single` + 基准色 `debb7b` + `pulse None`）。
2. **缺字段 = 继承上一个状态**（`ffxRecolorFloorPlus.Decode` 的 `usedColorX = !disabled[key]`
   + `target.specialColor*` 兜底）⇒ 要"整片统一"就把字段**写全**，别漏。
3. `trackColorAnimDuration` 会被 `÷ song.pitch`（`ffxRecolorFloorPlus.cs:119`）；
   我们 `pitch` 恒为 100 ⇒ 无影响。
4. `pulseLength` 相位锚在**绝对格号** `seqID % pulseLength` ⇒ 与其余演出一样**确定性可复现**
   （同一份谱每次播放完全一样）。

**与我们现有 ⑤b 的关系**：⑤b（`core/colorize.py`）写的是**逐格** `ColorTrack`
（`justThisTile: true`）；本招是**范围** `RecolorTrack`（一条罩一大片）。
⇒ 它更适合做**段级底噪**（一个段落一条），不是逐格上色。**建议单开成 ⑤e「轨道底噪」**。

### 1.2 入场 · 原创 3 招 ✅ **招式定稿，提前量 = 4 拍**（用户：「**234 没问题**」）

**写法**：每条 = **初态**（瞬间摆好）+ **回位**（缓动拉回），两条都写在**同一格**上。

```json
// ① 初态：写在 `f` 格，提前 8 拍生效（= 方块出现之前就摆好）
{"floor": f, "startTile":[2,"ThisTile"], "endTile":[2,"ThisTile"], "gapLength":0,
 "duration": 0, "angleOffset": -1440, "ease": "Linear", <初态>}

// ② 回位：同一格，提前 4 拍生效（= 余量 4 拍），2 拍飞完
{"floor": f, "startTile":[2,"ThisTile"], "endTile":[2,"ThisTile"], "gapLength":0,
 "duration": 2, "angleOffset": -720, "ease": <E>,
 "positionOffset":[0,0], "rotationOffset":0, "scale":[100,100], "opacity":100}
```

- `lead = 2` 格（目标 = `f+2`）；触发格从 `段首 − 2` 起，每格推一条
- **`beatsAhead = 8`**（必须 ≥ 起跑点，否则动画播在方块出现之前 ⇒ 白播）

| 招 | ease（回位） | 初态 |
|---|---|---|
| **入A** | `InOutBack` | `pos(6,4)` `rot 90` `scale[0,0]` `op 0` |
| **入B** | `OutBack` | `pos(0,2)` `rot 90` `scale[0,0]` `op 0` |
| **入C** | `InOutCirc` | `pos(3,−1)` `rot −30` `scale[80,80]` `op 0` |

★ 提前量的口径：**余量 m = 回位飞完 → 玩家踩上目标格，还剩几拍**。
`m = 0` 是用户原样（飞完那一刻正好踩上去，观感差）；**定稿 m = 4**。
`m = 0` 只在**低速谱**可用（用户：「2 3 只适合低速」）。

### 1.3 入场 · 反向 QE 🆕 **高速入场 / 三连音**（用户：「效果都很适合高速入场」）

**来历**：把 `7. QuomodocunquizE` floor 273 的逐格**离场**做**时间反演**。
QE 原文（同一条配方 ×657）：

```json
{"floor":273,"startTile":[-1,"ThisTile"],"endTile":[-1,"ThisTile"],"gapLength":0,
 "duration":8,"positionOffset":[0,-6],"scale":[0,0],"angleOffset":0,"ease":"InElastic"}
```

**反演规则 5 条**（缺一不可，见 `docs/61 §12.1`）：
① 目标格 `−1` → **`+lead`**；② `In*` → **`Out*`**；③ 离场终点变入场**起点**；
④ 入场目标 = **常态**；⑤ `MoveTrack` 只能指定终点 ⇒ 起点要先摆好。

**写法 = 两类事件**（与离场同构：一条总状态 + 每格一条动作）：

```json
// ① 总藏：一条罩住整段正文，瞬间摆成死态（`angleOffset -1440` = 提前 8 拍）
{"floor": 段首−RUNWAY, "startTile":[RUNWAY,"ThisTile"],
 "endTile":[RUNWAY+BODY−1,"ThisTile"], "gapLength":0,
 "duration":0, "ease":"Linear", "angleOffset":-1440,
 "positionOffset":[0,-6], "scale":[0,0], "opacity":0}

// ② 拉回：**一条罩 g 格**，逐组推进（第 k 组写在 段首 + k − lead 格）
{"floor": 段首 + k − lead, "startTile":[lead,"ThisTile"],
 "endTile":[lead + g − 1,"ThisTile"], "gapLength":0,
 "duration":3, "ease":"OutElastic",
 "positionOffset":[0,0], "scale":[100,100], "opacity":100}
```

| 参数 | 值 | 说明 |
|---|---|---|
| `lead` | **4 格** | 反演后的前瞻距离 |
| `duration` | **3 拍** | = QE 的 `8 拍 @320bpm = 1.5 秒`（**按秒折算，不能照抄拍数**） |
| `ease` | `OutElastic` | `InElastic` 的时间反演 |
| **`g`（一条罩几格）** | **1 / 2 / 3 / 4** | ★ **见下** |
| `beatsAhead` | **6 拍** | = `lead + 2` |

★★ **`g` 跟结构走**（用户本轮的新判断）：
> 「感觉 QE 的写法很适合**三连音**那种，**三个三个轨道地出来**，好读又美观。」
⇒ **三连音段用 `g = 3`**；普通用 `g = 1`；其它按段落结构取 2 / 4。
（`g = 3` 那一档在 v8 验证谱段3，**用户还没在游戏里确认过**。）

★ **偏移量恒为 `lead`**（第 k 组写在 `段首 + k − lead` 格上，目标格 `段首 + k` 相对它正好 `+lead`）。
**别写成 `lead + k`** —— 那样每前进一格偏移也多 1，**只命中一半方块，另一半永远看不见**（踩过，见 §3.3）。

## 3. 写法硬规则（每条都踩过或验过）

1. **只写要生效的字段**：`LevelEvent.Decode` 里 `disabled[key] = !dict.ContainsKey(key)`
   ⇒ **字段缺失 = 不生效**，不需要写 `"Disabled"` 去"关"它。
2. **`positionOffset` 里的 `null` = 这个轴不动**（语料 `[null,1]`），不是 0。
3. **锚点**：`[n,"ThisTile"]` = `floor + n`；`[n,"Start"]` = **绝对格号 n**；可混用。
4. **单位**：`duration` = **拍**；`angleOffset` = **度**，`180 = 1 拍`（所以 `−1440` = 提前 8 拍）。
5. **`MoveTrack` 的目标是绝对坐标**（`startPos + positionOffset`），**不是增量**；
   要"先甩出去再拉回"必须两条（或一条总状态 + 一条动作）。
6. ★★ **`PositionTrack` 是累加器**（`scnGame.cs:521/530/639`），
   我们 `core/writer.py` 现在**没写 `justThisTile`** ⇒ 每一处错位会**永久推走后面所有格**。
   **这是既有缺陷**，与本轮招式无关，但**别忘**（修法 + 3 格验证谱见 `docs/61 §3`）。
7. **`beatsAhead` 必须覆盖入场的起跑点**：`beatsAhead ≥ lead + 余量 + 余韵`，
   否则整套飞行动画播在**方块出现之前** ⇒ 方块凭空出现在终点。
8. **缓动方向定死**：离场 `In*`（慢起快终 = 被拽走）；入场 `Out*`（快起慢终 = 到位停稳）。
9. **时长的口径是"秒 / 跨几格"，不是拍数**：QE 是 bpm 320，`8 拍 = 1.5 秒 = 8 格行程`。
   照抄拍数会在不同 bpm 的谱上完全走样。

## 4. 结构分派（★ 2026-09 定稿：**用户分段 + 预设**）

### 4.0 ⚠ 两次撤回（都记着，别再犯）

2. 自动"结构事件分派"（小节头/段尾/图形段起点…）**也被取代** —— 用户口径：
   「**倾向让用户自己选择预设的入场和出场效果**」。

### 4.1 定稿模型（用户 2026-09 口径，逐字）

> 「让**用户自己选择预设的入场和出场效果**。允许**添加分段**，并且在当前生成的谱面里面
> **使用当前生成的谱面格子数定义**。否则，都只使用**预设的入场+出场**。特殊的，
> **三连音的写法中，三连音被特殊标出**。**不选择就自动用 QE 的写法**。」

⇒ 三条优先级（**高 → 低**），逐格判定：

| 优先级 | 来源 | 说明 |
|---|---|---|
| **1** | **用户添加的分段** | 用**生成后谱面的格号** `[lo, hi]` 定义；段内可指定 入场招 / 出场招 |
| **2** | **自动三连音段** | `Floor.engine == True` 的连续 run，**自动标出**；默认走 **QE 写法**（`g = 3`） |
| **3** | **全局预设** | 谱面级 `in_move` / `out_move`；没有分段、也不是三连音的地方全用它 |

#### B. `MoveTrack` 的 6 条铁律（81 827 条统计）

| 结论 | 数字 | 对我们的意义 |
|---|---|---|
| 单格（`startTile` = `0` 或 `−1`） | **96%** | ✅ 我们"逐格一条"的口径**正确** |

#### C. ★★★ 离场 / 归位是**成对的**，而且**归位在很前面**（这条最重要）

统计口径：`startTile` 用 `ThisTile` 锚点、单格事件（`start == end`）。

| 动作 | 前瞻格数中位 | 高频分布 | 我们 |
|---|---|---|---|
| **甩走**（`opacity 0` 或 `scale 0`） | **`−1`** | `−1`×2842 · `0`×909 · `−2`×273 · `−3`×129 | ✅ **我们就是 `−1`**（踹走刚走过的那格） |

10%~90% 分位 = **7 ~ 44 格**；样本 5 907 条。

⇒ ★★ **这就是用户早就说的「入场要更早」**！真实谱的"拉回常态"写在**前方 13 格**

## 5. 自检清单（实现时必须全部带上）

写进 `core/show.py` 的 `plan()` 返回值 + `tests/test_show.py`：

1. **字段集白名单**：`MoveTrack` 只允许
   `floor / eventType / startTile / endTile / gapLength / duration / positionOffset /
   rotationOffset / scale / opacity / angleOffset / ease / eventTag`
2. **作用范围不越界**：`0 ≤ lo ≤ hi < 格数`
3. **`gapLength ≥ 0`**（负值会让步长变 0 ⇒ 游戏死循环）
4. **不变量**：入场 `lo > floor`；离场 `hi ≤ floor`；
   **带动画（`duration > 0`）的事件一律不许跨过玩家**（`lo ≤ floor < hi`）
5. ★★ **完整性**：范围类事件必须**覆盖该段每一格且只覆盖一次**
   （踩过：偏移写成 `lead+k` ⇒ 漏一半方块，而旧的越界/跨脚下断言**全部通过**）
6. **事件按 `floor` 有序**
7. **`AnimateTrack` 字段集**：`floor / eventType / trackAnimation / beatsAhead /
   trackDisappearAnimation / beatsBehind`
8. **`beatsAhead` 覆盖检查**（§3.7）
9. **不许静默**：跳过/截断/撞车全部进报告（与 ⑤b/⑤c 同级契约）
10. ★ **同一 floor 上的事件顺序**：`AnimateTrack` → **入场（初态 → 回位）** → **离场** →
    `ColorTrack`。理由：入场与离场的作用格**可能重叠**（入场目标在玩家前方、离场目标在
    身后，但同一格可以被两种规则同时选中），一旦同格，顺序必须是"先摆好再踹走"，
    反了就变成"刚踹走又飞回来"。
11. ★★ **分派（§4.3）的断言**：同一类招相邻两次之间 **≥ 8 格**；一次"结构事件"**只触发一格**
    （反向 QE 除外，它是整段行为）；**不在结构点上的格子一条都不写** —— 把"招式总数"
    与"总格数"一起报出来（比值过高 ⇒ 观感糊成一片）。
12. **同格避让要记账**：与 ⑤b `color_events` / ⑤c `appearance_events` 撞车的结构点，
    让位并进 `n_collide`（与 `appearance.py` 同款，**不许静默**）。
