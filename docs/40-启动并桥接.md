# 40 · 「启动并桥接」：一个按钮把 BDG 拉起来并接上

> 用户 2026-10：「**UI 里面有一个启动并桥接的按键来用**」。
>
> 这个按钮做四件事：**建链接 → 起宿主 → 等它起来 → 把连接串推进插件**。
> 代码：`sidecar/hostctl.py`（流程）+ `tools/host.js`（起停）+ UI 上两个按钮。

***

## 1. 为什么要绕 CDP 推连接串

插件是**只读、无文件系统权限**的 renderer 插件，它**拿不到我们的端口**
（sidecar 每次启动端口都可能不同）。原设计是「把连接串贴进 BDG 面板」
（`docs/38` §10.1）—— 能用，但不是一键。

而**我们自己起的**宿主带 `--remote-debugging-port=9222`，那个调试通道**是我们开的**
⇒ 从那儿把地址推进宿主的 `localStorage['adoc.bridge.url']` 并调一次
`session.connect()`，是顺理成章的。

★ **它不碰宿主源码**，只写宿主的 localStorage —— 等价于用户点一下插件面板里的「连接」。

> 插件的 `renderer.js` 里 `session.url = localStorage.getItem(LS_KEY)`，但**不会自动连**
> （要人点）。所以推完地址还得替它调一次 `connect()`。

***

## 2. 四步与失败面

```
① node tools/host.js link       建 junction + 合并启用项（毫秒级、幂等）
② node tools/host.js start      **不阻塞**地起宿主（detached + unref + pidfile）
③ 轮询 http://127.0.0.1:9222/json/version   等 CDP 通（≤60s，每 1.5s）
④ node tools/_cdp.js "<js>" --target main   注入地址 + connect（≤25s，每 1.5s 重试）
```

每一步失败都落到**具体阶段**并给出**下一步该干什么**（`tests/test_hostctl.py` F 组钉住）：

| stage | 什么时候 | 对用户说什么 |
|---|---|---|
| `host` | 宿主没拉 | 「先跑 `npm run host:fetch`（需要代理 127.0.0.1:7897，约 600MB）」 |
| `deps` | 拉了但依赖没装好 | 「先跑 `npm run host:fetch`」 |
| `start` | 起不来 | 把底层原因带出来 |
| `cdp` | 起来了但 9222 不通（比如宿主是别人手动起的） | 「请手动把连接串贴进 BDG 面板（Alt+Shift+B）」+ **回传连接串** |
| `inject` | 9222 通了但没等到插件 | 「在 BDG 里确认插件已启用，或手动贴」+ 插件的原话原因 |
| `cancelled` | 用户取消 | 「已取消」 |

**每一步都汇报**（走同一条 SSE，`kind: "host"`），UI 上那行状态会变：
`◐ 正在启动宿主…` → `● 已桥接（宿主 pid N）`。

***

## 3. 起 / 停的口径（**不猜、不误杀**）

- `start` 用 `detached + unref`：**设计上不跟随我们退出**（这样 sidecar 重启不会把窗口带走）。
- pid 写 `out/_bdg_host.pid`，日志写 `out/_bdg_host.log`（都记在**我们的** out/ 里，不往宿主目录塞东西）。
- `stop` **只杀 pidfile 里记着的那个进程**（Windows 上 `taskkill /PID x /T /F` 收整棵树）。
  - 没有 pidfile ⇒ 「不是本脚本起的」并**什么都不做**；
  - pidfile 指向一个不存在的进程 ⇒ 探活失败，**顺手清掉残留 pidfile**，不杀任何一个 pid。
- 已经在跑 ⇒ `start` 认出来（`already`），**不重复起**。
- 并发点两次「启动并桥接」⇒ 第二个被 **409** 挡住。

***

## 4. ★ 退出时谁来收宿主（踩过的坑）

**现象**：从 UI 点了「启动并桥接」，关掉我们自己的 app，**BDG 宿主还在跑**（9222 还通、
pidfile 还在、5 个 electron 进程）。

**根因**：`app/main.js` 的退出路径本来是
`spawnSync(process.execPath, [tools/host.js, 'stop'])` —— 但在 **Electron 里
`process.execPath` 是 `electron.exe`，不是 node**。于是等于又拉了一个 Electron
去跑那个脚本，**静默失败**，而我只在 `status === 0` 时打日志 ⇒ 一句日志都没有。

**修法**：退出路径上**不依赖任何外部程序**，直接在进程内做（读 pidfile + 探活 +
`taskkill`）。理由：退出路径要的是**短、同步、不靠 node 在不在 PATH 上**。

实测（修完）：

```
[sidecar] 就绪 329ms
[renderer] ready {"port":62039,"fields":57}
[host] 已停掉我们起的 BDG 宿主（pid 118896）      ← ★ 就是这一行
然后：我们的 app 已关 / 9222 已断 / electron 进程数 0 / pidfile 已清
```

★ `tools/_host_test.js` 的 **K 组**是这件事的**源码守卫**（扫 `app/main.js` 的**代码**、
跳过注释）：代码里出现 `process.execPath` 就直接失败，免得这个坑悄悄回来。

> 为什么不能只靠 sidecar 里的 `atexit`：Node 在 Windows 上的 `subprocess.kill()`
> 走 `TerminateProcess`，**不跑**目标进程的 `atexit`。所以 `main.js` 里
> 「**先停宿主，再杀 sidecar**」的顺序是有意义的。

## 5. 怎么用

**一键**：侧栏底部「BDG 编辑器桥」→ **`▶ 启动并桥接`**。
宿主没装会明确告诉你去跑 `host:fetch`；宿主已在跑就直接接上；桥已连着就不重复连。

**分开做**（等价，命令行）：

```powershell
node tools\host.js link      # 只建链接
node tools\host.js start     # 只起宿主（不阻塞）
node tools\host.js state     # 一行 JSON 状态（sidecar/UI 用的就是这个）
node tools\host.js stop      # 只停我们起的那个
node tools\host.js dev       # 前台起（人在终端里看日志用）
```

**只重推连接串**（换了端口 / 面板里点过断开）：`POST /api/host/inject`。

***

## 6. 接口

| 方法 | 路径 | 干什么 |
|---|---|---|
| GET | `/api/host` | 宿主状态：`present / deps / pid / pid_alive / cdp_up / port / starting / url` |
| POST | `/api/host/start` | 起宿主并桥接（**立刻返回**，进度走 SSE `kind=host`；已在跑则 409） |
| POST | `/api/host/stop` | 停我们起的宿主（幂等） |
| POST | `/api/host/inject` | 只重推一次连接串 |

前端的钩子：`window.__dsh.host() / hostState() / hostStart() / hostStop()`
（`hostState()` **每次都重新问**，以前返回缓存对象，调试时会看到
「pid=0 但界面说已桥接 pid=1234」这种自相矛盾的快照）。

## 8. 还没做的

* **端口写死 9222**：如果用户自己已经开了个带 9222 的实例，`up()` 会说「通了」并直接往里注入。
  更严的做法是先确认 9222 上的就是我们起的那个（现在只靠 pidfile 判断「是不是我们起的」）。
* **没有「宿主已启动但项目是空的」的引导**：宿主起来后是欢迎页/空工程，用户得自己开一个工程。
* **`host:fetch` 的门控**已做（装好就一个字节都不下），但界面里**没有**「下载宿主」按钮 ——
  只能命令行跑。要做的话得配一个带进度的下载页（600MB）。
