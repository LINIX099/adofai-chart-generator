## 1. 闭合图形使用策略

### 1.1 先说一个反直觉的事实：第一版做出来是**死的**

我先把偏好做成 `figures.score()` 里的一条排序项（插在「直线格数」之后）。
跑完发现 **三档的产物哈希完全一样** —— 也就是说这个旋钮一点用都没有。

原因：

```python
def nat_candidates(...):
    ...
    if not _closed(tv, n):        # ← 自然段候选**本来就全是闭合的**
        continue
```

`nat_candidates` 是用 `_closed` 硬过滤出来的，所以闭合段之间**根本分不出胜负**，
那条排序项永远取同一个值。想让它有意义，必须作用在**「用不用闭合图形」**这个决策上，
而不是「用哪一个闭合图形」。

### 1.2 真正的杠杆：形状闸门的松紧

决定「用不用闭合段」的，是 `figures.choose()` 里那道硬闸：

```python
# 短段变速 = 白花两个 SetSpeed 换一个跟 DP 没差的图形
if c.kind == "nat" and s[0] > 0 and c.n < p.natural_speed_min_tiles:
    continue
```

于是偏好落在**闸门的松紧**上：

| 策略 | `nat_min_tiles` | 效果 |
|---|---|---|
| 更倾向闭合 | `max(2, base // 2)` | 闸门放宽，更多闭合段被接受 |
| 不干预（默认） | `base` | 与今天完全一致 |
| 更不倾向 | `base * 2` | 只有明显划算的闭合段才用 |

### 1.3 实测（`tools/_closed_probe.py`）

| 曲目 | 更不倾向 | 不干预 | 更倾向 |
|---|---|---|---|
| Automaton 直线率 | **53.4%** | 49.7% | 47.2% |
| Automaton 自然段格数 | 525 | 580 | **617** |
| FallenEra 直线率 | **59.1%** | 57.0% | 56.3% |
| FallenEra 自然段格数 | 374 | 375 | **400** |
| MemoryLocked 自然段格数 | 110 | 111 | **141** |
| MemoryLocked Twirl | 32 | 32 | **17** |

**单调、有效、无违规。** 代价也清楚：越倾向闭合，直线率越低（闭合段牺牲直线换「收得住」）。
这是这个旋钮本来就该有的取舍。

参数：`SolveParams.closed_figure_bias ∈ {-1, 0, +1}`，
UI「**闭合图形**」三档（更不倾向 / 不干预 / 更倾向，默认不干预）。

> ★★ **2026-10 追加（`docs/32` §1）**：用户报「闭合图形限制**完全没生效**」——
> **怀疑成立**。上面 §1.3 那张实测表是**核心层**（`tools/_closed_probe.py`）跑出来的，
> 核心逻辑确实是对的；但 **UI → sidecar 的取值错位**了：
> `closed_bias_index` 是全仓**唯一**一个「combo 存真值 `(-1,0,1)`、却按下标解」的字段，
> 于是界面三档实际只产生 `{-1, −1, 0}`，标签也全错位。
> 已改成 `value = 下标`（与同组 `dp_mode` / `ref_index` / `snown_index` 对齐），
> 并加了**全仓扫描护栏**与「三档映射必须互异」两条单测。
> 端到端复核见 **`tools/_closed_ab.py`**（它现在直接读 `SC.FIELDS` 的选项值，
> 不再手写 0/1/2 —— 手写正是当初漏掉这个 bug 的原因）。

## 2. 回正体检：它没死，但确实有**两处真让它死了**

### 2.1 先量：它到底动没动（`tools/_straighten_probe.py`）

| 曲目 | straighten=on vs off | 读数 |
|---|---|---|
| Automaton_Waltz | **产物不同** | `changed=86`，偏轴 `22027 → 15815`（−28%），Twirl `90 → 4` |
| FallenEra | 产物**相同** | `skipped=no-diagonal-run` |
| MemoryLocked | 产物**相同** | `skipped=no-diagonal-run` |

**算法本身是活的**，在 Automaton 上干了不少活。

### 2.2 FallenEra / MemoryLocked 为什么不动 —— 这次是**对的**

`diagonal_runs(theta=20°, min_run=8)` 要求「**连续 ≥8 格** deviation > 20°」。实测扫描：

```
FallenEra    最大 deviation 30°    theta=20/10/5°, min_run=8/4 → 段数 0
                                  min_run=2                → 24 段 / 48 格
MemoryLocked 最大 deviation 45°    theta=20/10/5°, min_run=8/4 → 段数 0
                                  min_run=2                →  4 段 /  8 格
```

也就是说：这两首的**偏轴只是零星几个格**，根本不存在「一条斜轨」。
没有斜轨可回正 ⇒ 不动手是**正确行为**，不是 bug。

> 判断依据：回正只在「长斜轨」上有意义 —— 它靠翻 Twirl 把一整段的方向掰回主轴；
> 孤立的 1~2 格偏轴翻了 Twirl 也掰不回来，只会白加图标。

### 2.3 ★ 但有两处**真的**让它死了，都修了

**(a) 激进路径把它整个关掉了 —— 这是我上一轮埋的**

```python
# core/ladder.py（旧）
p2 = _copy.copy(p)
p2.straighten = False        # ← 理由：「全局回正会与逐音 Twirl 打架」
```

结果：只要开着「使用激进的采音策略」，回正**一行都不跑**。已改成照跑 ——
回正**只改 Twirl 符号、不动 travel**，时序零影响；模板/自然/引擎/雪花段
仍被 `_protected_floors` 钉死。实测（Automaton）：

```
激进 回正关 → Twirl 0        哈希 5c9017c2ef
激进 回正开 → Twirl 1        哈希 a6655f94e8   偏轴 19575 → 15658（−20%）
```

**(b) 回正**一个参数都没有**接到 UI 上**

全仓 grep `straighten`：`core/solve.py` 里有 6 个参数，`sidecar/schema.py` 里**一条都没有**。
用户既看不到它在不在跑，也没法调松紧 —— 表现就是「好像死了」。

现已暴露三个（`④ 求解` 组）：

| 字段 | 默认 | 说明 |
|---|---|---|
| `straighten` | ✔ | 总开关 |
| `straighten_min_run` | 8 | 连续多少格偏轴才算「值得回正的斜轨」。**想让它更积极就调小** |
| `straighten_theta` | 20° | 偏主轴超过多少度才算「斜」 |

**(c) 附带**：激进路径把回正报告扔了（`ch.meta["straighten"] = {}`），
现在原样透出 `p2.straighten_meta`，状态栏/工具能看到 `changed / offaxis_before→after`。

## 3. 控制台布局（**用户明确说「后面考虑」，本轮只记不动**）

用户原话：「控制台的功能现在似乎多的过分了，需要考虑换布局方案？**这个稍微后面考虑**」。

现状（本轮之后）：

- `④ 求解` 组已经有 **19 个**「v0.3 新增」参数（`app/e2e.js` 里那条断言在数它们）；
- 加上原有的，`④` 一个组就塞了 30+ 个控件；
- `schema.GROUPS` 只有 7 个组，且 `④` 明显过载。

**候选方案（未选，留给下次）**：

1. **按功能分子面板**：`④ 求解` 拆成「基础 / 速度与直线 / 图形 / 雪花 / 激进采音 / 回正」，
   折叠态只显示命名与默认值；
2. **「高级」折叠层**：把 `snowflake_*`（10 个）、`ladder_*`（4 个）、`straighten_*`（3 个）
   收进「高级」抽屉，默认收起；
3. **预设**：把一组常用组合存成预设（`默认 / 激进 / 手工打磨`），减少需要同时可见的参数。

> 这一条**没有动任何代码**，只登记在这里与 `CHANGELOG` 的「待办」里。
