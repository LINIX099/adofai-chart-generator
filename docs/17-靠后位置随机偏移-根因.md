# 17 · 「靠后位置随机偏移（50~100ms）」根因

> 症状（用户口径）：**谱面播放到靠后的位置，有可能随机出现 50~100ms 的偏移。**

结论：**不是求解核心的问题，是 OGG/WAV 采音路径的问题。**
MIDI 路径完全干净；OGG 路径把「检波器系统性偏置」交给「网格吸附」去纠，
一旦 BPM 估错，吸附就会把 onset 挪到**错误网格**上 → 几十毫秒的偏移，
而且**越往后越明显**。

> ✅ **已修复（§6，2026-02 本轮）**：F1 吸附安全阀 + F3 自洽网格（周期精修 + 相位）
> + F4 检波偏置自标定。两个真值对上从 `|·|max 79.5ms / >50ms 20.7%`
> 修到 `|·|max 4.4ms / >50ms 0%`，均值 `−34.5ms → +3.8ms`，分段均值极差 0.8ms。
> **全部修复都只吃 OGG**（不需要 MIDI；MIDI 只在验收里当真值尺子）。

复现工具：`python tools/diag_ogg_offset.py <真值.mid> <音频.ogg>`

---

## 0. 先排除：求解核心是干净的

逐层比较「谱面时刻」与「音乐 onset 时刻」（第 i 个 onset ↔ 第 i+lead 层）：

| 样本 | 层数 | 逐层误差 max | 最大跳变 |
|---|---|---|---|
| Automaton_Waltz.mid | 849 | **45.2 µs** | 0.2 µs |
| FallenEra.mid | 565 | **43.8 µs** | 0.2 µs |
| MemoryLocked.mid | 195 | **0.0 µs** | 0.0 µs |

⇒ MIDI 路径下，谱面与音乐的时间关系是亚毫秒级、**没有任何阶跃**。
所以问题在 `core/audio_onsets.py`（OGG/WAV 路径）。

## 1. 复现：用有精确真值的音频

`samples/audio/doublepress_demo_120.ogg` 是**由 `doublepress_demo_120.mid` 合成**的，
所以 MIDI 的音符时刻就是精确真值（328 个音，最后 63750 ms）。

```
python tools/diag_ogg_offset.py samples/audio/doublepress_demo_120.mid \
                                 samples/audio/doublepress_demo_120.ogg
```

| | 匹配 | 偏移均值 | 中位 | \|偏移\|max | **>50ms 占比** |
|---|---|---|---|---|---|
| **① 原始检出（不吸附）** | 268/328 | **−35.5** | −35.8 | 39.0 | 0.0% |
| **② 吸附后（线上产出）** | 275/328 | −34.5 | −38.0 | **79.5** | **20.7%** |

**② > ① 的地方就是 bug**：吸附不但没纠偏，反而把 onset 挪到了错误网格上。

按时间分段看 ②：

| 区段 | n | 均值 | \|·\|max | >50ms |
|---|---|---|---|---|
| 0–30s | 124 | −36.2 | 56.3 | 12.9% |
| 30–60s | 137 | −31.0 | **79.5** | 19.7% |
| 60–120s | 14 | −54.2 | 56.7 | **100%** |

⇒ **越往后越糟**，与用户描述的「播放到靠后的位置才出现」一致。

## 2. 三阶段机制

### ① 检波器有系统性偏置（−35.5 ms，全程一致）

`librosa.onset.onset_strength` 的 STFT 窗半宽是 `n_fft/2 = 1024` 样本 ≈ 23 ms，
能量在脉冲到达窗中心**之前**就进窗 ⇒ 差分峰值**提前**。
`docs/双押练习说明.md` 早就量到过这个（当时记 ±16~18 ms，且随 hop 变化）。
本文件 hop=64 时实测 **−35.5 ms**。

★ **这个偏置是「真值 vs 原始检出」的差，是系统性的、可标定的。**

### ② 网格吸附本来是「顺手纠偏」的

`fit_onsets(t, bpm, grid=6, tol_frac=0.5, prefer_beat=0.5, beat_tol_frac=0.18)`：

```
step = (60000/bpm)/grid           # grid=6 → 1/6 拍
snapped = rint(t/step)*step       # 容差 tol_frac*step
banchor = rint(t/(beat*0.5))*(beat*0.5)   # 半拍锚点，容差 0.18*半拍
```

在 **BPM 正确**时（真值 120）：`step = 83.3ms`，半步容差 `±41.7ms`，
而检波偏置 −35.5ms 正好落在容差内 ⇒ **吸附把偏置纠回**，残差降到 −3.0ms ✓

### ③ 但 BPM 一旦估错，吸附就变成「挪错格」

本文件 `estimate_bpm` 返回 **240.371**，真值 120 ⇒ **2 倍（倍频）错误**。
原因：`estimate_bpm(..., start_bpm=180.0)` 把 librosa 的 tempo 先验钉在 180，
而对数距离上 240 比 120 更靠近 180，于是选错。

步长随之减半（41.6ms），偏置 −35.5ms **超出容差**⇒ 不再被纠正；
同时一部分 onset 被吸到**错误网格**上 ⇒ max 79.5ms、20.7% 超 50ms。

网格自洽性检查（用错误 BPM 建的网格）：

| 网格 | 步长 | 平均残差 | p90 |
|---|---|---|---|
| 1/6 拍（=41.6ms） | 41.60 | 10.4ms | 18.4ms |
| 半拍锚点 | 124.81 | **30.7ms** | **52.2ms** |

半拍锚点的 p90 已到 52ms —— 说明**锚点本身就和音乐对不上**。

## 3. 为什么是「随机」+「靠后」

- **随机**：取决于 `estimate_bpm` 的结果（先验 + 素材），不同曲子不同；
  也可能倍频/半频，也可能只差 0.1%~0.2%。
- **靠后**：网格由**估计 BPM** 生成，只要 BPM 有一点相对误差 ε，
  网格相对音乐就以 `ε·t` 线性漂移；到曲子后段漂移量可达
  `ε × 时长`（本文件 0.154% × 63.75s ≈ 98ms），
  于是「前半段被纠、后半段被挪错」——**偏移在靠后位置出现/变大**。

## 4. 修复方案（按风险从低到高）

| # | 方案 | 效果 | 风险 | 状态 |
|---|---|---|---|---|
| **F1** | **吸附安全阀**：把 `tol_frac` 收紧（宁可不吸），或**限制单次挪动 ≤ step/4**；BPM 不确定时自动收紧 | 立刻止血：不会再挪错格 | 低。只影响「吸不吸」，不改检波 | ✅ **已做**（`MIN_CONF=0.30`、`MAX_MOVE_FRAC=0.35`、`R·√n≥2.5`） |
| **F3** | **锚点带相位 + 自洽周期**：不再相信估出来的周期，用 onset 自己把周期精修到 `~1e-4` 相对精度并解出相位 φ | 消掉整曲相位差 **＋消掉漂移** | 低 | ✅ **已做**（`core/gridfit.py`） |
| **F2** | **倍频/先验校正**：候选 `{est/2, est, est×2}`，用「对网格过细加惩罚」的准则选；`start_bpm` 别写死 180 | 修掉本例 2× 错误 | 中。会改变所有 OGG 结果 | ⏸ **降级**（见 §6.4：周期修好之后，倍频**不再造成偏移**） |
| **F4** | **直接标定检波偏置** | 从源头消掉 −36ms | 中高。重排 OGG 历史结论 | ✅ **已做**（`estimate_detector_bias`，默认开，可关） |

**本轮实施顺序**：先做 F1+F3（止血，纯 onset 域），再叠 F4。
四者的验收判据统一是 **② 的 `|·|max` 与 `>50ms` 占比不高于 ①**（§5），
即"吸附不许把 onset 挪坏"。

## 6. 修复实施与实测（本轮）

### 6.1 数据流：**只需要 OGG**

```
OGG ─► mel 谱 ─► HPSS 切轨 ─► onset_strength ─► _pick ─► 粗 onset（每轨）
                                                              │
       ┌──────────────────────────────────────────────────────┤
       │ ① 检波偏置自标定（只用波形 + 粗 onset）              │
       │    estimate_detector_bias(y, sr, all_onsets)          │
       │    → 常量 bias，所有轨一起挪                          │
       ▼                                                      │
       │ ② 自洽网格拟合（只用 onset）                          │
       │    fit_grid(pool, period_of(bpm, grid))               │
       │    → period（精修）、φ、R                             │
       ▼                                                      │
       │ ③ 吸附（安全阀：R 不过就整条轨不吸）                  ◄┘
       │    snap_lattice + prefer_beat 锚点 + 同格合并
       ▼
    MidiFile（tempo_map 用精修后的 bpm）
```

**MIDI 只在验收里出现**：`doublepress_demo_*.ogg` 是从同名 `.mid` 合成的，
所以那对文件是唯一能算"到底偏了多少"的尺子 —— 它是**测试的输入**，不是流程的输入。
`FallenEra_MaySnow.ogg` 是纯 OGG 跑通的（下方 6.3 有它的输出）。

### 6.4 对 F2（倍频）的修正

原判：`estimate_bpm` 返回 240 而真值 120 ⇒ 倍频错误是根因之一。
**现在看这是不准确的**：周期精修之后，倍频**不再产生偏移** ——
240 的 1/6 网格（41.667ms）和 120 的 1/12 网格是同一条格子，
吸附到哪条格子上，绝对时间都是对的。

倍频真正影响的是**谱面结构**（`base_bpm` 决定直线/速度/量化词表），
而且它和"网格分辨率够不够"纠缠在一起：本例 240/6 恰好给了够细的格子，
真按 120 去建 1/6 网格反而**更糟**（一个音符单位落在两格之间）。
所以 F2 要做的话，必须**和"网格分辨率自适应"一起做**，单独改 `start_bpm`
可能变坏。→ 暂时降级为独立课题。

### 6.5 检波偏置的性质：**它是检波器参数的常量**

`tools/_ogg_impulse_calib.py` 用**合成脉冲**走同一条检测代码量偏置（**不需要任何素材**）：

| 嗓音 | 检出偏置 中位 | MAD |
|---|---|---|
| 单样本脉冲 | −38.35ms | 0.77 |
| 3ms 噪声爆发 | −38.05ms | 0.94 |
| 20ms 衰减正弦 | −38.01ms | 1.08 |

⇒ `−38.1 ± 0.2ms`，**与素材无关**，只取决于 `n_fft=2048 / hop=64 / sr=22050`。
理论也对得上：flux 峰值出现在"瞬态**刚进入** STFT 窗"那一帧，
而窗半宽 `n_fft/2 = 1024` 样本 `= 46.4ms` ⇒ 峰值必然提前约 0.8×46.4 ≈ 38ms。

这条性质给了 F4 一个**不依赖素材的兜底方案**（见 6.6，目前未接）。
