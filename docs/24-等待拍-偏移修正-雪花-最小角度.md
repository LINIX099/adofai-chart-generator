> 来源：用户 2026-10 的报障与需求（4 条）。
>
> ```
> bug：1. 在遇见一个需要等待的拍时 更喜欢用缓速 而不是暂停节拍
>      2. 偏移修正 看起来没有被正确使用
>      3. 雪花逻辑 还是陈旧的逻辑，允许使用参数的部位极少

## 1. 先复现：四个问题各自量到了什么

| # | 用户口径 | 实测（改之前） | 根因 |
|---|---|---|---|
| 1 | 等待拍该用**暂停节拍**，别用缓速 | Automaton/FallenEra/MemoryLocked 的「1~6 拍等待」里 **Pause 只占 0.6% / 2.7% / 3.1%**，其余全是减速档 `k>1` | UI 的 `pause_min_beats` 默认被钉在 **4.0**（旧 Qt 的遗留值），而 `SolveParams` 的本意是「不设下限」 |
| 2 | 偏移修正没被正确使用 | 载入 **ogg** 时 `entry/hit` 与音频差**一整个 offset**（实测 1529ms；`docs/21` §5 早先量到 2313ms）；播放器自带的「音乐延迟补偿」**一次都没被调用过** | ① `audio_for_current()` 对 MIDI/OGG 是两副面孔，而 offset 一律按「补了前置静音」算；② `preview-embed` 没暴露 `setMusicDelayMs` |
| 3 | 雪花逻辑陈旧、能用参数的地方极少 | `use_snowflake=True` 时 **Automaton 第三方反解 FAIL：max 324348us**（= 2 拍 @370bpm），**FallenEra 报 2~4 处 `twirl_on_setspeed`** | `_apply_snowflakes` 把「拨正/拨回 Twirl」拨到了**新长出来的 SetSpeed 格**上，`writer.build_actions` 又偷偷把它往后挪 → angleData 与 Twirl 错位 → 反解少读一次奇偶 |
| 4 | 需要「最小角度」 | 最小 travel 掉到 **22.5°**（`TRAVEL_SOFT_MIN=20°` 只写在常量里，DP/合并/双押各走各的） | 没有这个参数，也没有统一入口 |

## 2. ① 等待拍 → 暂停节拍

### 改了什么

| | 改前 | 改后 |
|---|---|---|
| `pause_min_beats` 默认 | UI `4.0`（core `0.0`，两边不一致） | **`1.0`**，且 UI 默认改为**直接读 core** |
| 参数标签 | `Pause 阈值` | `等待拍阈值`（help 写清「超过就暂停，而不是减速爬过去」） |
| Pause 格的速度档 | 无条件沿用前一格 | 沿用**只在「沿用后仍留下真暂停」时**才用，否则退回 `k=1` |

### 关键坑（这是「缓速」没被消灭的真正原因）

Pause 格的暂停拍数是

```
duration = (travel/180 + pb)·60000/(base/k) = (1+pb)·60000·k/base
必须 = r·60000/base      ⇒      pb = r/k − 1
```

旧代码为了让「暂停前后不多发 SetSpeed」，让 Pause 格**沿用前一格的速度档**。可前一格若是减速档（比如 `k=2`），那么

```
r = 2 拍，k = 2  ⇒  pb = 2/2 − 1 = 0      ← 暂停被吃干抹净
```

于是「等待」又变回 `travel 180 @ k=2`——**行星慢慢爬过去**，正是用户嫌的那个。

现在加了下限 `PAUSE_MIN_BEATS = 0.25`：沿用后 `pb < 0.25` 就退回 `k=1`（`pb = r−1`，永远是真暂停），代价是暂停前后各多一个 SetSpeed —— 用户口径里这比「缓速」值得。

### 验收（`tools/_wait_summary.py` / `tests/test_wait_angle_snow.py`）

合成谱（120bpm，间隔 1,1,2,3,1 拍）：

```
改前  Pause = [0, 0, 0.00, 0.50, 0]      ← 2 拍那处什么都没停
改后  Pause = [0, 0, 1.00, 2.00, 0]      ← 3 拍 = travel 180 + Pause 2 拍
      速度档 k = [2, 2, 1, 1, 2]          ← **等待格不再有减速档**
```

真实样本（默认参数，`tools/_wait_modes.py` 的 A/B）：

| 样本 | 阈值 4.0（旧 UI） | 阈值 1.0（新） |
|---|---|---|
| Automaton_Waltz | 直线率 **49.7%** · SetSpeed 59 · Pause 7 · 时序 167us | 直线率 **70.1%** · SetSpeed 157 · Pause 321 · 时序 **45us** |
| FallenEra | 直线率 57.0% · Pause 14 · 抖动 off45 **35.9%** | 直线率 **77.0%** · Pause 232 · off45 **18.1%** |
| MemoryLocked | 直线率 47.2% · Pause 13 · Pause 格 13 | 直线率 **93.3%** · Pause 138 · 减速档 85→**11** |

想退回旧行为：把「等待拍阈值」调到 4 即可（参数还在，只是默认值变了）。

## 3. ② 偏移修正

两件事都叫「偏移修正」，都缺了：

### 3.1 谱面侧：offset 的轴口径（实测 1529ms 的错位）

`session.audio_for_current()` 是**两副面孔**：

| 输入 | 交出去的音频 | 补了多少静音 |
|---|---|---|
| MIDI（无源音频） | `synth.render(lead_ms=preview_lead_ms)` 重新合成 | `S = preview_lead_ms` |
| 有 `source_audio`（ogg/mp3） | **原始文件原样返回** | **`S = 0`** |

而 offset 的口径是

```
游戏时刻 = offset + entryTime      音频时刻 = 该文件里的时刻
⇒ offset = onsets[0] + S − entryTime[0]
```

旧代码**无条件**把 `S` 当成 `preview_lead_ms`，于是 ogg 的「建议 offset / 自动 offset」全都多算了 `lead`。

新增 `Session.audio_lead_ms()`（唯一真源）+ `shipped_len_ms()`；`_offset_check` / 自动 offset / 导出 / 看板的 `tail_gap` 全部改用它。自动 offset 现在直接复用 `_offset_check` 的 `suggest_ms`（双押安全，不会另写一套公式）。

### 3.2 前端侧：payload 的轴口径（`docs/21` §5 的遗留）

`docs/21` §5 记录过一个「按你要求暂不处理」的问题：预览音频与谱面轴差 `offset − lead`（当时量到 −2313ms）。这次一并修掉，并把它变成**通用口径**：

```
采音轴 = 谱面轴 + audio_shift_ms            （audio_shift_ms = offset − audio_lead_ms）
<audio> 轴 = 采音轴 + audio_lead_ms
```

- `payload` 里**所有时刻**（`entry` / `times` / `hit` / `falls` / `cap`）统一输出在**采音轴**上 —— 和 `notes`（来自 MIDI/OGG 的音头）终于同轴了。以前 `notes` 在采音轴、`entry/hit/falls` 在谱面轴，MIDI 下 `S == lead == 首格时刻` 恰好重合所以看不出来。
- 前端只留两个换算函数（`audioToGrid` / `gridToAudio`）+ 一个 `gridToChart`（喂给内嵌 ADOFAI 播放器）。滑块、拖动全曲条、`curFloor()`、`addRegionAtPlayhead()` 都走它们。
- 顺带修了一个**真实的时序 bug**：自动 offset 开启时，第一次 rebuild 的 `payload.offset` 还是旧值（前端要等回填才写回），现在 `payload` 直接收**本次生效的 offset**。

### 3.3 播放侧：播放器自带的「音乐延迟补偿」终于接通

Re_ADOJAS 的 `Player` 有 `setMusicDelayMs` / `getMusicDelayMs` / `getSuggestedAudioDelayMs`（独立于谱面 offset 的设备输出延迟修正，`Player.ts:106,566,638`）。我们的 `preview-embed` **一个都没暴露**。

现在：`PreviewHandle` 增加 `setMusicDelayMs` / `getMusicDelayMs` / `getSuggestedMusicDelayMs`，`PreviewOptions` 增加 `musicDelayMs`；前端在「谱面预览」控制条上给了控件与「按实测建议」按钮（播放中改立即生效，不重算谱面）。

另外把导出用的「建议 offset」做成**一键应用**按钮（以前只印在状态栏里，得手抄）。

### 验收

`tools/_axis_probe_v2.py`（三种输入各取 `hit[i] − onset[i]` 的均值）：

| 输入 | `hit[i]`（改后） | 结论 |
|---|---|---|
| FallenEra_MaySnow.**ogg** | **−0.630ms** | 已知的检波偏置常量，不是错位 |
| FallenEra_MaySnow.onset.mid | −1.991ms | ✓ |
| MemoryLocked.mid | **0.000ms** | ✓ |

`tools/_wait_summary.py` 再加一条：用**建议** offset 时 `max|hit − onset| ≤ 0.045ms`。

## 4. ③ 雪花：修时序错位 + 放开参数

### 4.1 时序错位（324ms 的真根因）

雪花给段内每格写一个**非 2 的幂**的速度档（绝对匀速的要求），于是**段的边界立刻多出 SetSpeed**。旧流程是：

```
… → _finish（把 Twirl 从 SetSpeed 格挪开，此时只知道**旧的** SetSpeed 集合）
   → _apply_snowflakes（换速度档 ⇒ 新长出 SetSpeed，而 Twirl 已经拨到那儿了）
   → _apply（按当前 travel+flips 算 angleData）
   → writer.build_actions（又发现「Twirl 与 SetSpeed 同格」→ **再挪一次**）
```

写盘那一次挪动**发生在 angleData 算完之后**，于是文件里的 Twirl 与 angleData 不对应：反解器按 `angleData + Twirl 事件` 反推 travel 时少读（或多读）一次奇偶翻转，下游整段偏 180°。实测 Automaton_Waltz 第 385 格起累积 **+324.348ms**（正好 2 拍 @370bpm），第三方双射校验 FAIL。

修法：

1. `_apply_snowflakes` 改**两遍式**：先预演「雪花写完之后的 BPM」得到**未来的 SetSpeed 集合**，段前拨正 / 段尾拨回**只挑该集合之外、且不在任何雪花段内的直线格**（拨直线格不动物理：`turn` 两种 parity 都是 0）。
2. 新增 `_relocate_twirls()`，并把它排在 **`_apply_snowflakes` 之后、`_apply` 之前** —— 这样挪动会连带重算几何，模型与文件永远一致。
3. **`writer.build_actions` 不再擅自挪 Twirl**：只忠实输出，把撞车位置记进 `ch.meta["twirl_on_setspeed"]` 交给 `rules` 报错。宁可报错，也不能悄悄改几何。

验收（`tests/test_wait_angle_snow.py`）：

| 样本 | 改前 | 改后 |
|---|---|---|
| Automaton_Waltz（2 朵 / 144 格） | 违规 1（`twirl_on_setspeed`）· 反解 **FAIL 324348us** | 违规 **0** · 反解 **OK 23.6us** |
| FallenEra（2 朵 / 48 格，min4 时 4 朵） | 违规 2~4（`twirl_on_setspeed`） | 违规 **0** · 反解 OK 34.9us |

`A3.7` 里那条「雪花有既存 324ms 时序差，先别开 `sticky_speed`」的记录**到此为止**：雪花段本身已经自洽。`sticky_speed` 是否重开另说（它还有别的约束）。

### 4.2 参数太少（「允许使用参数的部位极少」）

原来 UI 只有 4 个雪花参数（开关 / 起用格数 / 100% 格数 / 对称阶数），而 `snowflake.plan()` 里还有形状、每臂步数、紧凑优先、随机采样这些能力**根本没接线**。

新增 6 个参数并全部透传到 `plan()`：

| 参数 | 默认 | 含义 |
|---|---|---|
| `snowflake_shape` | `auto` | 花瓣形状：自动（穷举取最花）/ 均匀 / 前重 / 后重 / 阶梯 / 锯齿 / 随机采样 |
| `snowflake_min_arms` | 2 | 一条花瓣最少走几步（整朵 = 2×步数×N 格） |
| `snowflake_compact` | 勾 | 同分时优先包围盒小的 |
| `snowflake_uniform_tol_ms` | 3.0 | 【原来就存在但没暴露】判定「等间隔段」的容差 |
| `snowflake_random` | 不勾 | 用随机采样代替穷举（同一份输入 + 同一种子仍可复现） |
| `snowflake_seed` | 20240213 | 【原来就存在但没暴露】种子 |

`plan()` 也补了 `shapes` / `travel_min` 两个入参（最小角度对雪花同样生效，`travels()` 全部 ≥ `travel_min` 才要这朵）。

验收：`snowflake_shape∈{uniform,step,zigzag}` 三个值都能在 `ch.meta["snow_shapes"]` 里看到；`plan(travel_min=170)` 要么不产、要么全格 ≥170°。

## 5. ④ 最小角度

新增 `SolveParams.travel_min`（度），UI「④ 求解」里的**最小角度**，默认 **20°**（= 原 `TRAVEL_SOFT_MIN`）。

它替换了散落各处的写死常量，逐条生效：

| 位置 | 原来 | 现在 |
|---|---|---|
| DP 候选（`_tier_options`） | 软约束写死 20° | `max(TRAVEL_SOFT_MIN, travel_min)`；取不到就**逐级放宽**（软 → 硬 → 最近 2 的幂），保证任何 Δt 都有解 |
| 速度档合并（`_merge_short_runs`） | 只守 15° 硬下限 | 并档后也必须 ≥ `travel_min` |
| 速度档粘性 | 用 `natural_travel_min` | `max(natural_travel_min, travel_min)` |
| 自然闭合段 | `natural_travel_min` | `max(natural_travel_min, travel_min)` |
| 三连音引擎 | 常数 45° | 低于 `travel_min` 整段放弃，交回 DP |
| 中旋双押（剩余格） | `MIN_TRAVEL=15` | `max(15, travel_min)` |
| 角度双押（剩余格） | `MIN_TRAVEL=15` | `max(15, travel_min)` |
| 雪花 | 无 | 整朵里任何一格 < `travel_min` 就不要这朵 |
| `rules.check_chart` | 无 | 新增 `travel_below_min` 报错 |

**豁免**（机制需要的形状，不是排版失误）：双押薄格 θ = 15°/30°、中旋折返格、`dp_pairs` 里登记过的格。

验收（Automaton_Waltz）：

| `travel_min` | 实测最小 travel | 违规 | 直线率 |
|---|---|---|---|
| 20°（默认） | 22.50° | 0 | 70.1% |
| 45° | **90.00°** | 0 | 80.9% |
| 60° | **90.00°** | 0 | 80.9% |

（调大最小角度会把细碎小角度的格推去别的速度档，直线率反而上升。）

## 6. 顺带修的两个小东西

1. **状态栏的「⚠ 规则违规」把 `info` 也算进去了**：`info`（雪花速度档豁免、双押中旋说明）本来只是提示，却被计成违规并打上 ⚠。现在 `n_violations` 只数 `level != "info"`，提示另计。
2. **两次 rebuild 之间的 `payload.offset`**：自动 offset 开启时第一次 payload 用的是旧 offset（要等前端回填）。现在 `payload()` 收本次生效的 `offset`，`_falls` / `cap_times` 也跟着用同一个值。

## 8. 还没做 / 已知边界

1. **`zoom: 200` 的取景**：内嵌播放器里行星略偏（+170/−68px）。与 Re_ADOJAS 自带样例的 `zoom: 100` 不一致，但**没有证据**说是这个造成的，仍未动（同 `docs/22` 的记录）。
2. **`dp_offset.py` 依然是死代码**：角度双押的 `[θ, T−θ]` 拆法**零净偏移**，中旋双押的恒等式也让单格零偏移，所以那套「累计偏移 → angleOffset/Pause 回正」在当前两条双押路径上都不需要。留着（`tests/test_dp_offset.py` 继续验公式），哪天出现会累计偏移的插入法再启用。
   > ★ **2026-10 复核（`docs/32` §3）**：用户怀疑「双押偏移没按公式修回去」。
   > 实测 —— **角度双押精确 0**；**中旋双押**确实每个主音都**偏晚 ≤1.8ms**，
   > 但那是 `dp_old2new` **指错了格**（指到被吃掉 Σs 的原格，而不是第一个折返格 X），
   > **不是时长问题**，所以 `docs/16` 的公式也修不了它 —— 改映射后三首样本全部 ±0.000ms。
   > 上面「死代码」的结论**不变**：公式仍然不需要启用。审计：`tools/_dp_offset_audit.py`。
3. **等待拍阈值 1.0 的代价**：Pause 与 SetSpeed 事件数都会上升（Automaton SetSpeed 59→157、Pause 7→321）。这是「宁可多事件，也不要缓速爬」的口径选择；不认同就把阈值调回 2~4。
4. 播放下落式/卷帘页与内嵌 ADOFAI 播放器仍是**两根时钟**（`docs/21` §4），这次只统一了它们与 payload 的**轴**，没有合并时钟。
