# 39 · 分段采音

> **一句话**：把「区间」换成**音轨角色时间轴** —— 让**主 / 次 / 双押三个角色
> 都随时刻变**，而且**边界不再参与聚簇**。
>
> 这是 `docs/34` §3 **方案 C** 的落地。之所以一次做到 C 而不是原计划的 B→C，
> 见 `docs/34` 顶部 2026-10 的更新说明（B 的价值基本被 C 覆盖，而 C 是 B 的超集）。

***

## 1. 数据模型

```jsonc
// state.segments —— 一份可序列化的编排表（跟着界面状态一起存/载）
[
  { "at_ms": 25550, "label": "B段",
    "main": [1, 3],     // ★ 三个维度各自三态：
    "sub":  null,       //   null = **继承**全局「② 音轨」的选择
    "dp":   [] }        //   []   = **显式关掉**（这一段不用这个角色）
                        //   [1,3]= 显式指定
]
state.segment_mode = "from" | "until"   // 语义，见 §2
```

**`null` 与 `[]` 必须能分开** —— 这是整个方案的地基。否则
「这一段别动次级」和「这一段次级一条都不采」会写成同一个数据，
而 P4 的两个高频场景（**降级**某轨 / **只留**节拍器）就表达不出来。

> 键名 `segment_mode` **带命名空间**是刻意的：一开始用了裸 `"mode"`，
> 结果和 `state` 里别的字段撞车，`until` 被**静默忽略**（实测踩到）。
> 现在 `tests/test_segments.py` 有一条断言钉住这件事。

***

## 2. 两种语义（互为镜像）

    模式 "from"（默认）                模式 "until"
    ──────────────────────            ──────────────────────
    [0,   at0) 全局(② 的三条列表)       [0,   at0) 段0
    [at0, at1) 段0                     [at0, at1) 段1
    [at1, end) 段1                     [at1, end) 全局

`from` = 点说的是「**从这点起**用这几条轨」（`docs/34` P6：真实编辑绝大多数
是「从第 N 小节起往后都用这几条轨」）。`until` = 「**到这点为止**」。

两者**切点逐点相同、片数相同**，只是「谁吃哪条规则」反过来 ⇒ 在 UI 上换模式
是零成本的（不用重画，只重算归属）。这是**唯一一个仍然留给用户的语义选择**，
做成了一个下拉框（`#sel-seg-mode`），默认 `from`。

***

## 3. 边界为什么不再吃音（P3 的真正病根）

老 `apply_regions` 是**先聚类、后切割**：

```
base = build_onsets(全局轨的音)          # ← 在整条轨上聚簇
r_on = build_onsets(区间轨的音)          # ← 也在整条轨上聚簇
r_on = [o for o in r_on if t0 <= o.t_ms < t1]   # ← 切在**聚完之后**
out  = base(区间外) + r_on
```

`build_onsets` 的簇是「距**簇头** ≤ `merge_ms`」的传递闭包。所以当**簇头**
落在边界外侧时，它被筛走，**簇里的音跟着整簇消失**。

分段采音改成**先切割、后聚类**，而且是**全曲只聚一次**：

```python
# 第 1 趟：每片按自己的角色算「这一段该有哪些音」（这里按片切）
pool = []
for t0, t1, seg in spans:
    notes = 主轨(该片) ∪ 次级(该片，只插主轨的空隙)
    pool += notes
# 第 2 趟：全曲拼成一个大池，只跑一次聚类 ⇒ 边界**不参与聚类**
onsets = build_onsets(pool, params)
```

于是**边界只决定「谁进池」**，不影响「谁跟谁并成一次按键」。

### 实测（`tools/_seg_probe.py`，20000 组随机输入）

| | 例 1 | 例 2 | 例 3 |
|---|---|---|---|
| 老做法 | `[40, 70, 260]` | `[50, 260, 450]` | `[60, 240, 530]` |
| 先切后聚（= 分段采音） | `[40, 260]` | `[50, 220, 260, 450]` | `[30, 80, 240, 530]` |
| 症状 | **凭空多 1 个** | **吃掉 1 个** | **吃掉 1 个** |

**555/20000（2.8%）**的结果不同，**双向**出错（既吃音、也凭空多音、还会把音
挪到别处）。附带修掉一个 off-by-one：老尾巴去重用 `<`、片内聚类用 `<=`。

`tests/test_segments.py` C 组把老算法**照抄一份**当对照组，三例逐一钉住；
再用 400 组随机「区间 vs 分段」对拍，要求**逐一相同**。

### 不变量（C 组的核心断言）

两片角色**完全相同**时，边界必须是**空操作**：把边界从 400ms 挪到 2500ms，
结果**逐点不变**，且恒等于「全曲并集真值」。这条断言是专门用来防止
「先丢后插」那套实现偷偷回来的。

## 5. 与「区间」的关系

**区间原样保留**，但：

```
有分段  ⇒  分段**整个取代**区间（含取代「步骤 4 全局主轨」那一段，
           因为分段的第二片本来就是「全局」）
没有分段 ⇒  区间路径**逐字节不变**（golden 9/9 未变）
两者都有 ⇒  分段优先，并往 `warning_list` 里**明确报出来**
           （「★ 区间与分段同时存在：分段优先，区间已整个忽略」）
```

「不许静默」的具体落实：

* 有分段时状态栏多出「分段 N 段（M 段生效 / 共采 K 点·从这点起）」；
* **某一段一个点都没采到**（比如你把它三档全关了）⇒ 逐段列出轨号警告；
* **簇跨了边界**（相邻两次按键被 `merge_ms` 并成一次）⇒ 报 `n_cross` 条数；
* `warning_list` —— ★ 顺手修了一个**一直存在的哑弹**：`app.js:604` 一直在读
  `r.warning_list`，而后端**从来没人生产这个键** ⇒ 「⚠ N 条警告」那条 UI
  一直是死的。现在后端补上了。

## 6. 顺手补的三件事

1. **`core/bdg/parse.py::role_track_role()`** —— 分段自动填充**只认我们插件的
   角色轨**（`<pluginId>:<main|sub|dp|off>`）。不能复用 `role_for_type`：
   它把**内置踩点轨**当主音轨（对采音是对的），但拿它当「角色指令」会让
   **每条普通轨凭空多出一批分段**；它把宿主 `bpm/twirl` 控制轨当 `off`
   （不采音，对），但那些点上是**变速**，不是角色。
2. **`derive()` 的音高覆盖**扩到分段轨 —— 与区间同一个哑弹：分段改用的轨会被
   自动改写的 `pitch_lo/hi` 整条滤没（实测区间那边会变成 0 个点）。
3. **`payload.segments` + `overview._drawLanes()`** —— 泳道只画**分段显式指定过**
   的角色块（`null` = 继承的**不画**）⇒「不画 = 今天的行为」，一眼看出哪被改过。

## 7. 怎么用（用户视角）

**手工画**：② 音轨 → 「分段采音」→ `＋ 加分段`（默认三维全继承）→
把想改的那一维从「继承」点成具体轨，或点「全关」；时刻用数字框或「取播放头」。

**从 BDG 一键生成**：在 BDG 里用我们的四个轨类型（主轨 / 次轨 / 双押轨 / 关轨）
摆点 → 回我们的工具点「从 BDG 角色轨生成」→ 角色轨上的点被编译成 `from` 模式的
分段（**累计快照**：后面没再出现的轨保持上一次的角色；只有**出现过**的维度才
写成显式，其余仍继承全局；净效果没变的点会被省掉）。

**看结果**：全曲预览条下半部分就是泳道 —— 蓝=主、青=次、琥珀=双押，
虚竖线 = 段界。数一下色块就知道哪几段被改过。

## 9. ★ 一个必须让你先知道的语义后果（**等你拍板**）

上面那 5 个「主轨」点（0.07 / 0.625 / 0.8 / 2.4 / 5.5）只生成了 **1 条规则**：

```
from 模式 + 累计快照  ⇒  同一条轨同一个角色打多次，净效果没变 ⇒ 合成一条
「从 0.07 拍起，主轨 = trk1」一直到曲末
```

这在 `from`（从这点起）的语境下是**对的**，但它对应两种可能完全不同的用户预期：

| 你的意思 | 现在的行为 | 能不能表达 |
|---|---|---|
| 甲「从这儿起，主轨换成 trk1，一直到曲末」 | ✅ 正是这个 | ✅ |
| 乙「主轨只在 0.07 / 0.625 / … 这几个**拍位**上生效」（**闸门**读法） | ❌ 会被合成一条 | ❌ **现在表达不了** |

面板**会报出来**（`生成 N 条分段（共 M 个角色点）`，`M > N` 就是被合并过的），
所以**不会静默骗你**。但如果你要的其实是**乙**，那得再加一档「闸门/区间」语义
（点 = 「**这一段**用这几条轨」，段与段之间回落到全局）。

**请你在真机上试一次再告诉我**：在 BDG 主轨上打 3 个点，看生成的泳道是不是
你要的形状。这条也写进了 `docs/34 §6` 的第 1 问 —— 它是唯一还悬着的设计问题。
