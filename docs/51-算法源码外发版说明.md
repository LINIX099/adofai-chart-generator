# ADOFAI 谱面生成器 · **算法源码**（外发 / 学习交流版）

> **这是什么**：一个把「音符数据」自动排成 ADOFAI（A Dance of Fire and Ice）谱面的
> 求解器的**算法本体** —— 采音、几何求解、双押/三押插入、时序模型、规则校验、导出。
>
> **这不是什么**：不含 Electron 界面、不含 BDG 宿主桥接、不含**任何**第三方曲目
> 音频或音符数据。想跑界面请拿完整仓库。
>
> 出处：‹仓库根›（打包时私有路径已抹掉）· 版本 **0.4** ·
> 用途：**学习 / 交流 / 传播算法本身**。

## 0. 30 秒上手（不需要任何外部素材）

包里自带一份**自制**演示素材（`tools/make_doublepress.py` 生成的，可再生成）：

```bash
python - <<'PY'
import sys; sys.path.insert(0, ".")
from core import midi, onsets, solve, writer, rules

m  = midi.load("samples/audio/doublepress_demo_120.mid")
tr = max(m.tracks, key=lambda t: len(t.notes))   # ★ 演示素材里 trk0 是空的 ⇒ 按点数挑
ons = onsets.build_onsets(tr.notes, onsets.OnsetParams(merge_ms=30.0))
ch  = solve.solve(ons, solve.SolveParams(ppqn=m.ppqn, midi_bpm=m.bpm0))

print("层数", len(ch.floors), "直线率 %.1f%%" % (ch.straight_frac * 100),
      "SetSpeed", ch.n_speed_events, "Twirl", ch.n_twirl)
print("规则违规", [v["code"] for v in rules.check_chart(ch)
                   if v.get("level") != "info"])
writer.write_dir(ch, "out_demo", name="main", audio_src=None)
PY
```

跑完 `out_demo/main.adofai` 就能直接丢进游戏 / 用第三方 parser 反解。
（想把音频一起给，就 `from core import synth; synth.render(m, "out_demo/main.wav", ...)`
再把它当 `audio_src=` 传进去。）

## 1. 一句话数据流

```
MIDI / OGG / 毫秒时间戳 / BDG 工程
        │  ① 采音 core/onsets.py · core/audio_onsets.py · core/midi.py
        ▼
    onset 序列（t_ms, pitch, velocity）
        │  ② 量化 + 选基准 BPM   core/solve.py::_prepare_rhythm
        ▼
   每格「占几拍 r」序列
        │  ③ 几何求解（二选一）
        │     老路径 = 逐格 DP 选速度档 + 图形评分器
        │               core/solve.py · core/figures.py
        │     对音阶梯 = 逐音降级（图形→当前档→加Twirl→变速→暂停）
        │               core/ladder.py
        ▼
   每格 travel / speed_k / Twirl       ← 时长 **已经** 保证精确
        │  ④ 双押 / 三押拆分（把一格 180° 拆成 [θ, 180−θ] / [θ₁,θ₂,余量]）
        │     core/dp_angle.py（含核心表 core/dp_offset.py · core/dp_midspin.py）
        ▼
   最终层序列（含薄格 / Twirl 重排 / 回正）
        │  ⑤ 体检 + 导出   core/rules.py · core/verify.py · core/writer.py
        ▼
   main.adofai
```

## 3. 算法地图

### 3.1 输入层

| 模块 | 职责 | 要点 |
| --- | --- | --- |
| `core/midi.py` | 读 MIDI → `MidiFile{tracks[Note]}` + `bpm0` + `ppqn` | 只有「音符」概念，不猜角色 |
| `core/audio_onsets.py` | OGG/WAV → 音头（检波） | 自洽网格吸附 + 检波偏置校正（`test_ogg_offset` 卡 ≤15ms） |
| `core/ts_source.py` | 毫秒时间戳 → 伪 MIDI | 一行一个数 / CSV / `mm:ss.xxx` / JSON |
| `core/onsets.py` | 音符 → **onset**（合并/去重/音高过滤/插空） | `OnsetParams`：`merge_ms` / `merge_anchor` / `min_velocity` / `min_interval_ms` |
| `core/segments.py` | 区间采音 / 分段采音 / 双押音头（`dp_marks` 带**源轨号**） | 「哪一段用哪几条轨」不影响下游一行 |

### 3.2 时序层（**这一层决定谱子准不准**）

| 模块 | 职责 | 要点 |
| --- | --- | --- |
| `core/rhythm.py` | 音值提取（r = 占几拍） | |
| `core/solve.py::_prepare_rhythm` | 量化 + 自动选基准 BPM + 参考音值 | `choose_reference` 最大化「直线率 − 事件率」 |
| `core/denoise.py` | 抖动的时间戳先**吸到格上** | 砖长众数 + 吸附分母 + 半径（保真档） |
| `core/gridfit.py` | 自洽网格拟合（相位 φ + 周期） | |
| `core/fitdirect.py` | **直拟合**：一砖一音、时序逐点精确 | 几何只能靠换档，换来「零漂移」 |
| `core/xkbase.py` · `core/bigline.py` | **采bpm 大直线**：无视音符排列，硬铺等间隔骨架 | 绝对对拍、绝对不好看 ⇒ 必须配多押 |
| `core/synth.py` | 合成节拍音频（预览/导出用） | 前置静音 `lead_ms` 是 offset 公式里的 `S` |
| `core/triplet_engine.py` | 三连音连续段：恒定 travel + 交错 Twirl | 保证「朝向回正」 |

### 3.3 几何层

| 模块 | 职责 | 要点 |
| --- | --- | --- |
| `core/path.py` | **唯一几何真源**：`travel/twirl → heading/坐标` | `turn = (travel+180)%360`（有 Twirl 取 `180−travel`） |
| `core/solve.py::solve` | 老路径主循环：DP 选档 → 图形 → 回正 → 雪花 | 见 §4/§5 |
| `core/figures.py` | **图形候选 + 单一评分器**（自然闭合段 / 三连音 / DP 对照） | 原地惩罚在这里（§7） |
| `core/ladder.py` | **对音阶梯**：逐音降级（用户 5 级硬序） | `aggressive_pick=True` 才走 |
| `core/templates.py` | 手写节奏型模板（照抄人类谱师的排版） | 优先级最高 |
| `core/snowflake.py` | 魔法阵（雪花）：绝对匀速的长对称花 | 等间隔段才下 |
| `core/straighten.py` | **角度回正**：只改 Twirl 符号，**不动 travel** | 时序零影响 |
| `core/track_fx.py` | 叠在一起的圈逐格错开（`PositionTrack`） | 只动渲染 |

### 3.4 多押（双押 / 三押）

| 模块 | 职责 |
| --- | --- |
| `core/dp_offset.py` | 双押偏移/回正的**公式**（`angle_offset` 语义） |
| `core/dp_midspin.py` | **中旋双押**：折返格写法 |
| `core/dp_angle.py` | **角度双押 / 三押**：把一格拆成 `[θ…, 余量]`；规定写法表；押数记账 |

| `core/writer.py` | 导出 `.adofai`（`angleData` + `actions` + `settings`） |

## 4. 五条铁律（**不是风格，是正确性**）

1. **时序零偏移**：一格时长只由 `(r, k)` 决定 ——
   `dt = (travel/180)·(60000/bpm)`，而 `travel = 180·r/k`、`bpm = base/k`
   ⇒ `dt = r·60000/base`，**与 k 无关**。
   ⇒ 所以「换速度档」「拆薄格」都**不改时长**（这是所有几何自由度的来源）。
2. **Σtravel ≡ 180·格数 (mod 360)**（回正）：不满足就**逐格漂角**，最后漂成斜线。
3. **直线率 > 45%**：直线层多 ≈ 手感好（用户红线）。
4. **不许静默**：丢了几个音、跳过什么、哪个参数被忽略 —— 一律上报。
5. **老路径逐字节不变**：`tests/golden/off_hashes.json` 冻结哈希机器验收
   （改默认行为**必须**显式重冻并在注释里说明）。

## 5. 三条数学事实（决定「能不能拐弯 / 能不能直走」）

```
turn = travel − 180            （无 Twirl；有 Twirl 取 180 − travel）
```

1. **同一速度档下，净转角只能是 180° 的整数倍**（`Σtravel = 180·W ⇒ Σturn ≡ 0 mod 180`）。
   ⇒ 我们的谱面本质是**沿 y 轴的梯子**：
   | 写法 | travel | 效果 |
   | --- | --- | --- |
   | 满直线 | 180 | 直走 |
   | 双押 | `[30, 150]` | **折返**（净转角 180°） |
   | 双押塔 | `[30, 330]` | 侧移 +1 |
   | 三押 | `[30, 60, 90]` | 侧移 −1 |
2. **要真拐 90° 必须付「半拍」或「半速拐角格」** —— 这是「走向（左右发展）」的代价，
   不是 bug。
3. **换档不改时长**（§4.1）⇒ 算法可以在**不碰时序**的前提下自由重排 travel，
   这也是「原地惩罚」「回正」「雪花」敢动手的前提。

## 6. 双押 / 三押 写法（规定表，**不按毫秒、不可自定义**）

统一公式（最后一块吃余量）：

```
双押 W=1:  [θ,        180 − θ]
三押 W=1:  [θ₁, θ₂,   180 − θ₁ − θ₂]      （θ₁+θ₂ 必须 < 180）
```

| bpm 窗口 | 双押 θ | 三押 `θ₁·θ₂` | 出处 |
| --- | --- | --- | --- |
| cbpm ≥ 840 | 90°（连续双押 ≥4 个仍 30°） | — | 语料 |
| cbpm ≥ 300 | 30° | `30·60`（余量 90） | 参考谱 `three_press_interact.adofai` 实测 |
| cbpm < 300 | 15° | `15·15`（余量 150） | 语料 + 用户口径 |

- **判据**：`押数 = 1 + 同时有音的 dp 轨数`（±`dp_tol`）——
  一条 dp 轨连续响两下**不算**三押，看的是**同时**。
- **四押 / 5 押不做，但必须记账并上报**（降级成双押 + `extra_press`）。
- **调速与双押**：`(当双押使用变速) 调速必须不与旋转重叠、且位于双押的第一格`
  ⇒ 拆完 SetSpeed 自然落在**第一块薄格**上，那一格**不叠 Twirl**。

### 6.1 两条实现路径的**时序**差别（实测 · 选默认值时必须知道的）

| 路径 | 做法 | 双押样例·密集主轨（328 个 166.67ms 的音）按键时刻误差 |
| --- | --- | --- |
| **角度双押** `dp_mode=1`（**默认**） | 拆格 `[θ…, 余量]`，θ 查**规定写法表** | **0.000 ms** ✅ |
| **中旋双押** `dp_mode=0` | 中间插 `999` 折返格（整砖折返） | **9.722 ms** ⚠ |

- 这个 9.7ms 与「原地惩罚」**无关**（`inplace_waste=False` 时一模一样），是
  「密集音（166.67ms）+ 240bpm 的 250ms **整砖** + 中旋只能整砖折返」的**固有量化误差**。
- 角度双押能把时间精确落在一格**中间**，所以它是「时序最准」的那条 ——
  这也正是用户口径（「双押就是一个不同 bpm 窗口下均匀使用的多种规定写法」）对应的实现。
- 所以：**默认走角度双押**，中旋留给老写法习惯；两条路径都保留（`core/dp_midspin.py` /
  `core/dp_angle.py`）。

### 6.2 三押开关（`three_press_mode`）

| 值 | 行为 |
| --- | --- |
| `0` **拆三押**（默认） | 押数 ≥ 3 ⇒ `[θ₁, θ₂, 余量]`（`docs/48` 的行为）|
| `1` **不拆** | 押数 ≥ 3 的那一组仍按**双押**插一格（记 `three_off`）|
| `2` **跳过** | 押数 ≥ 3 的那一组**连双押也不插**（记 `press_skipped`）|

`core/dp_angle.plan(..., three_press=, skip_press=)`；判据（押数）**不受影响**，照样数、照样上报。

## 7. 原地打转 & **原地惩罚**（本版新增）

**病根**：评分器的**第一位**判据是「这一段会产生几次 SetSpeed」，
而「一串 `travel=90` 绕小方块」**一次速度都不用换** ⇒
哪怕它**一格都没往前走**，也总能打赢「换两次速度、一路走直线」的写法。
实测 Automaton_Waltz 被这样铺出 **100+ 格 90° 方阵**（原地打转窗口占 12%）。

**修法（两处，都不动时序）**：

```python
# core/figures.py::score
waste = round((1 − prog) × 格数 ÷ 3)      # 每 3 格白转 ≈ 一个 SetSpeed 的代价
score = (changes + waste, −直线格数, 闭合偏好, −prog, 自重叠对数, Twirl 数, −格数, …)
# prog = 净位移 ÷ (格数 × 一格长)   ⇒ 1 = 一路向上 / 0 = 原地打转 / 负 = 往回走
```

- 标定与 `_dp_tiers` 一致（`1 格直线 = 1.0`，`1 次换档 = 3.0`）⇒
  「12 格原地打转 = 4 分」**输给**「2 次 SetSpeed + 一路直线 = 2 分」。
- 另外一个对照项 `dp_candidate` 把「**DP 自己的逐格铺法**」也放进候选：
  它更前进就让图形让路（`choose()` 返回 `None` = 交回 DP 逐格铺）。
- 三连音引擎**不吃**这一项（形状由 `plan_run` 定死，没得挑）。
- `SolveParams.inplace_waste = False` 可一键回到老口径（A/B 与冻结哈希用）。

**实测**（三个样本 · 默认参数）：

| 样本 | 直线率 | 原地打转窗口 |
| --- | --- | --- |
| FallenEra | 56.9% → **59.0%** | 7.1% → **4.3%** |
| Automaton_Waltz | 49.1% → **59.7%** | 12.1% → **5.3%** |
| MemoryLocked | 46.9% → **49.5%** | 3.1% → **0.0%** |

## 11. 已知的坑（读代码前先看一眼，省几小时）

1. **别把「角度」和「走向」混为一谈**：单格 `travel` 由**时值**定（三连音就是 60°/120°），
   宏观走向才受「只拐直角」约束。
2. **`travel = 180` 才是直线**（不是 0）。`0/360` 是回头方块，游戏会特判。
3. **Twirl 不改变时长**，只把写法在 `+(180−T)` / `−(180−T)` 之间镜像 ——
   所以「加一个旋转事件」是**几何**自由度，不是时间自由度。
4. **`preview_lead_ms`（前置静音 S）不等于 offset**：`offset = 首个 onset + S − 第一格`。
   交出去的音频是**原曲文件**时 `S = 0`（`core/synth.py` 与 sidecar 的分工）。
5. **雪花是「外部覆盖层」**：它在主循环之后改段内 BPM ⇒ 会让某些「双押预留槽位」
   长出 SetSpeed，那些槽位必须撤销（`dp_reserve_lost`）。
6. **改默认参数 ⇒ 必须重冻 golden**，否则 `test_ladder` 会（正确地）拦下你。
