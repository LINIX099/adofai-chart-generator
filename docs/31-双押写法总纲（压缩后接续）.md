## 2. 参考谱解码（结论）

### 2.1 参考谱 A `out/双押 常见写法.adofai`（bpm 250，带注释）

> 下表的 `travel` 是**有效值**（奇偶还原后），与 §2.2.1 同一口径。

| 段 | 倍率 | travel 单元（有效） | 合计 | 用途 |
|---|---|---|---|---|
| A | ×2 | **`30, 330`** | 360° = 2 拍 | **双押塔**（「任意情况下都是对的」） |
| B | ×0.5 | **`30, 150`** ×2（raw 写作 `30,150,330,210`） | 360° = 2 拍 | **斜向单元**（连续双押） |
| C | ×0.5 | `30,60` ×4 + 收尾 `30,150` | | 「强弱强」 |
| D | ×0.5 | `30,60` ×8 + 收尾 `30,150` | | 「强弱强弱强（5连）」 |
| E | ×4 | **`30, 330`** ×4 | | 时值相等 |

**两条速度硬约束**（注释原文）：

```
「如果需要调速，那么一定要放在平着的格子上面，否则会判定为不合规」
「如果需要调速，必须提前调好」
```

参考谱里**每段双押之前都有一格 `travel = 180` 平格 + `Pause`** —— 这就是它的落地方式。

**闭合**：`30+330 = 360 = 2×180` ✓；`30+150+330+210 = 720 = 4×180` ✓。

### 2.2 参考谱 B `out/双押交互.adofai`（角度双押 · 满直线）

101 格，单一 `SetSpeed ×4`，**无注释**。重复单元 **10 格**：

```
30, 150, 180, 180, 180,  330, 210, 180, 180, 180        Σ = 1800 = 10 × 180 ✓
dt: 10,  50,  60,  60,  60,  110,  70,  60,  60,  60
```

**用户给的读法（#8）**：

```
4k base  ⇒  cbpm = 4 × tbpm       （250bpm 的歌 → cbpm 1000，正是这里的 settings.bpm×4）
2 格为一拍                        （1 拍 = 250bpm 的 16 分 = 1000bpm 的 4 分 = 60ms）
组成 = [2 1 1 1] [2 1 1 1]        （2 = 双押那两格，1 = 单个格子）
时值：**每一个双押，和单独的一个格子，用的时值是一样的**
```

#### 2.2.1 ★ 已解（原「对不上」的那处）：奇偶还原

**正确的读法**：`core/path.py` 里 Twirl 是**累积奇偶**，算 travel 前先翻转 `ccw`：

```
ccw_i   = 累积奇偶（第 i 格有 Twirl 事件就先翻再算本格）
travel_i = (180 − turn_i)      若 ccw_i        turn_i = norm180(heading_i − heading_{i−1})
           (turn_i + 180)%360  否则            heading_i = 90 − angleData_i
```

只按 `(180 − turn)` 直接算出来的，是**写进文件的 raw 值**；在反向编码的缺口上会差一个
补角（`330 ↔ 30`、`210 ↔ 150`）。原来的 `tools/_dp_ref_analyze.py` 就是这么算的，
于是「一个双押 = 一拍」假性不成立。**工具已修**（现在同时打印 `travel(有效)` 与 `travel(raw)`）。

修完之后 `双押交互.adofai` 的**有效**重复单元是 **5 格**（不是 10 格）：

```
有效:  30, 150, 180, 180, 180        Σ = 720 = 4 拍 ✓     ← 每 4 拍一个双押 ✓
raw :  330, 210, 180, 180, 180   →  30, 150, 180, 180, 180  （每单元变一次写法）
dt  :  10,  50,  60,  60,  60 ms
双押:  第 1、2 格（10ms）—— `30 + 150 = 180° = 1 拍` = **和单个格子等时值** ✓
```

⇒ 「`330,210`」**不是**第二组的双押，而是**同一个 `[30, 150]` 的另一种写法**。
奇偶每 5 格翻一次，所以相邻单元交替使用正常 / 反向编码 —— 这正是用户 #11
「**为了不叠起来**」的落地方式，也说明 `dp_angle` 现有的
`MODE_REVERSE` / `MODE_NORMAL` 交替策略**方向是对的**。

**所以两处算术都成立**：双押 = 1 拍 = 单个格子；每 4 拍一个双押。

#### 2.2.2 ★★ 由此得到的统一公式（`a` 的实现基础）

把参考谱 A 也按奇偶还原后，塔 / 斜向 / 交互**是同一个公式**：

```
一个双押  = 两格 [θ, 180·W − θ]        θ = 薄角（15/30/60），W = 这个双押占几拍
```

| 写法 | 窗口 W | 写出来的两格 | 合计 | 与上下文的间隔 |
|---|---|---|---|---|
| **双押交错**（`双押交互`） | **1** | `[30, 150]` | 180° = 1 拍 | 后面跟 **3 个 `180`**（= 每 4 拍一个） |
| **斜向单元**（A 段 B） | **1** | `[30, 150]` ×2 | 360° = 2 拍 | 两对**背靠背** ⇒ 每 1 拍一个（连续双押） |
| **双押塔**（A 段 A / E） | **2** | `[30, 330]` | 360° = 2 拍 | 没有间隔，塔本身就是循环 |
| **强弱**（A 段 C / D） | **0.5** | `[30, 60]` | 90° = 0.5 拍 | 与下一个双押紧邻（5 连 = 9 对） |

> 用户原话「`30, 150, 330, 210`」= **raw 序列**，有效序列是 `[30,150][30,150]`
> = 「**非常好用的连续双押手段**」✓ 完全对得上。

⇒ **`a` 只需要一个参数 `W`（双押占几拍）+ `θ` + `连数 N`**，不需要给 4/5/8/10 各写模板
（用户 #4「举一反三」）。

> ⚠ 一处待用户确认：斜向单元用户说「**360cbpm 以上**」，但参考谱 A 里那一段是
> `×0.5`（有效 125bpm）。所以「360cbpm」大概率指的是**别的一层**（比如 4k base 的
> `cbpm = 4 × tbpm`，或原始歌速）。先按「有效 cbpm」实现并做成可调阈值，
> 不阻塞 `a`。

## 5. ★ 实施方案（压缩后照这个做）

### 5.1 第一步 · b（止血：双押不许静默丢）—— ✅ **已完成**

**目标**：`out/_dp_demo/dp{2,4,8}_angle` 上 `双押 > 0`；任何被丢弃的落点都要**报出来**。

**实际做法**（比原计划更省、且**零时间误差**）：把「图形拥有」拆成两层：

| 层 | 谁 | 拆不拆 | 为什么 |
|---|---|---|---|
| **硬保护** | 模板段 / 三连音引擎 / 魔法阵雪花 / 开局站位 / 尾层 | **永不拆** | travel 是别人算好的**结论** |
| **软保护** | 自然闭合段的填充格（`Floor.natural`） | **默认可拆** | 它只是「把剩下的时间铺满」的**配平量**：拆一格使 `Σtravel` 不变 ⇒ **总时长一分不差、闭合性不变、SetSpeed 位置不变** |

外加三条：

1. **带 `SetSpeed` 的格不拆** —— 参考谱 A 的注释「调速一定要放在平着的格子上面」；
   拆了它就从 `180` 变成 `θ`，SetSpeed 落在斜格上 ⇒ 不合规。
2. **自带 Twirl 的格照样能拆** —— 把 Twirl 搬到**薄格**上即可：奇偶照样翻一次、
   有效 travel 照样是 `[θ, T−θ]`、总时长不变 ⇒ 不必丢音，只是改用反向写法。
3. **`snap_ms`（默认 0）= 换位开关**：原格不能拆时，在 ±`window`(8) 格内找一个
   **音头差 ≤ `snap_ms`** 的可拆格顶上。默认 **0 ⇒ 绝不挪时间**，宁可少插也要报出来。

新增 `report` 账目（`core/dp_angle.plan`，**状态栏照抄**）：

moved / moved_ms_max   换过位的个数 / 最大挪动毫秒
owned                  被硬保护挡住（模板/引擎/雪花/站位/尾层）
setspeed               因「调速必须在平格上」让位
dropped                剩余 travel 不够 / 被显式排除
twirl_busy             原格自带 Twirl 而被改成反向写法的个数
dup                    同一格抢两次      out_of_range  落在站位/尾层外
soft_used              借用软保护（自然段）格的个数

### 5.2 第二步 · a（正解：把双押当约束）—— ✅ **已完成（v1）**

**核心公式**（§2.2.2）：**一个双押 = 两格 `[θ, 180·W − θ]`**，`W` = 这个双押占几拍。
塔 / 斜向 / 交互 / 强弱**全都是它**，只差 `W` 与「上下文里垫几个 `180`」。

**新增求解输入**（`SolveParams`）：

```python
#: 双押需求：[(onset 下标, 连数 N, 风格)]
#: 风格 `tower`=塔  `interactive`=交互/斜向  `strength`=强弱
dp_requests: list[tuple[int, int, str]] = field(default_factory=list)
dp_theta: float = 30.0      # 薄角 θ（段 D 出现过 60°）
dp_window: float = 1.0      # W：一个双押占几拍（塔 = 2，交互 = 1，强弱 = 0.5）
dp_spacing: float = 4.0     # 相邻两个双押之间隔几拍（交互 = 4，斜向 = 1）
```

**在 `solve()` 里预留槽位**（放在**图形扫描之前**，与模板段同级）：

```
每个双押占 2 格：   [θ, 180·W − θ]
间隔垫格：          travel = 180 的平格，数量 = round(dp_spacing − W)

塔   (W=2, spacing=2) : [30, 330]                    ← 无间隔，自循环
交互 (W=1, spacing=4) : [30, 150] + 180,180,180       ← 每 4 拍一个 ✓
斜向 (W=1, spacing=1) : [30, 150][30, 150]            ← 背靠背 = 连续双押 ✓
强弱 (W=.5,spacing=.5): [30, 60][30, 60] …

连数 N：上面这个单元重复 N 次 ⇒ **N 参数化，不写 4/5/8/10 的模板**（用户 #4）

速度硬约束：预留时就把 SetSpeed 位置**钉在 travel=180 的格子上**（§3.4 两条）
```

**与现有架构的关系**：

- 预留的格要像模板段一样进 `blocked` / `locked`，让 `figures.choose` 与 `_dp_tiers` **绕开**；
- **中旋双押 `dp_midspin` 完全不动**（#1）；
- Twirl 按「**为了不叠起来**」的原则自动放（#11）：相邻单元交替用正常 / 反向编码
  —— 参考谱 B 实测就是**每 5 格翻一次奇偶**（§2.2.1）。

逐格比 `travel`（塔则比 `out/双押 常见写法.adofai` 的 A/B 段）。

#### 5.2.1 ★ 实际落地（v1）—— 做到哪一步、没做到哪一步

**做法**（`core/solve.py`）：

```
SolveParams.dp_reserve = (onset 下标…)    # 空 ⇒ 一行都不执行，老路径逐字节不变
SolveParams.dp_theta   = 0               # 0 = 自动（choose_thin）

solve() 在「图形扫描」之前（2.54）：
    ① `_reserve_dp_slots()` 把被模板段 / Pause 格占住的挑掉 ⇒ 记 lost
    ② 预留的格进 `_blocked` ⇒ 自然段 / 引擎 / 模板**都不许占它**
    ③ 扫描到这里时**强制沿用上一格的生效档 `_cur_k`**
       ⇒ travel = 180·r / k_prev ⇒ **这一格自己不出 SetSpeed**（硬规则）
       ⇒ travel 顶出硬范围就放弃预留，退回常规路径并记 lost
    ④ 雪花覆盖（`_apply_snowflakes`）是**外部层**，会改段内 BPM ⇒
       收尾再做一次终检：长出 SetSpeed 的预留格**撤销标记**并计入 lost
    ⑤ `Floor.dp_reserved = True` ⇒ `dp_angle` 拆它并报 `reserved_used`
```

`sidecar`：双押落点（onset 下标）**提到 `solve()` 之前**算，再喂给 `dp_reserve`；
`dp_reserve`（默认开）/ `dp_theta` 两个新参数已接到 UI 上（② 主轨分区）。

#### 5.2.2 ⚠ 还没做的：把「SetSpeed 必须落在平格上」变成**全局约束**

> ★★★ **2026-10 用户更正：这一节的**前提本身就错了** —— 这条规矩**不是全局的**，
> 它**只针对双押**。完整说法（用户原话）：
>
> > 「对于『调速必须落在平格上』：**这个是针对于双押的，大多数时候不适用**。
> > 完整的说法：**（当双押使用变速）调速必须不和旋转重叠，必须位于双押的第一格**。」
>
> ⇒ **结论改写**：
> 1. 下面那张「47%~85% 落非平格」的表**不是缺口，不用修**（三连音的 `120° + SetSpeed×2`
>    本来就合法；`core/triplet_engine.py` 顶部写的就是这套写法）。
> 2. 正确版约束 = **调速不与 Twirl 同格**（＝ `core/rules.py` ①，唯一硬规则）
>    + **落在双押的第一格**。
> 3. ★ **捞回一笔账**：本文下面「丢点原因」里的「**SetSpeed 格 26**」——
>    那些点按**正确**规则**根本不用丢**：把调速落到双押第一格（薄格）、那一格不叠 Twirl
>    （退正常写法）就满足规则。`core/dp_angle.plan` 现在遇到 `_setspeed_here` 直接跳过，
>    是照**读错**的规矩写的。
> 4. 原文保留在下面（历史），但**不要再按它当全局约束施工**。
> 详见 `docs/49` §9.4。

实测（三首样本，`SetSpeed` 事件里落在**非平格**上的比例）：
