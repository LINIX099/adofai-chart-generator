# 55 · 打包与构建流程（便携版）· 一条命令到交付物

> 面向：**要重打一个便携包的人**（你 / 以后的协作者）。
> 全部命令都在**本仓库根**执行，除非注明 `cd app`。
> 实测环境：Windows 10 19045 · Python 3.14.3 · Node 24.19 · Electron 44.0.0 · electron-builder 26.15.3

---

## 0. 总览：一条链

```
① 拼运行时        python tools\make_runtime.py          → build\runtime\python\   (~354MB)
② 打壳            cd app && npm run pack:win            → build\portable\*.zip    (~283MB)
③ 验收（必做）    python tools\pack_verify.py --flow     → 全绿才算过
```

`npm run pack:win` 内部 = `pack:runtime`（= ①）+ `electron-builder --win --x64`。
只想快速看壳（不重打运行时）：`cd app && npm run pack:dir`。

---

## 1. 前置条件（缺一个都会在莫名其妙的地方失败）

| 需要 | 为什么 | 怎么确认 |
| --- | --- | --- |
| **Python 3.14.x（x64）** | ① 要它来解包 + `pip install` 到目标目录；版本**必须与包内运行时同 minor**（cp314 轮子才对得上） | `python -V` |
| **Node + npm** | ② 是 electron-builder | `node -v` / `npm -v` |
| **代理 `127.0.0.1:7897`**（verge-mihomo） | ★ **pip 直连索引会静默失败**；官方 python.org 下载会 timeout | `Test-NetConnection 127.0.0.1 -Port 7897` |
| 能访问 **npmmirror / registry.npmjs.org / codeload.github.com** | Electron 二进制、Python 树、release 资产 | 见 §5 的网络表 |

> ★ `tools/make_runtime.py` **会自己探代理**：探到才用，探不到就直连**并说出来**
> （探不到还硬设，会把本来能下的东西也挡掉 —— 真机踩过）。

## 2. ① 拼运行时 —— `tools/make_runtime.py`

```powershell
python tools\make_runtime.py            # 幂等：已就位就跳过，并顺手瘦身
python tools\make_runtime.py --force    # 从零重来（重新下载 Python 树 + 装依赖）
python tools\make_runtime.py --prune    # 只瘦身（可反复跑，删完照样自检）
python tools\make_runtime.py --proxy '' # 换网络环境时关掉代理
```

**它做什么**：下 `python-3.14.3-amd64.zip`（官方**完整树**，33.9MB）→ 解到 `build/runtime/python/`
→ 用**开发机** pip 以 `--target` 装 `numpy scipy librosa soundfile numba` → **瘦身** → **自检**。

**自检必须用包内那个解释器跑**（在开发机上 import 成功**不算数**）：期望
`numpy/scipy/librosa/soundfile/numba` 全 OK 且打印 `AUDIO_OK`。

### 尺寸账（改瘦身清单前先看这里）

| 项 | 大小 | 能不能删 |
| --- | --- | --- |
| `llvmlite.dll` | **114.8 MB** | ❌ **删不掉**：`librosa/filters.py` 模块级 `from numba import jit`，采音必经此处（实测挪走就崩） |
| `scipy` + `scipy.libs` | ~129 MB | ❌ librosa 依赖 |
| `numpy` + `numpy.libs` | ~51 MB | ❌ **必需**（`denoise/gridfit/synth` 都模块级 import） |
| `sklearn` 41 + `narwhals` 5 | 46 MB | ✅ **已删**（librosa 元数据声明了它，但代码只在 NMF 那条路用；`onset_detect`/`hpss` 实测不需要） |
| `Doc/` | 74 MB | ✅ 已删（官方完整树自带的 HTML 文档） |
| `tkinter`+`tcl`+`idlelib`+`ensurepip`+`pip`… | ~14 MB | ✅ 已删（我们没有 GUI，用户机器上不装包） |
| 合计 | **545 → 354 MB** | `__pycache__` **保留**（删了首启要重编译） |

## 3. ② 打壳 —— `app/package.json` 的 `build` 段

关键项（改之前先理解）：

| 配置 | 作用 |
| --- | --- |
| `directories.output = ../build/portable` | 产物落到 `build/`，不污染 `dist/`（那里放**源码外发包**） |
| `extraResources` | 把 `core/ sidecar/ patterns/ vendor/adofai_timemodel/ samples/ bridge_plugin/ runtime/python/ LICENSE LICENSES/ THIRD-PARTY.md VERSION` 放到 `resources/` |
| `extraFiles` | 把 `packaging/使用说明.txt` 放到 **exe 旁边**（拿到 zip 的人第一眼看到） |
| `win.target = zip` | 解压即用；**不做** NSIS/自动更新/签名 |
| `electronDownload.mirror = npmmirror` | ★ 受限网络下 `github.com:443` 不通，Electron 二进制只能从镜像下 |
| `signAndEditExecutable: false` | 不下 winCodeSign；我们不做签名（Windows 会弹 SmartScreen，说明书里写了） |

`app/main.js` 里与打包相关的**三处**（改动风险最高，别乱动）：

1. `ROOT = app.isPackaged ? process.resourcesPath : path.resolve(__dirname, '..')`
   —— 打包后 `__dirname` 在 asar 里，`..` 会指到 `resources/`，正好是 `extraResources` 的落点
2. `pythonExe()`：`ADOFAI_PYTHON` > `resources/runtime/python/python.exe` > 系统 `python`
3. `logFile()`：★ 打包后 `__dirname/.logs` 在 **asar 里（只读）** ⇒ 必须写 `app.getPath('userData')/logs`

## 4. ③ 验收 —— `tools/pack_verify.py`

```powershell
python tools\pack_verify.py           # 静态 + 冒烟（~1 分钟）
python tools\pack_verify.py --flow    # 再加完整链路（解压→载示例→出谱→导出）
python tools\pack_verify.py --keep    # 保留解压目录，人工复看
```

它逐条断言（**每条都对应一次真机踩过的坑**）：

1. 解出 `exe` / `使用说明.txt` / `THIRD-PARTY.md` / `LICENSE` / `LICENSES/*` / `bridge_plugin`
2. **不含** `beat_data_generator`（GPL-3.0 宿主不随包）
3. 包内解释器能 import numpy/scipy/librosa/numba（**用包内那个跑**）
4. 剥掉 PATH（`where python` 找不到东西）后 `--smoke` = **SMOKE PASS**
5. `--flow`：载内置示例 → 出谱 → 导出 `.adofai` + 音频，且 **`verify_ok`**
6. **没有宿主时**：`/api/host` 立刻返回（**不去跑 node**，0.1s）· `tool=false` · 桥那栏说人话 · 按钮禁用 · 状态如实「未连接」

## 5. 网络坑（**先看这个，省一天**）

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| **pip 直连索引静默失败** | `Could not find a version that satisfies ... (from versions: none)` —— 看着像**没有轮子**，其实连不上索引 | 走代理 `127.0.0.1:7897` |
| **github.com:443 不通** | `git fetch` / electron 二进制全挂 | git 用 **`ghproxy.net`** 当远端；electron 用 **`ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`** |
| **python.org 下载 timeout** | 33.9MB 的包 60s 只下几 MB | 走 **`registry.npmmirror.com/-/binary/python/`**（脚本里镜像优先、官方垫底） |
| **3.14.3 没有 embed 包** | `python-3.14.3-embed-amd64.zip` 404 | 用官方**完整树** `python-3.14.3-amd64.zip`（版本一致，cp314 轮子才对） |

## 6. 改东西时的自检清单（顺序别反）

```powershell
# 1) 语法（★ app.js 是 ES 模块，node --check 要 .mjs；e2e.js 要用 new Function 才抓得到重复 const）
Copy-Item app\renderer\app.js build\_chk.mjs; node --check build\_chk.mjs; rm build\_chk.mjs
node -e "new Function(require('fs').readFileSync('app/e2e.js','utf8'))"
node --check app\main.js

# 2) Python 全量
Get-ChildItem tests\test_*.py | % { python $_.FullName }      # 期望 32 套全过

# 3) UI 全量（219→248 条）
cd app; npx electron . --e2e --hidden

# 4) 打包 + 验收
npm run pack:win; cd ..; python tools\pack_verify.py --flow
```

**基线（当前 · `0.5.0-preview-bugfix`）**：Python **36 套**（`test_ui_smoke` 跳过；
`test_sidecar` **308**）· E2E **289/289** · `pack_verify --flow` **全绿** · zip **283.1 MB**
（`ADOFAI-ChartGenerator-0.5.0-preview-bugfix-win-x64.zip`）

**历史基线（v0.4.5）**：Python **32/32**（`test_sidecar` **282**）· E2E **248/248** ·
`pack_verify --flow` **全绿** · zip **283.1 MB**（`ADOFAI-ChartGenerator-0.4.5-win-x64.zip`）

> ★★ **版本号只有一个真源：仓库根的 `VERSION`。**
> `app/package.json` 的 `version`（electron-builder 用它命名 zip）与
> `packaging/使用说明.txt` 的抬头要跟着改；`sidecar/server.py` **不再写死**
> （`sidecar.server.version()` 直接读 `VERSION` —— 以前号写死三处，漏改一处就会
> 「界面显示旧号、包里是新的」，`pack_verify` 有一条断言专门守它，现在那条断言
> 也从 `VERSION` 读期望值了）。

> ★ 新增来源格式（如 `core/stem_json.py` 那份时间戳 JSON）**不用改打包配置**：
> `core/` 与 `samples/` 本来就是整目录进 `extraResources`，新模块/新示例自动进包。
> ★ e2e 里**别写「`setParam` 之后就 `waitRebuild()`」**：程序性写值**不触发重算**，
> 那会白等满 40s 超时（真踩过三次）；`await rebuild()` 之后再 `waitRebuild()` 同理。

## 7. 产物长什么样

```
build/
  runtime/python/                      ①的产物（可复现，别手动改）
  portable/
    ADOFAI-ChartGenerator-0.4.5-win-x64.zip      ← **交付物**
    win-unpacked/                                 ← 没压缩的同内容（调试用）
        ADOFAI 谱面生成器.exe
        使用说明.txt                              ← extraFiles：放 exe 旁边
        resources/
            app.asar                              ← 壳（main/preload/renderer）
            core/ sidecar/ patterns/ vendor/ samples/
            bridge_plugin/                        ← BDG 联动插件（可选）
            runtime/python/                       ← 自带 Python 3.14.3
            LICENSE  LICENSES/  THIRD-PARTY.md  VERSION
```

## 8. 明确不做（这一轮）

- ❌ NSIS 安装器 / 自动更新 / 代码签名（等镜头定稿 + UI 重做，`docs/49`）
- ❌ **不带 `vendor/beat_data_generator`**（GPL-3.0 + 233MB）；桥在无宿主时降级为「未连接」
- ❌ Essentia.js / 侧载 WASM（`docs/47` 决策 1：可选侧载，不进主包）

## 9. 许可与"谁的代码在哪"（改包之前必须看）

| 部分 | 许可 | 在包里的位置 | 义务 |
| --- | --- | --- | --- |
| 本程序 | **Apache-2.0**（用户 2026-10 定；更早是 MIT） | 全部自有代码 | 保留 `LICENSE` **全文** + `NOTICE`（§4(d)） |
| `adofai_timemodel` | MIT | `vendor/adofai_timemodel/`（自带 LICENSE） | 保留声明 |
| **`adofai` @3.3.2** | **BSD-3-Clause** | 并进了 `renderer/vendor/adofai-player.js`（bundle） | ★ **必须随附许可全文** → `LICENSES/adofai-BSD-3-Clause.txt` |
| **`three` @0.178.0** | MIT | 同上（bundle 内含） | ★ 同上 → `LICENSES/three-MIT.txt` |
| Python / Electron / numpy / scipy / librosa / numba… | 各自 | `runtime/` | 见 `THIRD-PARTY.md` |
| **BDG 宿主** | **GPL-3.0** | **不在包里** | 不 convey ⇒ 无额外义务 |

> ★ **`adofai-player.js` 是 9.5MB 的打包产物**：只写「见其仓库」是**不够**的
> （BSD-3/MIT 都要求二进制分发时复现全文）。`pack_verify` 会断言 `LICENSES/` 齐全。
> 另：`adofai` 上游仓库**没有 LICENSE 文件**（只在 npm 元数据声明 BSD-3），
> 我们按其声明附标准文本并把这件事记在文件头 —— 细节见 `packaging/LICENSES/adofai-BSD-3-Clause.txt`。
