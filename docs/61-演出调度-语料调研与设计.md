## 0. 一句话

把「**轨道本身怎么动**」做成一层可关的调度：**位置轨道 `PositionTrack`**（建关期静态错位）

由**谱面结构**触发、按**固定公式**取值，**只写 `actions`，不碰 `angleData` / `bpm` / `travel` / `Twirl`** ⇒ 时序零影响。

| 层 | 管什么 | 状态 |

### 1.2 两个核心事件的语义（**决定全部写法的两条**）

#### A. `PositionTrack` = **建关期累加器**（★ 最容易写错的一条）

`scnGame.cs:334-335` 在**整个谱面循环之前**声明：

```csharp
Vector2 vector  = Vector2.zero;   // 已提交的偏移（跨格保留）
Vector2 vector2 = Vector2.zero;   // 当前累加值
```

`scnGame.cs:507-558`（`case LevelEventType.PositionTrack`）：

```csharp
vector2 += item5.Get<Vector2>("positionOffset") * tileSize;   // ← 加上去，不是赋值
if (!output6)          // output6 = 本事件的 justThisTile
    vector = vector2;  // ← 提交给后面**所有**格
```

`scnGame.cs:637-639`（每格收尾）：

```csharp
floor4.transform.position = floor4.startPos + vector2 + zero;
floor4.offsetPos = vector2 + zero;
vector2 = vector;     // ← 下一格从"已提交值"开始
```

⇒ **`positionOffset` 是「笔的位移」，一写就永久影响后面所有格**；
只有 `justThisTile: true` 才是「只改这一格，下一格恢复」。

**这也解释了语料的两个高频值**：
`justThisTile: False × 16762`（累加式，用来「整段平移」）vs `True × 239`（单格）。

#### B. `MoveTrack` = **运行期绝对补间**（不累加）

`ffxMoveFloorPlus.cs:98`：

```csharp
Vector3 vector = target.startPos + targetPosV3;   // ← 绝对：从原始位置起算
```

- 目标 = **该格自己的 `startPos` + `positionOffset`**，重复触发不会叠加；
- 触发时机 = **玩家走到事件所在格**（`ffxPlusBase.SetStartTime`：`entryTime + angleOffset/180 × 一拍`）；
- 作用范围 = `startTile..endTile`，步长 `i += 1 + gapLength`（`ffxMoveFloorPlus.cs:41,77`）；
- 想要「先甩出去再拉回来」必须**发两条**（上一条把目标设成远处，下一条设回 0）。

### 1.3 ★★ `disabled` 的真相：**字段缺失 = 不生效**

`LevelEvent.Decode`（`LevelEvent.cs:314-320`）：

```csharp
bool flag5 = !dict.ContainsKey(key);   // 文件里没有这个键 ⇒ disabled = true
disabled.Add(key, flag5);
if (flag5) { data.Add(key, value5.value_default); continue; }
```

⇒ **`disabled` 不是从文件读的，是「这个键在不在」推出来的**。
所以：**只写你要生效的字段；不写的字段自然不生效**，不需要（也不该）写 `"Disabled"` 去"关"它。

★ 例外：**Bool 类型**的字段确实接受字符串（`LevelEvent.cs:333-340`）：

```csharp
else if (value5.type == PropertyType.Bool)
    if (obj is string text2) obj = text2 == "Enabled";
```

⇒ 语料里 `editorOnly: "Disabled"` / `justThisTile: "Disabled"` 是**布尔字段的字符串写法**，
等价于 `false`；`"Enabled"` 等价于 `true`。**两者游戏都认**，写 `true/false` 也可以。

### 1.4 时间口径（与 ⑤b/⑤c 同一套，已对账）

- `duration` = **拍**（`RDUtils × crotchet`，`ffxMoveFloorPlus.cs:193`）；
- `angleOffset` = **度**，`180 = 1 拍`（`ffxPlusBase.cs:119`：`degreeOffset/180 × 60/(bpm×speed)`）；
- `ease` = DOTween 的 `Ease` 枚举字符串。语料实测最常用：
  `Linear` / `InCubic` / `InQuad` / `OutSine` / `InCirc` / `OutBack` / `InBack` / `OutCirc` /
  `OutCubic` / `OutQuad` / `InSine` / `InElastic` / `OutQuart` / `OutElastic` / `OutExpo` / `InExpo`
  （另有 `InOutCubic` / `OutQuint` / `OutBounce` 等共 33 种）；
- `startTile / endTile` = `[相对偏移, "ThisTile"]`（语料 99.9% 是 `ThisTile`；`"Start"` 只出现 3 次）。

### 1.5 「只改渲染」的证据

| 事件 | 改了对象 | 有没有碰判定 |
|---|---|---|
| `PositionTrack` | `floor.transform.position` + `floor.offsetPos` | ✗ 无（`angleData` / `entryTime` 不动） |
| `MoveTrack` | `transform.position / rotation / localScale` + `opacity` | ✗ 无（同上；判定是**时间**判定，不是位置判定） |

⇒ **只要不碰 `scale` 之外的判定类事件，演出对时序零影响** —— 这一点跟 ⑤b/⑤c 同级，
可以照搬「默认开、可关、关掉逐字节相同」的契约。

⚠ **唯一待确认**：方块被 `MoveTrack` 推走后，**行星跟着走**（行星的位置由格子的 transform 算），
所以「轨道飞出去」= 行星也飞出去 —— 这是**演出想要的效果**，但**过火会让谱面读不出来**（§4.8 有上限）。

## 3. ★★ 开工前必须先处理的一件事：**我们现在的 `PositionTrack` 是累加的**

### 3.1 现象

`core/writer.py:173-181` 现在写的是：

```python
out.append({
    "floor": i, "eventType": "PositionTrack",
    "positionOffset": [_num(dx), _num(dy)],
    "rotation": 0, "scale": 100, "opacity": 100,
    "editorOnly": "Disabled",
})
```

**没有 `justThisTile`** ⇒ 按 §1.2A，`output6 = false` ⇒ `vector = vector2` ⇒ **偏移被提交，后面所有格一起被推开**。

### 3.2 影响推演（三份真实场景）

| 场景 | 现在的实际效果 | 期望效果 |
|---|---|---|
| 叠在一起的圈：第 2 圈偏 0.22、第 3 圈偏 0.44 | 第 2 圈偏 **0.22**、第 3 圈偏 **0.66**（上一圈的偏移被继承），之后**整条轨道永久平移 0.66** | 2/3 圈各偏 0.22 / 0.44，其余格不动 |
| 多个图形依次错开 | 偏移**逐图形累加**，曲尾可能偏出几十格 | 每个图形相对自身位置错开 |
| 与 `MoveTrack` 同格（语料共现 4201 处） | 两个偏移叠加，观感不可预期 | 需要明确的合成规则 |

因为「整段一起偏」是**刚性平移**（相机跟着玩家走），玩家**不容易看出来** ——
但它就是错的，而且**在有了演出调度之后会跟 `MoveTrack` 直接打架**。

### 3.3 修法（**动手前先真机验证**）

- **源码层面**：`scnGame.cs:379` 在**每个事件**开头都读一次 `justThisTile`
  （`item5.TryGet<bool>("justThisTile", out var output6)`），`PositionTrack` 分支确实用它
  ⇒ 写 `"justThisTile": true` 在 v19 是**合法且被读取**的。
- **旧注释的警告**：`core/writer.py:171-172` 写着「不要自己加 `relativeTo / justThisTile` ——
  这个版本不认，加了同样会炸」。⚠ **这条是更早版本（`PositionTrack` NRE 那次）的经验，跟现在的源码矛盾。**

## 7. 已知坑（别再踩）

1. **`PositionTrack` 是累加器**，不写 `justThisTile` 会永久推走后面所有格（§3）——**本轮最大发现**；
2. **`disabled` 不是文件里的字段**，是「键在不在」推出来的：**只写要生效的字段**（§1.3）；
3. **`MoveTrack.positionOffset` 是绝对目标**（相对 `startPos`），不是增量；「甩出去再拉回」要发两条；
4. **`angleOffset` 单位是度（180 = 1 拍）**，不是格、不是毫秒；
5. **`startTile/endTile` 用 `[偏移, "ThisTile"]`**，步长 `gapLength`（语料 99% 是 0）；

### 8.2 三条新查实的机制（决定怎么写）

1. **我们生成谱的"预设"是什么**（`core/writer.py:217-218`，实测落盘值）：
   `trackAnimation="Fade"` · `beatsAhead=8` · `trackDisappearAnimation="Fade"` · `beatsBehind=4`
   ⇒ 方块**淡入**（提前 8 拍）、走过 4 拍后**淡出**。
   ★ 要做自己的入场效果，**必须决定是"叠在淡入上"还是把淡入关掉**（验证谱段2 vs 段3 就是这一问）。
2. **`AnimateTrack` 可以改这两个提前量**（字段：`trackAnimation / beatsAhead / trackDisappearAnimation / beatsBehind`），
   而且它是**累积状态**（从那一格起对后面所有格生效）⇒ 每段想用不同提前量就得**逐段钉一次**。
3. **入场动作必须写成一对**（`MoveTrack` 的目标是绝对坐标，不是增量）：
   ```
   floor P      MoveTrack{ startTile:[+lead], endTile:[+lead+k], positionOffset:[远处], duration:0 }
   floor P+1    MoveTrack{ 同一段, positionOffset:[0,0], duration:D, ease:... }
   ```
   `duration: 0` = 瞬间摆位；下一格才滑回。**两条不能放同一格**（同格第二条会 kill 掉第一条的补间）。

| **入场粒度** | 两条、隔一格 | **同一格**上给未来第 1..N 格**各发两条**，靠 `angleOffset` 逐格错峰 |
| **缓动** | Out 系偏多 | 离场一律 **In 系**（`InElastic/InCubic/InCirc/InBack`）= 加速被拽走；入场用 **Out 系** = 减速到位 |
| **初态** | `(0,-8)` 纯位移 | **位移 + 缩放 + 透明度三连**；且常用 `null` 表示「这个轴不动」（`[null,1]`） |
| **时长** | 2~3 拍 | **8 / 16 / 32 拍**（整 8 的倍数） |
| **节奏** | 没有 | `angleOffset` 逐格递增（−1350 / −1305 / −1215 …）= **拍值错峰**，这是灵魂 |

### 10.2 ★ 为什么"入场提前量"不能单独调（本轮最重要的机制）

入场补间是「**先摆到远处，再滑回来**」。这两件事的时刻分别是：

- **初态**（摆到远处）：`floor = f` 的 `angleOffset = -1440` ⇒ 提前 **8 拍**
- **回位**（滑回来）：同一条 `floor = f` 的 `angleOffset = ret`，时长 `dur`

设目标格到达时刻为 `T`、`lead = 2` 格（直线 ⇒ 2 拍）：

```
飞行窗口 = [T − lead + ret/180 , T − lead + ret/180 + dur]
余量 m   = T − 飞完 = lead − ret/180 − dur          ← 用户原样 ret=0 ⇒ m = 0
```

**`m = 0` 就是"飞完的那一刻正好踩上去"** —— 实测观感灾难的主因
（方块在你脚下还在飞、还只有 95% 大小、95% 不透明）。

⚠ **但提前量不能单独加**：飞行窗口如果整段早于方块的**出现时刻**（`beatsAhead` 拍），
那套动画会**全部播在方块存在之前** ⇒ 结果是方块**直接凭空出现在终点**，效果反而没了。

```
要看得见 ⇒ beatsAhead ≥ lead + m + 余韵        ← v4 统一取 8 拍（m 最大 4 支持得住）
```

## 12. ★★ 反向 QE：把「逐格离场」时间反演成「逐格入场」（2026-09-18）

> 用户：「234 没问题，但是**这些全部都不对**（= §11 的「一片」4 个 batch 变体）。

### 12.1 结论：可以，反演规则 5 条（缺一不可）

QE 离场原文（`7. QuomodocunquizE` floor 273 起，同一条配方 **×657**）：

```json
{"floor":273,"startTile":[-1,"ThisTile"],"endTile":[-1,"ThisTile"],"gapLength":0,
 "duration":8,"positionOffset":[0,-6],"scale":[0,0],"angleOffset":0,"ease":"InElastic"}
```

| # | 规则 | 离场 | → 入场 |
|---|---|---|---|
| 1 | **目标格方向取反** | `-1`（身后） | `+lead`（**前方**） |
| 2 | **缓动取反** | `InElastic`（慢起快终） | **`OutElastic`**（快起慢终） |
| 3 | **终点变起点** | 终点 `(0,−6)` + `scale[0,0]` | 同一组当**初态** |
| 4 | **终点改常态** | 目标 = 死态 | 目标 = `(0,0)` + `[100,100]` + `opacity 100` |
| 5 | ★ **需要初始化** | 一条事件就够（现态 → 死态） | **不够**：`MoveTrack` 只能指定**终点**，起点必须先摆好 |

★ 第 5 条的**最优解法**（本谱采用）：**一条「总藏」把整段瞬间摆成死态，然后逐格拉回**
—— 与离场**同构**（一条总状态 + 每格一条动作），事件数从 `2N` 降到 `N+1`。

### 12.2 两档时长（★ 忠实镜像不能照抄拍数）

QE 是 **bpm 320**，`8 拍 = 1.5 秒`，而 1.5 秒里玩家正好走过 **8 格**。
我们 bpm 120 要 `8 拍`才是同样的 8 格行程 ⇒ **拍数必须按"跨几格"折算，不能照抄**。

| 档 | dur | lead | 说明 |
|---|---|---|---|
| 忠实镜像 | **8 拍** | 10 格 | 同样的**格数行程**（飞行 = 8 格的行走时间） |
| 同秒压缩 | **3 拍** | 4 格 | 同样的**墙面时间**（1.5 s） |

## 13. 反向 QE × 一条事件罩好几个方块（2026-09-18，v7）

> 用户：「效果都**很适合高速入场**，试试 QE 的走法，但是**一次性给好几个方块用**？」

### 13.1 做法

底层只有**两类事件**（与离场同构），唯一变量是**一条事件罩几个方块**：

```
① 总藏（一条罩整段）：duration 0 · pos(0,-6) · scale[0,0] · opacity 0 · angleOffset -1440
② 拉回（一条罩 g 格）：duration 3 拍 · ease OutElastic · pos(0,0) · scale[100,100] · opacity 100
```

★ **偏移量恒为 `lead`**：第 k 组写在 `s + k − lead` 格上，目标格 `s + k` 相对它正好是 `+lead`。
`gapLength` 决定这条罩住的段里「隔几格中一个」。

### 13.2 v7 五档（139 格 · 70 s · 6 段）

| 段 | 一条罩几格 | 拉回事件数 |
|---|---|---|
| 1 | 1（逐格，基线） | 8 |
| 2 | **2** | 4 |
| 3 | **4** | 2 |
| 4 | **8（整段）** | **1** |
| 5 | `gapLength 1`（隔一格，奇偶两拍错开） | 2 |

### 13.3 ★★ 本轮抓到的真缺陷（**自检没抓到，事件表抓到的**）

我最初把偏移写成 `lead + k` —— floor 每前进一格，偏移量**也多加了 1**：

```
错的：floor s+k-lead → 作用 [s+2k, ...]       ⇒ 段1 只命中 12,14,16,18…（漏一半）
对的：floor s+k-lead → 作用 [s+k,  s+k+g-1]   ⇒ 段1 命中 12,13,14…19
```

**漏掉的那一半方块会永远躺在死态里（完全看不见）**，而当时所有旧断言（越界 / 跨过脚下 / 字段集）**全部通过**。

⇒ 新增 **完整性断言**（`verify`）：对每个用反向 QE 的段，
**每一格正文必须被「拉回」事件命中，且只命中一次**；漏一个或多一个直接退出码 1。
现在跑出来是 `5 段正文共 40 格全部被命中且不重复`。

> 教训记进 §14 的坑列表：**"范围类事件"必须验覆盖完整性，不能只验不越界。**
