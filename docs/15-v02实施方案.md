## 0. 现状与这两件事的地基（先对齐再动手）

一切符号以 `core/solve.py::_apply()` 为准（唯一真源）：

```
turn = (180 − travel) 若 ccw 否则 (travel + 180)     # 归一化到 (−180, 180]
heading += turn                                      # 每格走出去的朝向
angle  = (90 − heading) mod 360                      # 写进 angleData
x,y  += 2R × unit(heading)                           # 格子坐标（R = planar_radius）
```

- **朝向 heading** 和**坐标 (x, y)**：`_apply()` 已对每格算好并写回 `f.heading` / `f.x` / `f.y`。
- **斜线的来源**：heading 若长期不回正，长串非零转向的 travel 会让路径越走越偏 →
  一条「斜着」的轨道。**回正 = 让 heading 尽量回到 0°/90° 等正交主轴**，路径才顺。

### 项1（角度回正）与项2（方向调度）是同一个底座

项2 要的「每块绝对全局位置、相对位置、朝向」`_apply()` 其实**已经在算**，
只是没有暴露成可查询/可复用的接口，也没有用于「回正决策」和「轨道偏移」。

→ **第一步：把几何轨迹抽成独立的 `Path` 对象**，供回正、偏移、模板时间戳、双押共用。

## 1. 项1 · 角度回正（默认开启）

### 目标
斜着的轨道不要**大规模**出现；一段斜轨太长之后，考虑这一段**是否需要回正**。

### 判据（先定一个可量化口径，后续调）
- 用**当前 heading 相对最近的正交主轴（0/90/180/270）的角度差** `θ = |heading mod 90|`。
- 一个「斜段」= 连续 `θ > 阈值`（默认 `θ>20°`）超过 `N_min` 格（默认 8 格）的游程。
- 出现斜段 → 在**段尾把它拧回**最近的正交方向（`heading` 补到 0/90/180/270）。

### 拧回的方式（几何上合法，不动时间）
- **不能破坏 `Σtravel ≡ 180n (mod 360)` 的闭合不变量**（README 红线）。
- 回正用**一对正负转角**在段内消化，不让累计 heading 偏移堆到段外：
  - 方案 A：把斜段**末端几格**的 travel 在「直线 180° 的 ±Δ」上重排，
    使最后一个 turn 把 heading 拉回主轴。代价：段尾 travel 微调，仍在 [15°,345°]。
  - 方案 B（首选，零时间代价）：回正只动 **Twirl 翻转位**（改 ccw 符号）
    或**成对 ±15°/30° travel** —— 反正 trav等式成对出现，heading 净回正而 `Σtravel` 不变。
- 结果：「斜轨」改成「一长段直线 + 集中的几次转向」，观感接近人类谱的「一条直线为主」。

### 默认开启 + 旋钮
| 旋钮 | 默认 | 含义 |
|---|---|---|
| `straighten` | True（默认开） | 总开关 |
| `straighten_theta` | 20° | heading 偏主轴多少度算「斜」 |
| `straighten_run` | 8 格 | 斜段至少多长才处理 |
| `straighten_max_twists` | 尽量少 | 回正时最多加几处转向 |

### ⚠ 与既有规则的冲突点（压缩后第一件事先验证）
- `_finish` 里**自然闭合段已经不许 Twirl**（靠 Σtravel 自己闭合）——回正不能给自然段硬塞 Twirl。
- 雪花段是闭合图案，**不能回正**（花瓣形状由算法定死）。回正只作用于画中间的 DP 段落。

## 2. 项2 · 方向调度（绝对/相对位置、朝向、轨道偏移）

### 目标
计算每个方块的**绝对全局位置、相对位置、朝向**，用来：
1. 计算**轨道的位置偏移**（PositionTrack 的 `positionOffset`，见 `core/track_fx.py`）
2. **活用于回正**（项1 的决策输入）
3. 将来叠加在角度双押 / 时间戳模板上。

### 落地
抽 `core/path.py`：

```
class Path:
    headings: list[float]      # 每格走出去的 heading
    positions: list[(x, y)]    # 每格绝对坐标（长 = n+1）
    def heading_of(i)          # 第 i 格朝向 → 是否正交 / 偏多少
    def offset_of(i)           # 相对前一格的相对位移 (+Δx,+Δy)
    def recent_centroid(i,k)   # 最近 k 格的局部质心（回正决策 + steer 已用类似量）
    def straighten(spans, params)   # 见项1，返回新的 travel/heading 序列
```

- `Path` 由 `_apply()` 的几何逻辑喂，`_apply()` 改为**消费 Path 输出**（重构为单向数据流，避免两处算坐标）。
- **轨道位置偏移**：复用它给「间距过密 / 过于重叠」的段落逐个 `PositionTrack.positionOffset`
  错开（沿用 `core/track_fx.py` 已验证的字段写法，不动时序）。
- 顺带解决项1：回正就是「改 Path 的 heading 序列 + 重算位置」。

## 3. 项3 · 双押（角度）+ 雪花按开源优化

### 3.1 角度双押（把 BUGJI 的 `180−a / carry` 思路融进本项目）

BUGJI `bdg_plugin_adofai::renderer.js` 的双押写法（已抓源码）：

```
多押：同一 beat 有多 marker 时，插一块
       插入块 angle += (180 − 双押角度)
       下一块用 carry = 双押角度 补回（叠加在正常角度上）
双押角度可选 15° / 22.5° / 30°
```

**优势**：只改 `angleData`，不需要中旋 999，观感贴近人类写的 ±15°/30° 双押。
**它的已知缺陷**（README 已知问题 #8、#9）：`carry` 只作用在紧邻下一块，
并不完全等价「同一瞬间按下」，长谱会累积延迟偏差 → 需要一个**成对闭合**的写法。

**融合方案（本项目正确方向）**：
- 采用 `docs/双押逻辑.md` §7.2 的几何：转角 ±15°(<300cbpm) / ±30°(≥300cbpm)，
  `travel = 180±θ`。
- **必须成对**（§7.3）：插入一个 +15° 双押，段内必须配一个反向 −15°，`Σtravel` 才回正。
  转折点即「一个双押 = 15° 折返格」，用**两格**体现（`travel` 分给两格、总和等于原来那一格拍的 travel）。
- 参照 star_calculator 的 **`[pAngle, beatAngle − pAngle]` 成对插入** 模式（见下面雪花节）：
  双押缺口 `[θ, 基准−θ]` 的和精确 = 基准格原本的 travel → **零净偏移、天然闭合**。
  这样既拿到「同瞬间按下」的手感，又避免 BUGJI 的延迟偏差。
- 判据沿用已定口径：cbpm ≥ 300 → 30°，否则 15°（`docs/双押逻辑.md` 已定）。

**落点**：新增 `core/dp_angle.py`（仿 `core/dp_midspin.py`）：
`plan(ch, targets_ms, cbpm)` 用第二条轨音头 → 成对插 `[θ格, 基准−θ格]`；`apply()` 就地插入并回填 `meta["dp_pairs"]`（rules.py 已认这个键）。

### 3.2 雪花按开源项目的优化

你提供的 `bugcode.cc/adofai/adofai-tools/` 里，**雪花/星星 + 伪双押**真正在 `star_calculator.js`（非 level_converter/difficulty_info 那些难度换算器）。核心算法：

```
beatAngle = 180 + (180 − 180/(pCount/2)) / pInterval      # 每拍基准 travel（>180 即外圈）
reverse → beatAngle = 360 − beatAngle                       # 外角/内角切换（镜像）
finalAngles: 每 pInterval 步，在步末插 [pAngle, beatAngle − pAngle]   # ★ 成对双押缺口
adofaiAngles[i] = 180(i+1) − Σ finalAngles[0..i]            # travel → angleData
```

**可借鉴点（对照本项目 `core/snowflake.py`）**：

| star_calculator | 本项目现状 | 吸收或决策 |
|---|---|---|
| 用「`pCount` 瓣 × `pInterval` 步」参数化整朵星/雪花形状 | `snowflake.py` 用 N 重对称 × arms 分摊 | 可加「按对称阶数与步数参数直接生成，不必靠随机采样"撞运气"」 |
| **双押缺口 `[pAngle, beatAngle−pAngle]` 成对、和 = 基准** | `双押逻辑.md` §7.3：双押成对回正 | **直接采纳**：这就是角度双押的模板 |
| `reverse` 镜像 = 外角/内角切换 | `ALLOW_MIRROR=False`，用户已定死「只走内圈」 | **维持 `False`**，reverse 只当外圈参考，不列入默认 |
| **travel 序列 → angleData 的公式 `180(i+1)−Σ`** | `_apply` 从 `angle=head(90−heading)` 推 | 只读参考，不照搬（两套单位口径不同） |

**雪花的优化方向**：把 `snowflake.py` 的**形状生成确定性化 + 语义化**：
不再只靠 `random + richness 打分撞运气，改成按（对称 N, 每瓣步数 arms）直接构造一整朵
（闭环、内圈、尽可能花/美），并保留「10 格内不用、之后权重递增」的 `should_use` 用户口径。
方向调度底座（项2 的 Path）同时给出**逐格绝对位置**，雪花参数选择时可直接校验包围盒与重叠，避免靠运气试错。

## 4. 项4 · 模板使用率：MIDI 先转时间戳、按时间戳对上图形的

现状（`core/templates.py::match`）：
- 现在**先音值序列匹配**（`notes` 身份：四分音符拍的整数倍），再对**原始 Δt** 做时序闸。
  命中率低的原因（`docs/12-模板接入.md`）：量化没洗干净、时序闸太死（`template_timing_tol_ms`）。

用户的方向（v2 项4）：
> 先把 MIDI 转成**时间戳**，然后**找时间戳能对上哪个图形的时间戳，然后使用。

**方案**：
- 给每个模板加一个**时间戳签名** = 每步的**拍值**（`notes`×拍长·基准 BPM），本质已是 `travel` 的确定函数。
  对齐方式从「相邻 Δt 容差」升级为**绝对对齐**：
  - 先在**参考网格**（base_bpm 的一拍）上把谱的 onset 时间戳铺开。
  - 枚举每个模板的「片段时间戳窗口」（该模板需要多少拍、落在哪几个 onset 下标）。
  - 与谱上连续 onset 的时间戳窗口做 DP 最优对位（错开每个窗口的允许偏移 = 模板 `timing_tol`）。
- 这与张段落切分（`template_rest_ms`）结合：每个**短段落**里，把所有模板窗口
  按时间戳窗口数排列组合地对位，取覆盖 onset 覆盖数最多的组合（整数线性覆盖，保留 DP 兜底）。
- 仍守两条红线：模板段 `k=1`（不引入额外 SetSpeed）、不进 Pause / 长三连音屏障。

**判定指标**：`tools/compare_templates.py` 的覆盖率（v0.1 默认预设 56 格/850）应显著上升。

### A3. ★ 必须记住的不变量与坑

1. **几何只有一个真源** = `core/path.py`。改几何前先看 `Path`：
   `turn = ±(180 − travel)`；`a_i = a_{i−1} − turn`。
2. **`travel`（有效值）与「写入 angleData 的值」是两回事，但不需要额外字段**：
   反向写法只要把 Twirl 放在该格，`turn = 180 − travel` 会自动写出补角。
   （曾在 `Floor` 上加 `raw_travel`，结果把补角**重复应用**一次，parser 差 11s。）
3. **Twirl 是自由的第二维**（翻转 `Δa` 符号）。所以「只多一次按下 + 零时长偏移 +
   零几何变化」**并非不可能**；条件是 `2T ≡ 180 (mod 360)` ⟺ 被拆格 `T = 90°/270°`。
4. **插入双押层后「层 ↔ onset」不再 1:1** ⇒ **不能**再用 `verify.verify_file`
   （它假设 floor j ↔ onset j−1）。要用 `dp_old2new` 重映射，或做逐层双射。
5. **拆格护栏**：不拆模板/自然/引擎/雪花格、开局站位、尾层，也**不拆本来就带 Twirl 的格**；
   薄格撞 SetSpeed 时退回正常写法。
6. 雪花 `uniform` == `star_calculator.js` 的内圈 `beatAngle`，对标 **`pInterval = arms − 1`**。
7. `use_snowflake` 默认关；开启有**既存**的 `twirl_on_setspeed` + 324ms 时序差，
   根因在 `_apply_snowflakes`，与形状生成无关。

   > ★ **2026-10 已修**（`docs/24` §4）：根因是「拨正/拨回 Twirl」被拨到雪花**新长出来的
   > SetSpeed 格**上，而 `writer.build_actions` 又在写盘时偷偷挪一次（那时 angleData 已定）。
   > 改成两遍式（先预演未来的 SetSpeed 集合）+ `_relocate_twirls()` 排在雪花之后、`_apply` 之前；
   > `writer` 不再擅自挪 Twirl。Automaton 反解 **FAIL 324348us → OK 23.6us**，违规 0。
   > 雪花参数也从 4 个补到 10 个（形状/步数/紧凑/等间隔容差/随机/种子）。
8. **OGG 采样域的不变量**（`docs/17` §6，本轮新增）：
   - 网格**不能**用 `estimate_bpm` 的估计周期直接建 —— 它有 ~0.15% 相对误差，
     会让网格以 `ε·t` 漂移（63.75s 漂 96ms）。必须走 `core/gridfit.fit_grid`
     精修周期 + 相位。
   - **多轨必须共用同一个 `(period, φ)`**，否则各轨相位不同会互相错位
     （所以 `load_as_midi` 是「先全轨检测 → 全局拟合一次 → 再各轨吸附」两遍式）。
   - **吸附安全阀**：`R < 0.30` 或 `R·√n < 2.5` ⇒ 整条轨**不吸**（宁可不吸）。
   - 检波偏置是**常量**（≈ +40ms，只取决于 `n_fft/hop/sr`，与素材无关）；
     标定用**全部轨**（打击轨的 RMS 峰最干净）、只信最强 30% 起音。
   - `tempo_map` 写**精修后**的 bpm；任意网格相位**不影响 Δtick**
     （`tick = k·PPQN/grid + round(φ·PPQN/(p·grid))`），所以相位可以自由解。
9. **倍频（F2）不是偏移的原因**（旧判断已纠正）：周期修好后，240 的 1/6 网格
   与 120 的 1/12 网格是同一条格子，绝对时间都对。倍频只影响 `base_bpm`
   （谱面结构），要做必须连同**网格分辨率自适应**一起做。
10. **UI 重写的不变量**（`docs/19`，本轮新增）：
    - 业务逻辑**只在 Python**（`sidecar/session.py`）；前端只画 + 收参数。
    - 参数面板由 `sidecar/schema.py` 生成，**默认值从 core dataclass 取**，
      所以 UI 默认值与求解器默认值不会漂移；新增参数只需在 schema 加一行。
    - 前端写回 sidecar 回填的值（offset / base_bpm）**必须走 `setControl`**
      （打 `applying` 标记），否则「offset 变→重建→改写 offset」死循环。
    - `api.req` 里 HTTP 码叫 `httpStatus` —— sidecar 的 `status` 是**状态文案**。
    - 插了双押层的谱**不能**再用 `verify_file` 逐层对照（会假失败），
      要用 `verify.verify_press_subset`；`check_offset` 同理要用 `hit_times`。
11. **区间采音（`docs/20`）的三个口径**：
    - 区间 = **时间窗 + 音轨集合**，只在「采音」这一步覆盖（步骤 4b），
      求解/模板/雪花/双押**全部无感** —— 别去动下游。
    - 区间内是「**整段丢掉**全局 onset 再放进区间自己的」，重叠时**后写的赢**；
      边界按 `merge_ms` 去重（留最早）。
    - 全曲预览条是**音频毫秒轴**，谱面视图是 **entryTime 轴**，两者不要混。
