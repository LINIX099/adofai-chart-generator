# 26 · 轨道位置偏移改为可选开关（v0.3 第五项）

> **状态：已实现并验收。** 用户 2026-10 原话：
> 「**给轨道设置的随机位置偏移 改为可选是否开启**」。

***

## 1. 问题：core 里早就有开关，但 UI 上根本够不着

`core/track_fx.py`（重叠闭合图形的 `PositionTrack` 单格错开）**v0.1 就写好了**，
`SolveParams.use_position_track` 也一直存在且**默认 `True`**：

```python
# core/solve.py
use_position_track: bool = True
pos_track_step: float = 0.22
pos_track_min_beats: float = 8.0
```

但全仓 grep `use_position_track`，**只在 `core/solve.py` 命中**（`dist/` 里的旧快照不算）：

```
core/solve.py:187   use_position_track: bool = True
core/solve.py:1515  if getattr(p, "use_position_track", True):
```

`sidecar/schema.py` 里**一个字段都没有**，`sidecar/session.py::params_solve()`
也从来没把这三个值传给 `SolveParams` —— 于是它永远吃 dataclass 的默认值，
**用户在界面上关不掉**。

> 这和 `docs/24` §4.2「雪花允许使用参数的部位极少」是同一类病：
> **能力已经实现，但没接到参数面上**。修法也一样：补参数面，而不是重写逻辑。

***

## 2. 改了什么

### 2.1 `core/solve.py` —— 关掉时落一个确定的 0

```python
if getattr(p, "use_position_track", True):
    from . import track_fx as _tfx
    _tfx.apply(ch, step=..., min_beats=...)
else:
    # ★ 关掉时也要落确定的 0：否则 meta 里干脆没有这个键，
    #   状态栏 / payload / 单测只能看到"缺席"，分不清「关掉了」还是「没算」
    ch.meta["pos_tracks"] = []
    ch.meta["pos_track_n"] = 0
```

**没动 `track_fx` 的任何几何逻辑**（方向调度 / 分组 / 步长全部原样）。

### 2.2 `sidecar/schema.py` —— 补 3 个字段（`④ 求解` 组）

| 字段                    | 类型    | 默认     | 说明                     |
| --------------------- | ----- | ------ | ---------------------- |
| `use_position_track`  | check | `True` | ★ 用户要的那个「是否开启」        |
| `pos_track_step`      | float | `0.22` | 每多一圈向外错开多少格（0.02\~1.0 格） |
| `pos_track_min_beats` | float | `8.0`  | 隔得比这更远的重合才错开（0\~64 拍）  |

标签用「**轨道位置偏移（叠在一起的圈错开）**」—— 用户口中的「随机位置偏移」，
在 UI 上要说清它到底在干什么，否则勾掉之后看不出来差别在哪。
`help` 里明确写了**「只改渲染、不改几何与时序」**。

### 2.3 `sidecar/session.py` —— 接线 + 可观测

```python
# params_solve()
use_position_track=bool(st.get("use_position_track", True)),
pos_track_step=float(st.get("pos_track_step", 0.22)),
pos_track_min_beats=float(st.get("pos_track_min_beats", 8.0)),
```

- `payload()` 新增 `pos_track_n`（关掉时 = 0），前端与 e2e 才有东西可断言；
- 状态栏：有错开时追加「；轨道错开 N 格」，**被显式关掉时**追加
  「；轨道位置偏移已关闭」（没有重合、也没关掉时不加，免得变噪音）。

***

## 3. 为什么它「时序零影响」

`PositionTrack` 只写**渲染事件**（第 i 格渲染在哪儿），
**不碰 `angleData` / `bpm` / `travel` / `Twirl`**：

```
core/writer.py:133   floor.get("positionOffset", ...) ← ch.meta["pos_tracks"]
```

所以：

- 关掉开关 **不会** 改变谱面几何、命中时刻、`verify_file` 的任何一项；
- `dp_midspin` / `dp_angle` 的层号重映射都是 `if pt:` 守卫，空列表自然跳过（已核对）；
- 唯一变化是 `.adofai` 里少 N 条 `PositionTrack` 事件 ⇒ **观感**。

**这也是它能安全地做成默认开的原因**：不想要就关掉，不会牵动任何别的东西。

## 4. 验收

```
python tests/test_sidecar.py        # 83/83（上一轮 81，本轮 +2 条）
npx electron . --e2e                # 107/107（上一轮 102，本轮 +5 条）
```

新增断言（`tests/test_sidecar.py`）：

- `schema` 覆盖 `use_position_track` / `pos_track_step` / `pos_track_min_beats` 三个键；
- 三者默认值与 `core.solve.SolveParams()` **逐项一致**（沿用 schema 的既定口径：
  「UI 默认值一律从 core dataclass 取」，不在这里钉死历史数值）；
- `params_solve` 把 `use_position_track=False / pos_track_step=0.35 / pos_track_min_beats=16.0`
  真的传进了 `SolveParams`。

新增断言（`app/e2e.js`）：开关默认 `true`；**`payload` 真的暴露了 `pos_track_n`
且本谱确有错开**（防「读错 dict 导致恒为 0 的空过」）；关掉后 `pos_track_n === 0`；
状态栏出现「轨道位置偏移已关闭」；重新打开后条数回到原值。

> ⚠ 这条「防空过」的断言是**踩过坑才加的**：第一版我读的是 `rebuild()` 返回的那个
> `pos_track_n`，而 `payload()` 是另一个 dict —— 于是 `(payload||{}).pos_track_n`
> 恒为 `undefined → 0`，测试 **全绿但什么都没验**（0 → 0 → 0）。
> 修法：给 `payload()` 也补上 `pos_track_n` / `pos_tracks`，并断言 `pos_track_n > 0`。
> 实测值 **17 → 0 → 17**。

## 5. 已知边界

| 边界                                | 说明                                                          |
| --------------------------------- | ----------------------------------------------------------- |
| 只对**同位置重合**的格生效                   | 距离 < `LOOP_RADIUS`(0.35 格)、且非相邻（间隔 ≥2）、且**时间隔 > `min_beats` 拍** |
| 雪花段**排除**                         | `find_loop_groups` 里 `if getattr(fs[j], "snowflake", False): continue` —— 魔法阵**故意**原路折返，本身就是设计 |
| 方向调度（`schedule=True`）**默认关**       | 三首样本实测无净收益（循环图形彼此孤立、没有可避让的邻居），见 `track_fx.plan` 的 docstring |
| 关掉后 `pos_tracks` 为空列表 | 不是「键缺失」—— 这是刻意的，见 §2.1 |
