# 42 · 分泳道：投射时按**源轨**分轨

> 用户 2026-10：「开启下一环节：**分轨道**。现在我们需要有两个贪心投射逻辑：
> ① 采多轨道的音时，在投射中也分多轨道，备注它是哪个轨道即可；
> ② 采多轨道的双押时，把双押单开一个轨道。」

***

## 1. 一句话

投送载荷从「**按角色**分轨」改成「**按 `<角色>:<源轨>` 分泳道**」，
**双押单开一条**（它不带源轨维）。

```
选 4 条主轨 + 有双押  →  5 条泳道
   ADO·主轨 trk0   lane=main:0   413 点
   ADO·主轨 trk1   lane=main:1   126 点
   ADO·主轨 trk2   lane=main:2     9 点
   ADO·主轨 trk3   lane=main:3    81 点
   ADO·双押轨       lane=dp:       40 点
```

**兼容底线**：同一角色下**只有一个源轨**时**不加后缀**（还是一句 `ADO·主轨`）——
单轨工程的布局与老版本**逐字节不变**。只有你真的采了多条轨才分。

***

## 2. 前置：`Onset` 原本把「来自哪条源轨」扔了

`Note.track`（MIDI 轨号 / BDG 轨号 / 音频轨号）**本来就填好了**，但
`build_onsets()` 聚成 `Onset` 时只留了 `t_ms/velocity/pitch`，**源轨信息丢了**。

所以第一步是把它接上：

```python
@dataclass
class Onset:
    ...
    # ★ 这个 onset 由**哪几条源轨**的音并出来的（升序去重）
    src_tracks: tuple[int, ...] = ()
```

在 `build_onsets` 里 `src_tracks = sorted({n.track for n in 簇})`。

★ **为什么是元组而不是一个数**：一次按键可能是好几条轨**同时响**（在 `merge_ms`
内被聚成一簇）。那种**跨轨簇**必须看得出来 —— 否则「分轨道」时只能瞎归给其中一条。

> 新字段放在**最后且带默认值** ⇒ 老代码 `Onset(t, v, p)` 那样的位置构造不受影响。

***

## 3. 泳道怎么切

```python
lane = f"{role}:{源轨}"     # 音乐角色
lane = "dp:"                # ★ 双押不给源轨维 —— 它本身就是「单开的那个轨道」
```

`lane_names()`：同一角色下**只有一个源轨** ⇒ 不加后缀（`ADO·主轨`）；
真的多条 ⇒ `ADO·主轨 trk0` / `trk1`…（`names=` 还能按泳道覆盖轨名）。

每个点的 `attrs` 里**备注源轨**：

```jsonc
{ "adbIdx": 0, "adbRun": "…", "adbRole": "main",
  "adbTrack": 2,            // 归到哪条源轨的泳道
  "adbTracks": [2, 5] }     // ★ 只在**跨轨簇**时出现：这一次按键涉及的全部源轨
```

载荷还多报一个 `n_cross_track`（跨轨簇条数）—— **不许静默**。

***

## 4. ★★ 顺手抓到一个「切内置轨」带出来的坑

我们把轨从**插件轨**换成**内置踩点轨**（`docs/41`）之后，
`role_for_type("beat")` 对**每一条**内置轨都返回 `ROLE_MAIN` ⇒

* **双押泳道会被认成主轨**；
* 用户把点**拖到另一条泳道**（= 改角色）**看不出来**。

修法：**内置轨先按轨名认角色**（`parse.role_from_lane_name()`）——
我们的泳道名字就是 `ADO·主轨 trk0` 这种，名字里带着角色；认不出再退回按 `type` 认。
带插件 `type` 的轨不受影响。

★ 这里有个**故意**的选择：**不用 `attrs.adbRole` 判角色**。
因为 `attrs` 是**合并**写入的（`docs/38` §4），用户拖轨并不会清掉旧标记
⇒ 拿它判会把「拖轨 = 改角色」这个信号**弄丢**。用**轨名**判才保得住。

（`tests/test_bdg_roundtrip.py` A3 组两个方向都钉住了：双押点不被误判成换角色；
把主轨点拖到双押泳道**必须**判成换角色。）

***

## 5. ★ 要你拍板：**跨轨簇**归哪条泳道

实测（`tests/fixtures/bdg/v2_real_electric_hornet.bdg`，选主轨 0–3）：

```
629 个 onset，其中 **227 个（36%）是跨轨簇**（一次按键有多条轨同时响）
    (0,)         214
    (0,1)         87
    (0,1,3)       14
    (0,2)         14
    (0,3)         79
    …
```

现在的行为：**归到最早那条源轨的泳道**，其余源轨记进 `adbTracks` 并报 `n_cross_track`。
36% 不是小数目，所以这件事得你说一句。三条路：

| 方案 | 效果 | 代价 |
|---|---|---|
| **A（现在）归最早那条 + 备注全部源轨** | 泳道互不重叠、点数不膨胀 | 那一刻其它源轨的贡献在**泳道上看不见**（只在 attrs 里） |
| **B 复制进每一条涉及的泳道** | 每条泳道都完整 | 点数膨胀（约 +36%）、**一个 idx 出现在多条泳道** ⇒ 收回对账要改（身份不再唯一） |
| **C 分轨在**聚类之前**做**（每条源轨各自聚簇，永不跨轨合并） | 泳道天然互斥、语义最干净 | ★ **会改谱**：多轨同时响从「一次按键」变成「好几次按键」——那是另一种谱面 |

我倾向 **A**（已经实现，且不偷偷改谱），把 C 做成一个**开关**（要不要跨轨合并）。
B 不建议：它会破坏「`adbIdx` = 身份」这个对账地基。

## 6. 代码位置

| 文件 | 干什么 |
|---|---|
| `core/onsets.py` | `Onset.src_tracks` + 在 `build_onsets` 里从 `Note.track` 填上 |
| `core/bdg/roundtrip.py` | `lane_of` / `split_lanes` / `lane_names`；`build_import` 按泳道出轨；`Sent.src_tracks` |
| `core/bdg/aliases.py` | `SYNC_TRACK`(`adbTrack`) / `SYNC_TRACKS`(`adbTracks`) / `K_LANE` / `K_SRC_TRACKS` / `K_N_LANES` / `K_N_CROSS_TRACK` |
| `core/bdg/parse.py` | ★ `role_from_lane_name()`：内置轨按**轨名**认角色 |
| `sidecar/session.py` | `dp_lane_onsets()`：**真的那批双押点**（`dp_hit_idx`）单开一条；`self.dp_hit_idx` 存下来 |
| `sidecar/server.py` | 默认载荷 = 主轨 onsets（带源轨）+ 双押泳道 |
| `bridge_plugin/renderer.js` | 按名字找/建内置轨（泳道名带 `trk` 后缀也能各自认出来） |

`dp_lane_onsets()` 交出去的是**真的双押点**（上一次 `rebuild` 的 `dp_hit_idx`），
**不是**双押轨上的音 —— 双押轨本身不参与采音（它只标记「哪些 onset 出双押」）。

## 8. 还没做

* **跨轨簇的方案**（§5）等你拍板；C 的开关没做。
* **UI 里看不见泳道**：投射完只在状态栏多一句话，还没有「哪条泳道多少点」的列表。
* **收回时的泳道归属**：现在靠 `attrs.adbRole` + 轨名；如果用户把两条泳道的点
  混在一起（把 trk0 的点拖到 trk1 的轨），我们只会看到**角色没变**（都还是 main），
  源轨归属**不会**跟着更新 —— `adbTrack` 是投送时的快照，用户拖轨不改它。
  要的话得在收回时用「点在哪条泳道」反推源轨（轨名里有 `trk` 号）。
