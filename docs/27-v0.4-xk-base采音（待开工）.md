## 2. 由此推出的含义（我的整理，**标注了哪部分是我推的**）

### 2.1 「Nk base」= 以「每拍 N 个按键」为谱面基础

用户说的「使用的键 / 使用 N 根手指」= **每拍落 N 个按键**。于是：

```
Nk base  ⇒  cbpm = tbpm × N        （用户原话，N = 2）
            2k base → cbpm = tbpm × 2
            4k base → cbpm = tbpm × 4
            8k base → cbpm = tbpm × 8
```

> ⚠ **括号里的「几分音」标签我没有再写死**（第一版写的是 8/16/32 分音，删了）。
> 理由：用户说「大直线 = 直接采 **4 分音**」，而按 `docs/双押逻辑.md` 的
> `cbpm = tbpm × 4` 换算，×4 对应的是 **16 分音** —— 两处对不上，
> 说明「N」到底数的是**每拍的键数**还是**几分音的分母**，我还不能确定。
> 用户已明确「**做0.4的时候细说**」，所以这里**只存事实，不做推论**。

**★ 这条正好解释了项目里一个一直没被点名的隐含约定。**
`docs/双押逻辑.md` §「BPM 口径」写着：

```
tbpm = cbpm ÷ 4        ⇒  cbpm = tbpm × 4
（原文交叉验证：360bpm 的 16 分音 ⇒ tbpm 360 ⇒ cbpm 1440 ✓）
```

`cbpm = tbpm × 4` **就是 4k base**。也就是说：

> **现有求解器实际上一直在做「4k base」，只是那个 4 从没被当成参数暴露出来** ——
> `base_bpm` 是求解器**自己挑八度**挑出来的（实测 FallenEra 出现过 `119.84 / 180 / 359.5`，
> Automaton 出现过 `185 / 359.5 / 370`，见 `docs/双押逻辑.md` §「架构问题」）。

**xk base 要做的，就是把这个「倍率」变成用户说了算的东西**，并且不再由求解器随机挑八度。

### 2.2 ★ 「大直线 / 采bpm」= **强行铺 4 分音**，无视音符排列

用户原话：**「大直线 意思就是直接采 4 分音，无视所有音符排列强行采音。
绝对能对上拍但是绝对不好看」**。

这条把「采bpm」从「侦探式测 tempo」里摘出来了 —— **它不是去猜 BPM，而是直接铺一条骨架**：

```
大直线：  无视 onsets 的排列，按「一拍一个方块」硬铺 → 一条笔直的长直线
          骨架自带节拍 → 绝对对得上拍
          代价 = 绝对不好看（因为它跟音乐内容毫无关系）
```

**★ 项目里其实已经有这个旋钮了**：`sidecar/schema.py`

```python
BEAT_BEATS = (0.0, 0.25, 0.5, 0.75, 1.0, 1.5, 2.0, 4.0)   # ← 「一条直线 = 」的可选值
_f("ref_index", "solve", "一条直线 = ", "combo", default=0, ...)   # 0 = 自动
```

`beat_beats = 1.0`（列表里的第 4 项）就是**「一条直线 = 1 拍 = 4 分音」**，
README 也写着「手动钉死『一条 180° 直线 = 几分音符』（基准 BPM = 歌曲拍速 ÷ 音值）」。

差别在于：

|                    | 现状                                    | 大直线 / 采bpm                        |
| ------------------ | ------------------------------------- | --------------------------------- |
| `ref_index`        | **默认 0 = 自动**，求解器遍历候选音值自己挑            | **钉死到 4 分音**，不给求解器挑               |
| 音符从哪来              | 从 **onsets** 出发，DP 拼几何                 | **无视 onsets**，直接铺等间隔直线            |
| 结果                 | 尽量贴音乐                                 | 绝对贴拍、绝对单调                         |

> ⚠ 别把它想成 `ref_index = 4` 就完事 —— 现在就算把 `ref_index` 钉到 `1.0`，
> 后面的 DP 仍然会按 onset 时刻去落块。**「无视所有音符排列强行采音」是新行为，不是旧参数。**

### 2.3 ★ 所以它**必须**和 双押 / 三押 / 四押 连用

用户原话：**「所以采bpm需要和双押、三押、四押这种逻辑连用」**。

含义很清楚：**大直线是骨架，不是成品。** 4 分音骨架保证了拍准，但要变成能看的谱，
必须在其上叠**多押**（一次按下多个键）来承载真正的音乐内容。

> ★★ **一个必须先说清的现状：多押的「判定与语料」早就有了，缺口在「生成机制」。**
>
> **已有（别重新发明）** —— `docs/10-节奏型库.md` §「补充：三押、四押也在」：
>
> - 用户口径：「夹角之间不足 30°（300+ bpm）时，可以直接按多押打（此时为完美无瑕）。
>   低于 300 bpm 时最好使用 15°」
> - **实测：295 张谱 / 794 765 层**（`tools/_analyze_multipress2.py`）——
>   **三押 3 929 处、四押 1 514 处**；真多押 **96% 是同向**（同向 3 773 vs 交替 156）
> - 写法清单：三押 `90°·90°`(1411) · `15°·15°`(678) · `30°·60°`(450) · `30°·30°`(161)；
>   四押 `30°·60°·90°`(365) · `1°·1°·1°`(134) · `90°·180°·90°`(94)
> - **判定口径已定**：`v = (travel/180)/speed`，`Δt = v × 60000 / BPM`，
>   **多押 = Δt ≤ 35 ms**，**连续 n 个多押 gap → n+1 押**；
>   且该段**前后必须各有一格正常间隔**（否则高速段会被整段误判，`docs/11` §6.3）
> - 相关工具：`tools/_multipress_runs.py`、`tools/_analyze_multipress.py`、`_analyze_multipress2.py`
> - `docs/10` 末尾自己留的口子：「**多押本身（含三押、四押）留给多轨那条线**」
>
> **缺口（0.4 要做的）**：`core/` 里 grep `三押` / `四押` = **0 命中**，
> 生成侧至今**只有双押** —— `core/dp_midspin.py`（中旋双押）+ `core/dp_angle.py`
> （角度双押，`choose_thin` 按 `cbpm ≥ 300` 选 15°/30° 薄格）。
>
> ⇒ 0.4 的活是**把已有的多押知识变成生成器**（判定口径直接复用），
> 而它天然依赖 xk base 给出的「每拍 N 个键位」。
> 链条：**xk base（键位密度）→ 骨架（大直线）→ 多押（内容）**。

### 2.4 ★ 采bpm 打开后：**主轨采音失效，其余音轨只能当多押**

用户原话：**「选择采bpm之后，就默认不能再采使用别的音轨了，只能把别的音轨当多押用」**。

这是在回答「采bpm 之后别的音轨还能不能采音」——**不能**。规则很干净：

```
采bpm 关：① 主轨（勾哪几条采哪几条）→ 采 onset → 现有求解
采bpm 开：谱面完全由「4 分音骨架」决定 ⇒ **主轨失效**
          其余音轨**只能**作为多押来源（双押 / 三押 / 四押）
```

**为什么这样才对**：大直线的定义就是「无视所有音符排列强行采音」（§2.2）。
如果还允许别的音轨往骨架里插按键，那就不叫「无视排列」了 ——
骨架提供**节拍与物量**，其它音轨只提供**同时按几个键**（多押）。

**落到现有代码**（`sidecar/schema.py` 的 `TRACK_LIST_ROLES`）：

```python
TRACK_LIST_ROLES = {
    "onset": ("lst_tracks", "主轨（可多选）：勾哪几条就采哪几条，取并集"),
    "dp":    ("lst_dp",     "勾选当作双押轨的轨（不参与主轨并集）"),
}
```

好消息：**「双押轨不参与主轨并集」这条本来就写死了**（注释原文），
所以「其余音轨只能当多押用」是既有口径的自然延伸 —— **只需把 `dp` 轨从「双押轨」升格成「多押轨」**。

UI 上要做的（0.4）：

- 采bpm 打开时，**② 主轨那一组锁死 / 置灰**，并在组标题旁写清「采bpm 已接管，主轨不参与采音」；
- 双押轨那一组的标签改成 **多押轨**，并按 §2.3 的清单放开 三押 / 四押。

> ⚠ 这条**顺带把 §4 Q3 答了**：采bpm **不产出 onset** —— 它**取代**了 onset 采音。
> 于是 `core/audio_onsets.py`（检波）在采bpm 模式下**整条不跑**，
> 但「一拍有多长」（骨架的 `beat_ms`）**仍然要有来源**，那条还得细说（见 §3 表格）。
