## 0. 单位与命中（★ 先钉死口径）

用户说的 **`cur` 的单位是「格/秒」**，而本项目的 `Floor.bpm` 是 cbpm（格/分钟）：

```
cur(格/秒) = cbpm / 60
```

**判定依据**：145 份语料里按三种解释各筛一遍 ——

| 解释 | 命中 |
|---|---|
| **格/秒** `max ≥ 40 且 mean ≥ 20` | **9 份**（去重后 8 份）★ 有选择性的子集 |
| `×base`（相对基准速度的倍数） | 1 份（太严） |
| cbpm | 几乎全中（太松） |

## 2. 轨道写法（84 个超高速段实测）

| 指标 | 实测 | 读法 |
|---|---|---|
| 段内每格 ms 只有 1 种（**严格等间隔**） | **11 / 84 = 13%** | 超高速段**不追求等间隔** |
| `travel` 全是 90 的倍数 | **35 / 84 = 42%** | 略多于四成是"直角/直线" |
| `travel` 种类数（众数） | **2 种 × 33 段、3 种 × 17 段** | ★ 主流是**两三种 `travel` 交替**，不是单一值 |
| 中旋格（`angleData=999`）合计 | **488** | 中旋用得很多 |
| Twirl 合计 | **1567**（平均每段 **18.7 个**） | ★ Twirl 密度高 |

**⇒ 模板 R1**：超高速段的轨道写法是
「**少量几种 `travel` 交替 + 高密度 Twirl + 大量中旋格**」，
**不是**「全直线 + 等间隔」（那只占 13% / 42%）。

★ 对照 `docs/64` §11.9 的「采 bpm 段」判据（`cur ≥ 2×base` + `travel` 全是 90 的倍数）
—— 那**只是** 42% 的那一半；超高速段还有一多半是"花"的。

## 3. 镜头写法（段内 68 条，只有 3 份谱有）

### 3.1 定量口径

| 指标 | 实测 | 说明 |
|---|---|---|
| 角色 | 补间 ×72 · 硬切 ×17 · 定基 ×16 | **硬切和定基一起占 1/3** |
| **`relativeTo`** | **`Player` ×34（50%）· `LastPosition` ×31（46%）· `Tile` ×3（4%）** | ★ **`LastPosition` 近一半** |
| `duration`（**拍**） | 中位 **8**，另有 16 / 28 / 64 / 128 / 256 | ★ **时值按「拍」写，不按格** |
| **覆盖格数** | 中位 **96.6**，范围 **0 ~ 1630.8** | ★ 一步跨上百格 |
| `zoom` | 中位 250，范围 100 ~ 550 | |
| `position` | `[0,0]` ×43 / 非零 ×25 | 近 2/3 不动位置 |
| `ease` | `Linear`×24（**全是 `dur=0` 的硬切/定基**）· `OutQuart`×9 · `InCubic`×8 · `OutBack`×7 · `OutQuint`×7 · `OutQuad`×5 | 真补间用 `Out*`/`In*` |

### 3.2 四个家族（可直接抄）

#### 家族 ① 「视差摆头」—— `LastPosition` 硬切 + 补间，成对（`drive-download`）

```
f     硬切  LastPosition  pos=[0,0]  rot=-7  zoom=190  dur=0   Linear
f     补间  LastPosition  pos=[0,0]  rot=+7  zoom=300  dur=8   OutQuart
f+12  硬切  LastPosition  pos=[0,0]  rot=+7  zoom=190  dur=0   Linear
f+12  补间  LastPosition  pos=[0,0]  rot=-7  zoom=300  dur=8   OutQuint
```

* **`LastPosition`** ⇒ 镜头**不跟玩家**、停在原地；
* `rotation` 只 ±7°，`zoom` 190↔300 呼吸；
* **硬切负责"咬住"，补间负责"摆"**；
* 实测重复间隔 **1066 / 1144 格**（与音乐小节对齐），全谱重复 7 次。

#### 家族 ② 「段落级 push」（`drive-download`）

```
f  补间  Player  pos=[0,2]  rot=0   zoom=300  dur=128  OutBack   （跨 1176~1631 格）
f  定基  Player  pos=[0,0]  rot=10  zoom=1    dur=0    Linear
```

* 一个 **128 拍**的长推，跨**上千格**；
* 配一条 **`zoom=1`** 的瞬切 —— 「**先怼到极小再推出去**」的起步加速。

#### 家族 ③ 「成对呼吸」（`2599299341`）

```
f     补间  Player  pos=[3,1]  rot=-3  zoom=450  dur=8  OutQuad   （跨 161.7 格）
f+8   补间  Player  pos=[3,0]  rot=+5  zoom=250  dur=8  InQuad
```

* **`Out*` 出去 + `In*` 回来**，成对；`duration=8 拍`；三个小节重复一组。

#### 家族 ④ 「统一 16 拍长补间」（`削弱版 selfmade disaster`）

```
f  补间  Player  pos=[0,0]  rot=5  zoom=550  dur=16   InSine
f  补间  Tile    pos=[-1,0] rot=0  zoom=250  dur=16   OutQuad
f  补间  Tile    pos=[-1,0] rot=0  zoom=300  dur=256  InOutBack  （跨 1536 格）
```

* 时值统一 **16 拍**；`relativeTo` 在 `Player`/`Tile` 之间切换；`zoom` 跨度大（100/250/300/400/550）。

## 4. ★★ 这张表回答了一个悬了很久的问题：**时值按「拍」还是按「格」**

`docs/64` §11.7 留的问题是「高 cur 缓慢的时值按格还是按拍」，
`docs/65` §7 也提到过。**语料给了答案，而且是分档的**：

| `cur` | 时值口径 | 覆盖格数 | 依据 |
|---|---|---|---|
| **普通**（≈1 格/拍，慢段） | **按格**（一条补间 ≈ 1 格） | 1 格 | `docs/64` §11.3：教学谱四档 `cur` 的覆盖格数众数都是 **1.0 格** |
| **高 cur**（做过 `SetSpeed`） | **按拍**（8 / 16 拍） | 数十格 | 本文 §3.1：中位 8 拍 |
| **超高速**（≥ 40 格/秒） | **按拍**（8 / 16 / 64 / 128 / 256 拍） | **上百 ~ 上千格** | 本文 §3.1：覆盖格数中位 **96.6** |

⇒ **不能用一套口径打天下**：
慢段「一格一补间」，超高速段「一段几拍、跨上百格」。

★ 这**推翻了** `tools/make_camera_demo.py` 里那个「所有时值一律按格写」的临时决定
（见 `docs/64` §11.6）：它在普通速度下没问题，**在超高速段会把镜头退化成
"只覆盖几格"的微观抖动**，而语料要的是**宏观运镜**。

1. **「40 格/秒」这个门槛**是主人给的；语料里 40~50 格/秒的 4 份**全部没有镜头**，
