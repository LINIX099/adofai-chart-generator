## 1. 去噪定稿（`core/denoise.py`）

### 1.1 网格的定义 = 宿主吸附的定义

```
time = offset + beat · (60000/baseBpm)        ← 宿主 tempo.ts / store.ts
snapBeat(beat, div) = round(beat·div)/div     ← 半数向 +∞（JS Math.round）
⇒ 毫秒轴上的格：t = φ + k · (period/div)，period = 60000/baseBpm = 「砖长」
```

★ 两处**必须**记住：

1. `Math.round` 是**半数向 +∞**（Python 的 `round` 是银行家舍入）⇒ 代码借
   `core.bdg.snap.js_round`，`tests/test_denoise.py::C_half_grid` 拿 `±2.5 格`
   当探针证明两者确实会分道扬镳。
2. **相位 φ 就是我们的 `offset`**（同一个物理量、同一根轴）⇒ 不能分开调；
   `plan(ts, offset_ms=…)` 给了 offset 就用它当相位，并把「差几格」报出来。

### 1.2 三个决策（用户说「按照合适的来」）

| 决策 | 取值 | 依据 |
|---|---|---|
| 默认吸附范围 | **全吸**（`radius=None`） | 与 BDG 一致；给 `radius` 才是「只吸离格近的、远的原样保留」（BDG 没有的能力） |
| 分母 | **自动**：`safe_div()` = 最细但仍 `step ≤ 最小间隔` 的那一档，上限 1/32 | ★ 太粗吸不掉抖动、太细两个音撞进同一格（宿主 `addMarker` **静默返回 null = 丢音**） |
| 相位 | 用数据拟合；给了 `offset` 就用 offset 并报偏差 | 相位 = offset（1.1 第 2 条） |

**实测（Flower_Dance 的 1358 个时间戳，`tools/_denoise_live.py`）**：

```
div=1  格150.00ms  丢 9 个音（撞格）      格距 2 的幂 96.5%
div=2  格 75.00ms  丢 0                 93.0%
div=4  格 37.50ms  丢 0   中位挪 2.3ms  89.6%   ← 自动选到这一档
div=8  格 18.75ms  丢 0                 85.1%
div=16 格  9.38ms  丢 0                 64.2%   ← 抖动被切成 ±1 格，结构崩
div=32 格  4.69ms  丢 0                 38.1%
```

⇒ 「最细但安全」= 1/4，同时**结构最好、不丢音、抖动全吸收**（抖动 ±6ms « 半格 18.75ms）。

### 1.3 ★★ 周期不能被抖动骗走（这是本期最难的坑）

`core.gridfit.refine_period()` 用的是**拍级集中度 R**。抖动的点会让 R 的极大点
被「把拍对齐」那种**宽平山顶**骗走 —— 实测同一份短样本上它给

```
period 148.99 / 相位 92.32 / R 0.78      （真值 150 / 76.87）
⇒ 每个点都吸到邻格，13/14 个点错位
```

改成直接量「点离最近格多远」的**格内平方残差**（`_step_loss` + `refine_step`，
三段收敛 2% → 0.1% → 0.005%），判据与目标（我们接下来要挪多少）一致。

**然后是可辨识性问题**：短样本 + 抖动时，0.06% 的周期误差在 2 秒里只造成 1.2ms
漂移，而抖动有 ±5ms —— **任何方法都分不出来**。但真值几乎总是「人写的整齐值」
（那份 RL 数据就是正好 **400 BPM / 150.000ms**）。所以再加一层
`snap_nice_period()`：**只在不会让格内残差变差**时（`l_nice ≤ l_ref × 1.25`）
才吸到整数/半整数 BPM。

> 长样本上精修已经到 1e-6，整齐值会让残差明显变差 ⇒ **自动拒绝**，不会把好周期搞坏；
> 短样本上两者都在抖动底座上 ⇒ 接受整齐值。

真数据结果：`period 150.000000ms / bpm 400.000 / 相位 +2.131ms / 1/4 格 / 丢 0 个`。

### 1.4 不许静默

`denoise()` 返回（并进 `warning_list`）：

* 每个点挪了多少（中位 / p90 / max / 占几格）；
* **撞格被丢的点**（含它原本的时刻与目标格位置）—— 宿主那边这是**静默 null**；
* 半径档下**原样保留**的点数；
* 砖长依据、分母依据、相位偏差、周期是否取整齐值。

## 2. 直拟合（`core/fitdirect.py`，`fit_mode="direct"`）

`solve()` 是**最优化**（模板/三连音/雪花/回正），代价是**会改时序** —— 对抖动时间戳
实测 261s 上漂 **155ms**（`tools/_ext_ts_go.py`）。直拟合反过来：**时序优先，几何服从**。

```
每个 onset = 一层（长间隔拆成若干「填充层」）
travel = 180 · (Δt / period) / k        k ∈ SPEED_TIERS（2 的幂）
⇒ 每层时长 = (travel/180)·(60000/(base/k)) = Δt   ← times_from_chart 的逐字模型
```

* **逐点精确**：`times_from_chart()` 反算的 entryTime 与输入**零误差**
  （实测 `err_max_ms = 0.000000`；这也是验收线，见 `tests/test_fitdirect.py::A_exact`）；
* **速度档策略**：默认「粘住上一档」（`keep=[20,340]`），只在保持会让 travel 越界时才换
  ⇒ 换档更少；`keep=(-1,-1)` 可切成「一味求直」（实测 88.7% → **89.6%**，SetSpeed 175 → 193）；
* **直线率**：去噪后实测 **88.7%**（格距是 2 的幂的比例 = 89.6%，两者对得上）。
  对比 `solve()` 那条路靠模板/三连音能到 39~42%（但会漂）—— **两条路各有取舍，界面上选**；
* ★ **`ch.meta["onset_floors"]`**：onset ↔ 层 的对应表。有填充层时
  「第 i 个 onset 在第 i+1 层」**不成立**，`sidecar.session.rebuild` 的 `hit_times`
  与双押落点必须走这张表（已改，且被 `test_sidecar[16]` 守住）。

## 3. 收回轨道项目（回传协议）

### 3.1 用户口径 → 设计

> 「我们的工具使用的音轨**就是** BDG 里面带时值数据的音轨。」

⇒ 判定标准 = **哪条轨上有我们投送过的标记**（`attrs.adbIdx` / `adbRole`）。
一条 **BDG 轨 = 我们的一条音轨项目**（**按轨分组**，不是按泳道键 —— 跨轨簇的点仍然
留在它原来那条轨上）。用户自己新建的轨**不搬**：那是他的素材，不是我们的谱。
轨上**用户新加的点**（没有标记）照搬，并单独计 `n_added`。

### 3.2 线格式（插件 → 我们）

```jsonc
{ "type": "tracks",                  // ← docs/45 新增的入站类型
  "run": "20261010-…",               // 批次号（取我们标记里的多数派）
  "anchor": { "baseBpm": 400.0, "offsetMs": 2.131 },   // 宿主当前的锚
  "n_points": 631, "n_added": 2, "n_skipped": 0,
  "tracks": [
    { "name": "ADO·主轨 trk0", "role": "main", "lane": "main:0", "src_track": 0,
      "points": [ { "idx": 3, "beat": 12.25, "ms": 1840.6, "src_tracks": [0] } ] } ] }
```

* `ms` 用宿主快照自带的 `timeMs`（它的模型算的），我们没有二次换算；
* `idx: null` = 用户新加的点；
* `src_tracks` 保留跨轨簇的全部源轨号（收回来之后仍然知道它是好几条轨同时响）。

插件侧：`bridge_plugin/renderer.js` 的 `collectBack()` / `sendBack()`，
面板上那颗 **「⤴ 返回数据到谱面生成器」**（另有菜单项与快捷键 `Alt+Shift+R`）。

### 3.3 我们这边（`sidecar/bridge.py` + `sidecar/session.py`）

```
type:"tracks"  →  Bridge._on_tracks()
                 ├─ core.bdg.roundtrip.back_lanes()   规范化泳道（纯函数，可离线测）
                 └─ Session.restore_tracks(payload)
                      ├─ lanes_back   = 收回的轨道项目（UI ② 列表就是它们）
                      ├─ onsets_override = 非 dp/off 泳道的点（按 ms 去重）
                      ├─ dp_back      = 双押泳道（再投射时原样还给它）
                      └─ back_meta    = 报告（轨/点/新加/合并/锚差）
```

* **音轨列表（`Session.track_map()` → `lanes_map()`）在收回模式下就是那些轨**
  （`index` = 泳道下标，`suggest` = 角色，`summary` 带点数与时间范围）；
* `derive()` 走「轨道项目模式」：明说「不再从 MIDI 采音」；
* `rebuild()` 在收回模式下**跳过采样**，直接用收回来的点；
  ★ 有收回的轨道项目时**区间/分段整个忽略**（会报一条警告，不许静默）；
* `dp_lane_onsets()` 优先用 `dp_back`（双押轨的点就是权威，不再靠对账重新认）；
* HTTP：`GET /api/bridge/back`（看一眼）、`POST /api/bridge/back/apply`、
  `POST /api/bridge/back/clear`；界面 block 在 BDG 桥下面。

### 3.4 ★ 收回时两条「对不上」的体检

1. **锚不一致**：拿宿主报的 `anchor` 反算 `beat×period+offset` 与它给的 `ms` 比 ——
   对不上说明**用户在那边改过 baseBpm/offsetMs**，这会让整首错位 ⇒ 报 `anchor_mismatch_ms`；
2. **同刻合并**：两条泳道在同 1ms 内都有点 ⇒ 合成一次按键并计 `n_dup`（宿主的
   `addMarker` 在同拍会静默返回 null，我们自己先合）。

### 3.5 落格锚（`anchor_from_grid`）

直拟合 + 去噪时，交给宿主的 `offsetMs` **不是** `.adofai` 的 offset，而是**格相位 φ**：
只有这样才能让宿主的 `beatOfTime(点)` **恰好**等于 `k/div`（整数格），用户那边顶栏
一调分母就对齐，且不会被它的吸附再挪一次。差多少会写进 `warning_list`。
（关掉这个开关就退回旧行为 = 用 `.adofai` 的 offset。）

## 6. 边界与风险

* **倍频不可辨识**：全是 16 分时「砖长」会取到细分（bpm 变 4×）。对吸格无害
  （div 跟着变细），但对「交给宿主的 BPM」有影响 —— `tile_period` 的注释写了
  为什么不再拿一个离群间隔去决定倍频（原来那样会把 151 拽到 75.6）。
* **自动分母是「最细但安全」**，不是「最粗」：密集段（最小间隔很小）会选到 1/16，
  抖动会被切成 ±1 格 —— 到上限时会明说，用户可用 `denoise_div` 手动压粗。
* **轨道项目模式与区间/分段互斥**：同时存在时区间/分段被忽略并报警告。
* **还没做**：BDG 侧完整的 importer（现在只做了「时间戳」这一种，见 §7）；
  泳道拖拽/命中测试；`docs/27` 的 xk base 采样。

## 7. 补：**毫秒时间戳**两端都打通（用户 2026-10）

> 用户把那条链路写成两段：
>
> ```
> midi        ──► 多条音轨 ──► 采音 ──► BDG（保留多音轨线）        ← §1~§3 已通
> 毫秒时间戳  ──► BDG ──► 回到我们的工具                          ← 本节补的是它
> ```
>
> 查了一遍：**第一段箭头（时间戳 → BDG）当时根本没有入口** —— `load()` 只认
> `.mid/.midi` / 音频 / `.bdg`，27 个 `/api/*` 里也没有导入时间戳的；而且
> `rebuild()` 第一行就是「先加载一个 MIDI / 音频」⇒ 纯时间戳工程起不来。
> 现在两端都补上，并且顺手修了 §6 里那条 `adopt_onsets` 丢源轨的不一致。

### 7.1 时间戳当**一等来源**（`core/ts_source.py`）

老套路复用：**做成一种 `MidiFile`**（`docs/38 §9` 对 BDG 用过一次），于是
「选轨 → 采音 → 求解/直拟合 → 桥」**一行都不用改**：

```
一份时间戳 ──read_ts──► [ms…] ──to_midi_like──► MidiFile（一条轨，每点一个 Note）
                                                  │
                        现有 UI / 现有管线 / 桥接锚 全部照旧
```

* **认四种写法**：一行一个毫秒数（我们见过的那种）· CSV（取**每行最后一个**数，
  因为常见导出是「序号,毫秒」/「标签 毫秒」）· `mm:ss.xxx` / `hh:mm:ss.xxx` ·
  JSON（数组，或 `{"timestamps":[…]}` 这类带键的）。跳过的行、识别到的格式、
  去重与丢弃**全部记进报告**（`ts_source.report_text`）。
* **砖长/网格在这里就算出来**（`core.denoise.plan`，同一个真源）⇒ 界面文件信息行
  直接显示「砖长 150.0000ms（bpm 400.000）· 相位 +2.131ms · 分母 1/4」。
* **三条默认值**（`load()` 里给前端）：`merge_ms = 0`（30ms 的默认合并会把密集处的
  点**悄悄并掉** —— 时间戳是"点"不是"音"）、`fit_mode = direct`、`denoise_on = true`。
* 界面：① 的文件对话框与按钮都加上时间戳后缀；`default_merge_ms/fit_mode/denoise_on`
  在 `doLoad` 里落到控件上。

### 7.2 插件侧**导入时间戳**（`bridge_plugin/renderer.js`）

面板新增「⇣ 导入时间戳文件…」，菜单里也有一项，并且注册成宿主的**导入器**
（`api.ui.registerImporter`）。流程：

```
pickFile + readText（插件能读文件，`docs/44` 更正过）
   → 解析成 [ms…]（与 Python 侧同一套规则）
   → {type:"grid", times:[…]} 问我们：砖长/相位/分母
   → setBaseBpm + setOffset（★ 锚必须早于拍位）→ addTrack → addMarker + attrs
   → 回读比对：被吸附挪了就报出来，并让用户把分母设成 1/div
```

* ★ **格子只有一个真源**：吸附数学在 `core.denoise`（Python），JS 再写一份必然分叉
  ⇒ 插件只负责「读文件 + 画点」，`grid` 消息由我们算。算不出来/没连上就**明说**
  （按宿主当前锚硬摆 + 提示可能被吸附挪动）。
* 摆完的点**都带 `adb*` 标记** ⇒ 按「⤴ 返回数据到谱面生成器」能整条收回，
  链路闭合：**时间戳 → BDG（看得见、可手改）→ 回到我们的工具（音轨 = 那些轨）**。

### 7.3 没有源文件也能重建（`Session.ensure_engine`）

用户可以**只在 BDG 里**开工（自己摆点，或用上面的导入器），回来时我们这边
一份 MIDI/OGG 都没有，而 `rebuild` 的下游（`ppqn`/`bpm0`/`length_ms`）都要一个
`midi` ⇒ 现在自动造一个**只带时轴**的引擎（一条空轨 + bpm 取自去噪砖长 +
`length_ms` = 末点 + 4 拍），并在 `warning_list` 里说明「没有音频可预览」。

### 7.4 修掉 `adopt_onsets` 丢源轨（§6 那条不一致）

* `roundtrip.onsets_out()` 现在把 `src_tracks` 一起带回来；
* `session.adopt_onsets()` 用它造 `Onset`，并且 `role == dp` 的点进 `dp_back`
  （与「返回数据到谱面生成器」同口径）⇒ 走完「收回改动」再投射，**泳道不再塌成一条**；
* 顺带报 `n_dp` / `n_lanes`。

### 7.5 这一段里踩到的两个坑（都已进单测）

1. **拍级集中度 R 不能当网格门槛**。`gf.concentration(t, period)` 量的只是
   「音是不是都落在整拍上」—— 一首 8 分/16 分为主的曲子 R 会接近 0，于是真值
   150ms 的格被判「跟音乐没关系」（实测 R=0.05）。改成：**格级 R** 当门槛
   （配 Rayleigh `z = R·√n ≥ 2.5`），**拍级 R** 只当情报报出去；拍级低的时候
   额外说一句「音不都在整拍上，网格是照 1/div 定的，这本身不是错误」。
2. **插件的信封占用 `ts`**。`Session.send()` 会给每条消息打 `{v, seq, ts}`，
   我一开始用 `ts` 装毫秒数组 ⇒ 被 `ts: Date.now()` 冲掉（`gm.ts.length` 成了
   `undefined`）。键名改成 **`times`**，服务端两种都收；插件单测里留了一条
   「信封的 ts 没被挤掉」的断言。
3. 另外：`_explain` 的判据从「`period` 的整数倍」改成「**`period/2` 的整数倍**」——
   半砖/四分之一砖是**合法细分**，不该把砖长否掉（原来 8 个间隔里有一个半砖就会
   把 bpm 从 400 拽到 800）。
