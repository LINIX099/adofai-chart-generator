## 0. 用户口径（原文）

```
1 需要对音时，先找能不能用已有图形定义
2 找不到时 从当前旋转角度的180°范围内，寻找一个能对上音的角度
3 再找不到时 添加旋转事件，从新的180°寻找能对上音的角度
4 再找不到时 先变速，然后1 2 3
5 在找不到时 使用暂停节拍

但是，如果4产生的角度 低于最小角度
使用5
```

一句话概括：**把「一次按键 = 一个方块」的落点决策，改写成一条逐级降级的阶梯**，
前一级都失败才允许动下一级；`变速` 是第 4 级，`暂停节拍` 是兜底第 5 级。

## 1. 关键事实（动手前必须认账的数学）

### 1.1 时间模型（全项目唯一真源：`core/path.py` + `core/solve.times_from_chart`）

```
每格时长   dt_i = (travel_i / 180) × 60000 / bpm_i   [+ pause_beats_i × 60000 / bpm_i]
速度档     bpm_i = base_bpm / k_i          k ∈ SPEED_TIERS = (1/8,1/4,1/2,1,2,4,8)
几何       turn_i = ±(travel_i − 180)      （符号由 parity 决定，归一化到 (−180,180]）
           heading_i = heading_{i−1} + turn_i
           a_i = (90 − heading_i) mod 360          ← 写进 angleData 的就是它
parity     ccw_i = ccw_{i−1} XOR twirl_i
```

### 1.2 ★ 四条恒等式（本文全部推论都建立在这四条上）

**(A) 给定档位 k，travel 被完全确定，没有自由度**

```
r_i = Δt_i × base_bpm / 60000          （间隔占几「基准拍」）
travel_i = 180 × r_i / k_i             ← 反解自 dt_i ≡ Δt_i
```

**(B) Twirl（parity）不改变时长**，只切换同一个 travel 的两种写法

给定前一格的写入角 `a_{i−1}`，令 `Δa = a_i − a_{i−1}`（归一化）：

| parity   | 写出来的 `Δa`    | 由它反解出的 travel |
| -------- | ------------ | ------------- |
| 不加 Twirl | `+(180 − T)` | `T`           |
| 加 Twirl  | `−(180 − T)` | `T`           |

两种写法**互为相反数**（关于前一格的角镜像），**有效 travel 完全相同、时序一模一样**，
只有路径几何不同（互为镜像）—— 这与 `docs/16` §4.2 实测一致
（`[θ, T−θ]` 不加 Twirl ≡ `[360−θ, 360−(T−θ)]` 在第 1 格加 Twirl）。

> 措辞校正（`tools/_ladder_verify.py` 实测）：两者的**差**是 `2(180−T)`，
> 只有 `T = 90 / 270` 时差恰好 180°。说「180°」的准确含义是：
> 两种写法的**出射朝向关于「当前朝向」镜像**，两者都落在 `±(180−T)` 这个扇面里，
> 而该扇面最大不超过 **±180°**（= `turn` 的合法区间）。见下面的恒等式 (D)。

**(C) 半圈的划分与 parity 无关，只取决于 T 自己**

```
T ≤ 180  ⇔  turn ≤ 0  ⇔  内圈（行星切角，走短线）
T > 180  ⇔  turn > 0  ⇔  外圈（行星绕一大圈）
```

**(D) 两种 parity 的出射朝向关于「当前朝向」镜像**

```
turn(无Tw) = +(T − 180)        turn(有Tw) = −(T − 180)
heading'(无Tw) = h + (T − 180)  heading'(有Tw) = h − (T − 180)
```

`tools/_ladder_verify.py` 已对**代码本身**（`core/path.turn_of` + vendored parser 的
反解公式）逐值验过 B / C / D 三条（T 从 15° 到 345° 全部 OK）。改本文之前先跑那个脚本。

> ### ★★ 必须直视的结论
>
> **「对音」的自由度只有两个：换档位** **`k`（第 4 级）与** **`Pause`（第 5 级）。**
> 「180° 范围」与「加 Twirl」**不提供新的时间自由度** —— 它们决定的是
> **几何/观感**（走哪个半圈、镜像还是同向、会不会自重叠），也就是本项目既有的
> 「内圈优先 / 直线优先 / 不自重叠 / 少图标」那一套评分。
>
> 所以阶梯应当被理解成：**每一级都在扩大「可接受的落点集合」**，
> 而不是「每一级都在时间上更灵活」。第 2/3 级扩的是**几何候选**，
> 第 4 级扩的才是**时间候选**。

### 1.3 三条不能动的不变量（每一步都要守）

1. `Σtravel_i ≡ 180 × n (mod 360)` —— 闭合（README 红线，破了就逐格漂角）
2. 第 0 格 `travel = 180`、`angleData[0] = 0`（真谱 95.6%）
3. 不许回头方块：`15° ≤ travel ≤ 345°`（游戏对 `angleMoved ≈ 0/2π` 特判成 2 拍）

> ★★ **2026-10 补**：上界现在是 `min(345, p.travel_max)`（UI「最大夹角」，
> 见 `docs/63` §2.3 / §12.1）。以前这里写死 345，`travel_max` 整个阶梯一次都没读过，
> 而且 `solve_aggressive` 连 `meta["travel_max"]` 都没写 ⇒ `rules` 的 ③c 也瞎了
> （`out/_grin/grin.mid` 实测：`travel_max=270` 却吐出 345°/338.25°/331.5° 共 10 格，
> 状态栏还写「违规 0」）。实现见 `core/ladder.travel_hi` / `rung_ok`。

以及本项目既有的：Twirl 与 SetSpeed 不同格、`travel ≥ travel_min`（**豁免：双押薄格 / 中旋格 /
雪花段**，见 §9.10）、模板/自然/引擎/雪花段是**锁定段**不许拆、`Pause` 格是屏障（跨不过去拼闭合）。

> ★ **上界不适用「豁免」**：`exempt`（双押/雪花）只免**最小角度** ——
> `rules` 的 ③c 只对双押格开口子（雪花段照查），两边口径必须一致，否则又变成「检查器报违规」。

## 2. 每一步的候选集与判定

> 记号：`T_k(i) = 180 × r_i / k`；`K = SPEED_TIERS`；
> `K_ok(i) = {k ∈ K : 15 ≤ T_k(i) ≤ 345}`；`M = travel_min`（默认 20°）。

### 第 1 级 · 已有图形定义（多格整体对音）

**含义**：不逐格决策，而是让一段连续的按键整体套进一个**已有图形**。
本项目现成的「图形定义」有四种，**沿用现有优先级**（`core/solve.py` 里就是这么排的）：

| 图形      | 模块                                              | 对音方式                                        | 现状       |
| ------- | ----------------------------------------------- | ------------------------------------------- | -------- |
| 手写节奏型模板 | `core/templates.py` + `patterns/templates.json` | 模板自带逐格 travel，`match_dp` 用**时间戳窗口 DP** 全局对位 | ✅ 已实现，主力 |
| 自然闭合段   | `core/figures.py::nat_candidates`               | `travel = 180·r/k`，靠 `Σtravel` 自己复位，零 Twirl | ✅        |
| 三连音引擎   | `core/triplet_engine.py`                        | 恒定 travel + 块状 Twirl 掩码                     | ✅        |
| 魔法阵（雪花） | `core/snowflake.py`                             | 整朵 N 重对称，逐格解 `k = 180·r/travel` 做**绝对匀速**   | ✅        |

**放行条件**：图形存在 且 段内每格 `travel ∈ [M, 345]` 且 不跨 `Pause` 屏障 且
不与已锁定的段重叠 且 段长门槛满足（`natural_speed_min_tiles` 等既有闸）。

**结果**：整段写入，`i += 段长`，回到第 1 级。

### 第 2 级 · 当前半圈内找差一个「写法」的落点

**候选**：`C2(i) = {k = k_prev}` —— **不换档、不加事件**，就是第 1.2(A) 的那一个 `T`。
若 `T` 落在**内圈**（`T ≤ 180`）则本级的「180° 范围」就是这个内圈半圆；否则是外圈半圆。

**判定（逐条全过才放行）**

```
15 ≤ T ≤ 345              （不是回头方块）
T ≥ M                     （Q8 定稿：所有级都卡；雪花段与双押格豁免，见 §9.10）
T 不破坏 Σtravel 闭合      （对单格恒成立，无需检查；段级才需）
不落在锁定段 / Pause 屏障内
写法取 parity 不变的哪一种（Δa = +(180 − T)）
```

**评分（有多个候选时）**：直接复用 `core/figures.py::score` 的字典序
`(换档次数, −直线格数, Y<0, 自重叠对数, Twirl 数, −段长, |travel0 − prefer|)`。

**失败** ⇒ 第 3 级。

### 第 3 级 · 加一个旋转事件（Twirl），从另一个 180° 里找

**候选**：`C3(i) = C2(i)` 但**翻转 parity** ⇒ 写出来的 `Δa` 从 `+(180−T)` 换成 `−(180−T)`
（出射朝向关于当前朝向**镜像**，`docs/25` §1.2(D)），也就是「从新的 180° 找」。

**收益**：同一个 `T`，路径从「向一侧拐」变成「向另一侧拐」⇒
`Σtravel` 不变、时序不变，但**自重叠 / 走位方向完全不同**。
这正是 `core/straighten.py`、`twirl_mode=steer/alternate` 在做的事，
区别是**新阶梯要求在「逐音决策」阶段就把 Twirl 用掉**，而不是全部排完再回头补
（现在的 `_plan_twirls` 是后置全局 pass —— 这是本阶梯与现状最大的结构差别，见 §5）。

**判定**：同第 2 级的四条 + **本格不能同时是 SetSpeed 格**（社区硬规则；撞了就放弃本级）。

**失败** ⇒ 第 4 级。

### 第 4 级 · 先变速，然后回到 1 / 2 / 3

**候选**：`C4(i) = {k ∈ K_ok(i) \ {k_prev}}`，**按下面的顺序**逐个试（顺序必须钉死，否则不可复现）：

```
① 先试「沿用 k_prev」以外的、能给出直线（T ≡ 180）的最小 |log2 k| 档
② 再按 |log2(k / k_prev)| 从小到大（越少换档越好）
③ 同 |log2| 时优先 k < k_prev（提速档：把长音压回合法区间，也是现在 DP 的做法）
④ 同分时优先 T 落在内圈
```

对每个 `k`，**先把第 1 级重跑一遍**（用户明确说「然后 1 2 3」——换了档可能就有图形能套了），
不行再跑第 2、3 级。

**★ 用户补丁（原文最后一句）**

```
如果第 4 级选出来的 T < M（低于最小角度）
    ⇒ 不要用这个 k
    ⇒ 直接进入第 5 级（暂停节拍）
```

注意这是**短路到第 5 级**，不是「再试下一个档」。理由：变速让 `T` 变小正是「为了对音把角度
压小」的典型路径，而这恰好是用户要避免的观感问题（与 `docs/24` §5 的最小角度同源）。

> ✔ **已定稿（§9.0 Q3）**：**短路** —— `T < travel_min` 立刻进第 5 级，**不再试其余档位**。

**失败** ⇒ 第 5 级。

### 第 5 级 · 暂停节拍（兜底）

```
travel = 180（直线，1 拍）
pause_beats = r_i / k' − 1        k' = 沿用前一格的档（这时不用怕「缓速」，
                                  因为 Pause 会把时间补上）
若 r_i / k' − 1 < PAUSE_MIN_BEATS(0.25)  ⇒ 退回 k' = 1，pause = r_i − 1
```

即 `docs/24` §2 已经实现的 Pause 规则，**原样复用**（含 `PAUSE_MIN_BEATS` 那条）。

### 阶梯总览（伪代码）

```python
def place_note(i, ctx):
    # ── 1 已有图形定义 ─────────────────────────────────────────
    for fig in ctx.library_candidates(i):            # 模板 > 自然 > 引擎 > 雪花
        if fig.legal(ctx) and not fig.crosses_barrier(ctx):
            return Decision(kind="figure", fig=fig)
    k_prev = ctx.k_prev
    # ── 2 当前档、当前 parity ──────────────────────────────────
    d = try_single(i, k=k_prev, flip=False)
    if d: return d
    # ── 3 加 Twirl（翻 parity，写补角写法） ─────────────────────
    d = try_single(i, k=k_prev, flip=True)
    if d: return d
    # ── 4 变速后回到 1/2/3 ────────────────────────────────────
    for k in tier_order(i, k_prev):                  # 见 §2 第4级 的顺序
        T = 180 * ctx.r[i] / k
        if T < ctx.travel_min:                       # ★ 用户补丁
            break                                    #   ⇒ 直接落第 5 级
        if fig := ctx.library_match_at(i, k):
            return Decision(kind="figure", fig=fig)
        d = try_single(i, k=k, flip=False) or try_single(i, k=k, flip=True)
        if d: return d
    # ── 5 暂停节拍 ────────────────────────────────────────────
    return Decision(kind="pause", travel=180.0, k=ctx.pause_tier,
                    pause_beats=ctx.pause_for(i, ctx.pause_tier))
```

## 4. 候选之间的排序（必须钉死，否则不可复现）

复用 `core/figures.py::score` 的字典序，**原样不改**（用户已经在 `docs/` 里确认过这个顺序）：

```
① 换档次数少          ←「滥用速度会让手感非常差」
② 直线格多            ← 红色底线
③ Y ≥ 0（向上画）      ← 社区不约而同
④ 自重叠对数少
⑤ Twirl 图标少
⑥ 段更长、travel 更接近 prefer_travel
```

阶梯新增的部分只需要一条**级间**规则：

> **级号小的永远优先于级号大的**。即：宁可要「第 2 级的非直线」也不要「第 3 级的直线」，
> 宁可要「第 3 级」也不要「第 4 级的变速」。**级是硬序，评分只在同一级内部比较。**

这条是用户阶梯语义的直接翻译 —— 写成代码时别把级号和评分混进同一个 tuple 里排序，
否则第 4 级的「直线」会盖掉第 2 级的「非直线」，阶梯就白写了。

### 9.10 ★ Q8 定稿的展开（因为它牵动 `rules` 与雪花规划器两处）

用户口径：**最小角度对「所有级」生效，豁免只有两类 —— 双押 与 雪花。**

落实到代码，共**三处**口径必须一致（现在不一致，见下面的实测）：

| 地点                                             | 应该怎样                                                  | 现状                                     |
| ---------------------------------------------- | ----------------------------------------------------- | -------------------------------------- |
| `core/rules.py` ③b `travel_below_min`          | 排除 `dp_pole` **和**雪花格 `sno`                            | ⚠ **只排除了 `dp_pole`**：第 52 行算出了 `sno` 却没在 ③b 用 |
| `core/snowflake.py::plan/_valid` 的 `travel_min` | **雪花豁免** —— 规划器不许拿 `travel_min` 卡候选                    | ⚠ 目前 `solve` 把 `travel_min` 传了进去，是**硬闸** |
| 阶梯第 2 / 3 / 4 级的放行条件（§2）                       | `T ≥ travel_min`，但**雪花段与双押格豁免**                        | 待实现（P0/P1 要按这条写）                       |

**实测（`tools/_snow_travel_gate.py`，2026-10 新增，只读）**：

```
最小角度扫描（Automaton_Waltz，雪开 min4/full8）：
  travel_min   20.0°  雪花 144 格  雪花内 travel min 120.00°   规则 error {}
  travel_min   90.0°  雪花 144 格  雪花内 travel min 120.00°   规则 error {}
  travel_min  120.0°  雪花 144 格  雪花内 travel min 120.00°   规则 error {'travel_below_min': 1}
       低格 第446格 travel=45.000000°  雪花=否  双押=否      ← 报警来自**残余 DP 格**，不是雪花
  travel_min  150.0°  雪花   0 格                              ← 规划器拿 travel_min 卡掉整朵雪花
```

三条结论：

1. **雪花的 `travel` 天生很大**（实测最小 60°\~120°），所以在 UI 允许的
   `travel_min ∈ [0,120]` 区间内，**雪花永远不会撞闸** —— 缺豁免目前是**潜在**问题，不是现网故障。
2. `travel_min` 超过 ~120° 后 `rules` 报的 `travel_below_min` 全部来自**非雪花的残余格**
   （45° / 135°），说明"闸"真正卡住的是最后一公里，不是雪花。**别误判成雪花违规。**

### 10.3 ★★ 实测把原设计改掉的 **三处**（照 §2 旧文字写会踩坑）

**(1) 第 4 级不能用 `break` 短路，必须 `continue`（Q3 口径校正）**

§2 写的是「`T < travel_min` ⇒ **短路**到第 5 级」。按字面实现（`break`）之后，
Automaton 第 9 层凭空多 **121.622ms**，`verify_file` **FAIL**（最大误差 1 459 499µs）。

原因：`tier_order` 把「能给出直线」的档排第一，而 `r` 很小时（四分音符 `r=0.25`）
这个首选档是 `k=0.25`（`T=180`，**完全合法**）；但排在它后面的提速档 `k=2` 的
`T=9 < 20` 会**先**撞上 `break`。

⇒ 改成 `continue`：跳过这个档继续试，**所有档都给不出 ≥ `travel_min` 的角度才落第 5 级**。
这与用户原意「4 **产生的**角度低于最小角度就使用 5」等价（4 产生的角度永远不会低于闸），
而且不会自伤。§8.1 那条 `r=1.50, min=140° → 第 5 级` 的预期**仍然成立**（实测通过）。

**(2) 第 5 级在 `r < 1 拍` 时会写出「假的等待」**

第 5 级的形状是「`travel=180`（1 拍直线）+ Pause 补余下的时间」。
`pause = r/k − 1` 在 `r < 1` 时恒为负 ⇒ 被 `PAUSE_MIN_BEATS` 那条短路吃成 **0** ⇒
只剩一条 1 拍直线，这一格时长变成 `r` 的整数倍 —— 就是把 **(1)** 的 121.622ms 放大。
⇒ 加守卫：`pause_beats <= 0` 时**退回「不许暂停」的兜底**（老老实实按 `r` 画）。

**(3) 长休止必须在第 2/3/4 级**之前**拦下，直接进第 5 级**

不加这一步时，2 拍的休止会被第 4 级一个 `T=180` 的慢速档（`k=2`）**干净地吸收**掉 ——
几何合法、时长正确、零违规，但那正是用户 item ① 明确否掉的「**缓速爬过去**」。
实测 Automaton 的 Pause 从 321 掉到 **0**、直线率掉到 **41%**（低于 45% 红线）。

⇒ 按既有口径（`pause_min_beats`）先拦：`r > pause_min_beats` 且真有等待可放 ⇒ 第 5 级。

### 10.4 Q5 是怎么落地的

Q5-A 说「保留全局 DP，降级为第 4 级的档位排序器」。实际实现：

- `solve()` **仍然照常跑** `_dp_tiers` + `_merge_short_runs` 得到 `ks`，
  但把 `ks` **原样传给阶梯**，阶梯只用它喂第 1 级的图形扫描
  （`figures.choose` / `nat_candidates` 需要 `ks` 决定候选档）；
- 第 4 级自己用 `tier_order()`（§2 第 4 级①\~④的直译）排序，**不读 `ks`**。

也就是说 DP 的**排序准则**被抽成了 `tier_order`（保直线 → 少换档 → 优先提速 → 优先内圈），
而不是「每格去问 DP 要一个建议」。这一条与 Q5 的**意图**一致，但**实现方式不同**，记在这里备查。
