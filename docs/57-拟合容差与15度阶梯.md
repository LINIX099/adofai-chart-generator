# 57 · 拟合容差 + 使用激进的拟合策略（15° 阶梯）

> 用户 2026-10 原话：
>
> 「还有一个重要的东西也是非常需要的：我们需要**拟合容差**来尽可能的杀死抖动，**0~100**
>  按照**毫秒**输入和计算，拟合容差尽可能把**正负 0~100ms 的抖动修正至常规线**。
>  加一个 **使用激进的拟合策略**，其效果为：拟合的时候**最小角度为 15°**，也就是
>  **只允许 15 30 45 60 75 90……往后**。」

> 拍板（同日）：
> **Q1 = A**（`0` = 完全不修/保真，默认 **100** = 尽可能杀抖动）
> **Q2 = B**（严格「角度只出现 15° 的整数倍」）
> **Q3 = 只管直拟合**（最优化那条路不动一个字）

状态：**已实现（v0.4.5 之后的一轮，版本号沿用 0.4.5）**。

## 1. 两条口径（先说清楚，不然后面全是误会）

| 参数 | 取值 | 含义 |
| --- | --- | --- |
| **拟合容差** `fit_tol_ms` | **0~100 ms**，默认 **100** | **允许把点挪多远**。0 = 一个点都不挪（保真）；越大修得越狠。**超出容差的点原样保留并报出来**（不许静默、不许硬掰）。 |
| **使用激进的拟合策略** `aggressive_fit` | 勾/不勾，默认**不勾** | 只对**直拟合**有效。勾上 ⇒ ① 「最小角度」**钉死 15°**（后端强制，界面置灰显示 15）② 把「常规线」换成 **15° 阶梯**：非双押格的角度全部落在 `15 30 45 60 75 90 …`（15° 的整数倍）上。 |

★ **旧参数 `denoise_radius_ms`（吸附半径，0 = 全吸）已撤**：它的 `0` 是**最凶**的一档，
与「容差」的直觉正好相反（用户口径 `0` = 不修）。现在同一个量就叫 **拟合容差**：
`0` = 不挪，`>0` = 只修 ±容差 内的抖动。

## 2. 一个必须先讲明白的硬事实：**角度不是独立可选的**

一层的角度由它自己的时长和速度档唯一决定（`core/fitdirect.py` 的模型）：

```
travel = 180 × (该层时值 / 基准砖长) ÷ k        k = 速度档（2 的幂）
```

所以「只允许 15 30 45 60 …」**不能**靠「在角度表里挑一个」实现 —— 它等价于把**时值**
吸附到这一串格子上：

```
该层时值 = 基准砖长 × k / 12          （⇒ travel = 15° 的整数倍）
```

也就是说：**激进拟合必须动时间**（每个音最多动「拟合容差」那么多）。
这正是「拟合容差」存在的理由 —— 两条需求其实是**同一件事**的两面。

实现（`core/fitdirect.snap_to_ladder`）还有一条纪律：**误差不累积**。
它每一步都拿**原始时刻**当锚（`新时刻 = 上一新时刻 + 15° 的整数倍时值`，
且这一步的误差 ≤ 容差），而不是去吸「间隔」—— 吸间隔会让误差滚雪球
（每步错 5ms，一千个音就漂 5 秒）。

另外：**拆层也按整数个 15° 拆**。旧口径按 `travel/340` 等分，`345°` 会拆成
`175.5° + 175.5°`（不在阶梯上）；现在按整数单位分 ⇒ `180° + 165°`。

### 3.1 同一轮被 e2e 抓出来的两处「显示跟不上状态」

1. **依赖置灰过期**：`setControl()`（程序性写值的唯一入口）不刷新依赖置灰 ⇒
   「载入时间戳来源 ⇒ 求解方式自动切直拟合 ⇒ 激进拟合那框还是灰的」。已把
   `applyFitLock()`/`applyDpLock()` 挂进 `setControl()`。
2. **小窗「格子 ↔ 毫秒」只在播放时刷新** ⇒ 暂停时 / 刚载入 / 刚改 tbpm+N，
   它显示的都是旧格号。已改成：**每次重算后**刷一次、**`seek()` 定位后**刷一次；
   并把「播放头还在前奏」时的**负格号**夹成 `1`（加一句「尚未进谱」），
   不再显示「第 -3 格」。

## 4. 不许静默的账（全部上屏）

- 去噪那条：`… · 容差 {N}ms`；
- 容差不够时：`拟合容差 {N}ms：M 个点离格超过它，**原样保留**`；
- 激进模式：`★ 激进拟合：去噪只算网格不挪点（容差交给 15° 阶梯吸附）`；
- 阶梯那本账：`★ 15° 阶梯（容差 Nms）：修正 X 音 · 挪动 中位/max · 挪不动原样 Y 音 · 非阶梯格 Z 层`；
- `Z == 0` ⇒ `非双押格的角度全部落在 15 30 45 60 75 90……（15° 的整数倍）上`；
- `Z > 0` ⇒ `⚠ 仍有 Z 层不在 15° 的整数倍上（双押/中旋折返或长休止的 Pause 格；要更严就调大容差）`；
- 界面 ④b 那一行同步显示（`fitLadderText`）。

**为什么会有 Z > 0**（不是 bug）：双押薄格（15°/30°）与中旋折返格是**机制需要的形状**
（与「最小角度」的豁免同一条口径）；长休止的 Pause 格角度恒为 180°（在阶梯上），
但它只统计非双押格，所以正常应为 0。

## 5. 代价 / 注意事项（必须写给用户看）

1. **时间会被动**，每个音 ≤ 容差（合计不一定为 0，但不累积）；
2. 阶梯上的时刻是「基准砖长 / 12」的整数倍 ⇒ **不再落在 BDG 顶栏的 `1/2^k` 吸附格上**，
   投到编辑器时**别开吸附**（否则宿主会把它挪走）；
3. 只对**直拟合**有效；最优化那条路（模板/三连音/雪花）完全没动；
4. 默认**不勾** ⇒ 老口径逐字节不变（`golden` 不受影响）；
5. ★ **两条流水线的口径**（有意为之，不是 bug）：**导出的谱面 / 预览 / 视图**都走
   `Chart` 的层时间 = **吸附后**的时刻；而「投射到 BDG」推的是**我们的 outset 原始时刻**
   （BDG 那条路的真源是工程本身，`docs/45`）⇒ 两边最多差 **≤ 容差**，对账按 `adbIdx`
   标记走（不按时间），所以不会错位。若哪天要两边逐毫秒一致，做法是把吸附后的时刻
   **回写**到 `session.onsets`（像去噪那样就地替换）—— 现在**故意不做**，因为 BDG 那边
   用户还会自己编辑。
