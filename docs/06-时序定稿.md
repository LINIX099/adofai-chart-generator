## 一、我先用社区语料做了一次统计标定（不用下谱）

「offset 是谱师听音写的」+「优质谱会一直编到歌曲结尾」这两条合起来，
给了一个**只用音频时长就能验证**的判据：

```
offset + entryTime[最末层]  ==  最后一个方块命中时的音频时刻
若谱面编到结尾  =>  这个数应当 ≈ 音频总长
```

扫 `‹社区语料目录›\` 下 **151 个目录 / 468 组「谱面+音频」**：

```
命中(±20s)  120 / 468 = 26%      （其余是配对错了：一个目录里多张谱多个音频）
|误差| 中位 = 0.6 秒
有符号中位   = −0.1 秒            ← 几乎无偏
countdownTicks 众数 = 4  (464/468)
```

几条最干净的对照（误差 0.0s）：

| 曲目 | 谱 | bpm | cd | offset | 最末层 | 音频 | 误差 |
|---|---|---|---|---|---|---|---|
| ex | level1.adofai | 120 | 4 | 0 | 17.0s | 17.0s | 0.0 |
| ex | level2.adofai | 190 | 4 | 1260 | 20.8s | 22.1s | 0.0 |
| A PLUM RUSH | sub1.adofai | 100 | 4 | −13 | 25.2s | 25.0s | 0.2 |
| it go | sub4.adofai | 200.09 | 4 | 0 | 9.7s | 9.6s | 0.1 |

**结论：`offset (ms) = 谱面 entryTime[0] 对应的音频时刻。** 误差中位 0.6 秒，无系统性偏差。

> 我上一版把 offset 猜成「第一个方块命中的时刻」——错了。差的正是倒计时那一段。
> （我之前还试过用音频 onset 包络互相关去反推，提升只有 1.2~1.4 倍，
> 信噪比不够、我没敢用；现在这条路用不上它了。）

## 二、游戏时间模型（定稿）

```csharp
// scrLevelMaker.CalculateFloorEntryTimes
entryTime[0] = 0;
entryTime[1] = (countdownTicks−1) × 拍 + 第 0 层的角长时间;      // ← 倒计时只补在第 1 层
entryTime[j] = entryTime[j−1] + 第 (j−1) 层的角长时间;
```

**关键推论：行星开局是「停在第一格上」的，数完倒计时才第一次按。**
所以第 i 个音（onset i）对应的不是第 i 个方块，而是第 **i+1** 个方块：

```
第 i 次按下的音频时刻 = offset + entryTime[i+1]
```

⇒ **N 个 onset 需要 N+1 个方块**，多出来的那一个是最前面的「开局站位层」，不消耗按键。

## 三、生成器怎么落地（零误差）

直接反解出要满足的两条：

```
设 前置换入音频的静音为 S，引导层时长 lead
第 i 次按下 = offset + (cd−1)×拍 + lead + Σ_{j≤i} T_j
想让它 = 原始 onset 时刻 + S
=>  offset = onset₀ − (cd−1)×拍 − lead + S
```

取 **`S = (cd−1)×拍 + lead`**，就得到最省事的解：

```
前置静音  S = (countdownTicks−1) × 60000/基准BPM  +  引导层时长
offset   = 首个 onset 时刻
引导层   = 1 拍（travel 180°，直线，也是个好看的起手）
```

导出时 `core/synth.render(lead_ms=S)` 会自动在 wav 开头补 S 毫秒静音，
**倒计时就落在那段静音里**，游戏里听起来就是正常的"数拍子然后开始"。

### 实测验证

```
样本              cd   offset    前置静音   命中时刻误差   反解校验
Automaton_Waltz    4     649ms    2595ms    0.0 µs        OK (849 层, 0.0 µs)
FallenEra          4       0ms    4000ms    0.0 µs        OK (565 层, 0.0 µs)
MemoryLocked       4   71850ms    4800ms    0.0 µs        OK (195 层, 30 µs)
Automaton_Waltz    1     649ms     649ms    0.0 µs        OK
FallenEra          1       0ms    1000ms    0.0 µs        OK
```

「命中时刻误差」= 把 `offset + entryTime[i+1]` 反算出的音频时刻，跟原始 onset 逐音比对。
**cd=1 和 cd=4 都是 0.0 µs。**

另：`offset + entryTime[最末层]` 与「成品音频总长」的尾部余量是 +0.2s / +2.6s / +23.9s，
和上面统计标定用的是同一条判据，量级一致。

## 四、UI 变化

「⑤ 导出元信息」换成「**⑤ 时序 / 导出**」：

| 控件 | 默认 | 说明 |
