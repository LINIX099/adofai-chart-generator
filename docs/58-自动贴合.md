# 58 · 自动贴合（时值体检）：给「AI 扒的 / 抖动极大的」原始文件一键定参数

> 用户 2026-10 给了一份真文件（`mad_piano_party_timestamps.json`，130.5s 钢琴曲、3122 个音头），
> 说「**这是 AI 扒的，存在很大的抖动**」，并问：
> 「这个流程可以复用吗？再遇到这样的抖动极大的原始文件，有复用的可能性吗」
> ⇒ 拍板做 **B 档**（体检卡 + 一键套用），功能名 **「自动贴合」**。版本号 **0.4.6**。

---

## 1. 这份真文件教会我们的事（**全部实测**）

| 路 | 点 | `plan()` 自动认格 | 相对真砖长 90.909ms 的残差 中位 / p90 / max | ±25ms 能吸掉 |
| --- | --- | --- | --- | --- |
| melody（OnsetNet） | 1010 | ✗ `R=0.015 < 0.30` | **2.40 / 6.59 / 41.8 ms** | 97.5% |
| drums（频谱通量） | 523 | ✗ `R=0.048 < 0.30` | 7.55 / 20.6 / 41.5 ms | 94.6% |
| guitar | 585 | ✅ 但认成 **181.8ms**（错档） | 7.88 / 25.9 / 44.7 ms | 88.7% |
| piano | 985 | ✅ **90.909ms** | 5.89 / 18.1 / 45.4 ms | 95.9% |

三条结论（这就是「自动贴合」存在的理由）：

1. **抖动其实不大**（中位 2~8ms），真正的问题是 **`plan()` 认不出网格** ——
   于是「砖长」这一栏空着，出谱**整齐却不在音乐上**（实测踩拍率只有 **26.6%**；
   人工把砖长填成 90.909 后 ⇒ **100%**）。
2. **倍频陷阱**：能自动认出来的砖长里，**错的那一档（181.8 = 真砖长的 2 倍）看着也对**。
   选错档 → 踩拍率 31.7%。
3. 该填的不只是砖长：**容差**（跟着抖动量）、**去密**（跟着密度）、**要不要激进拟合**
   （跟着「直线率 / 15° 格率」）—— 这四个一起才对。

> ★ 一个副产发现：**「AI 扒的」不等于「抖得没法用」**。这份文件 97.5% 的点落在真砖长
> ±25ms 内；坏的是**估计器**，不是数据。所以体检的口气是「给提示」，不是「先洗数据」。

---

## 2. 判据（为什么这么选砖长）

**候选**（两族，可信度不同）：

- ① 每路 `plan()` 能认出来的砖长（及其 ×2 / ÷2）—— **经过精修的，优先信**；
- ② 每路各自的「相邻音间隔中位数」（及其 ×2 / ÷2）—— 只在①全不合格时才用。
  ★ 必须**按路分别取中位数**：把所有路混在一起取，会造出一个假的中位间隔
  （实测 34.8ms），把砖长带偏。

**判据**：**从最粗往细走，第一根「覆盖率 ≥ 85%」的砖长就是它**
（= 音乐上的「基本节奏单位 / 一条直线」）。

两个**必须**这么做的理由（都踩过）：

- 「覆盖率最高就选谁」会选到**最细**的砖：34.8ms 的格在 ±25ms 容差下**覆盖 100%**
  —— 判据退化成「越细越好」。所以覆盖率一律用**相对容差**：`min(容差, 砖长的 20%)`。
- 反过来「门槛从严到宽逐个试」又会先撞上细砖（45.45ms 也覆盖一切）⇒ 同样错。

**倍频陷阱**由第一族「最粗优先」自然解决：真文件里 181.8 的覆盖率只有 **0.58**
（解释不动「每 90.9ms 一个音」的旋律），90.909 是 **0.917** ⇒ 选 90.909。

**建议主轨**：在「能跟上砖长（覆盖 ≥ 90%）」的路里挑**点最多**的那条。
★ 不能只按覆盖率挑：鼓那类「点少、间隔大」的轨覆盖率常常略高一点点，
但它是节奏/伴奏轨，拿它当主轨出来的谱面又稀又散（实测踩拍只有 77%）。

## 3. 建议参数怎么来（**都靠试算，不靠拍脑袋**）

| 建议 | 依据 |
| --- | --- |
| `denoise_hint_ms`（砖长提示） | = 判据选出的砖长 |
| `fit_tol_ms`（拟合容差） | **最小的**那一档，使得全曲 ≥95% 的点落在砖长的 ±容差 内（档位 10/20/30/50/100） |
| `merge_ms`（去密） | **最小的**那一档，使得密度落进 3~6 层/秒（档位 0/30/60/90/120/150） |
| `aggressive_fit` | 对建议主轨**真试算两遍**（开 / 不开 `core.fitdirect` 的 15° 阶梯），比下面这个分 |
| `tracks_checked` | = 建议主轨（其余保持不勾） |
| `dp_checked` / `sub_checked` | **一律清空**。★ 有鼓轨时明确提醒「不建议自动当双押轨」——它是频谱通量扒的、多而抖，实测会插出 504 个双押 + 543 个发卡、直线率掉到 21% |

**「像人」打分**（写死并在此说明，避免黑箱）：

```
踩拍 30 · 直线 20 · 15° 格 15 · 密度 15 · 发卡 10 · 换档 10
```

★ **踩拍第一**：整齐但不踩拍的谱面是废的 —— 那份真文件就是这么被认出来的。

## 4. 落点

| 件 | 位置 |
| --- | --- |
| 体检纯函数（候选 / 覆盖率 / 残差 / 碎音 / 去密 / 试算 / 打分） | `core/tempo_diag.py` |
| `Session.tempo_diag(st)`（**只读**，不碰任何状态） | `sidecar/session.py` |
| `POST /api/tempo_diag` | `sidecar/server.py` |
| `api.tempoDiag(state)` | `app/renderer/api.js` |
| 左栏 ① 里的**「自动贴合」**卡 + 「按建议套用」 | `app/renderer/app.js`（`doTempoDiag` / `renderTempoDiag` / `doTempoApply`） |
| 夹具：**倍频陷阱**（真砖长 90.909、有一路会被认成 181.8） | `tests/fixtures/stemjson/octave_trap.json`（由 `tools/make_stemjson_fixtures.py` 生成） |

**口径（三条硬约束）**：

1. **体检本身一个参数都不改**（e2e 断言：点完「分析」后 state 逐字段不变）；
2. **不点「套用」就没有任何影响**（默认行为逐字节不变，`golden` 不受影响）；
3. **算不出来就说算不出来**：点数 <8、纯噪声、各路节奏互不相容 ⇒
   明确回 `ok:false` 或 `brick_reliable:false` + 人话说明，**不许编一个砖长**。

## 5. 验收

- `python tests\test_tempo_diag.py` —— **新套件 36 项**：
  A 干净数据（砖长对、不硬推激进）· B **倍频陷阱**（先断言前提「吉他确实被认成 181.8」，
  再断言选到 90.909）· C 抖动（容差跟着走、覆盖率单调、碎音计数、去密降密度）·
  D 退化（点太少 / 纯噪声 ⇒ 明确说「定不出来」）· E **真实文件**（在就给证据：认不出格的是
  melody/drums、砖长 90.909、直线率试算 1.3% → 90.4%；不在就跳过）· F 试算与打分方向。
- `python tests\test_sidecar.py` —— 新增 **[18c] 组**（12 项，HTTP 全链路）⇒ **294 passed / 0 failed**。
- `app/e2e.js` —— 新增一段（9 项）：卡片在 / **体检不改参数** / 结论是人话+数字 /
  认出 90.909 / 点套用才改参数 / 套用后能出谱且非阶梯格 0。
- 复验：`tests/test_*.py` 全绿（**33 套**）· e2e 全绿 · `python tools\pack_verify.py --flow` 全绿。

## 6. 明确不做

- ❌ **不在载入时自动改参数**（那是 C 档：会改变默认出谱，用户没点头）；
- ❌ 不自动勾双押轨（原因见 §3）；
- ❌ 不自动导出（体检只到「把参数摆好」这一步）。
