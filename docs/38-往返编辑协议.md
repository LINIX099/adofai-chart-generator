# 38 · 往返编辑协议（我们 ⇄ BDG）

> 用户 2026-10 定的预期流程：
> 「在我们的工具里面选择好音轨之后，**使用一个按键启动并把当前进度投射进编辑器**。
> 编辑器里面可以**预览**，并**修改或者删除具体的音**。再从编辑器把**进度重新返回**我们的工具。」
>
> 本文 = 这条闭环的协议。前置：`docs/35`（桥）/`docs/36`（软解析）/`docs/37`（v0.4 落地）。

***

## 0. 闭环一句话

```
   ┌── 我们 ──────────────────────────────┐        ┌── BDG 编辑器 ────────────────┐
   │ 选好音轨 → onsets（含角色）           │        │                              │
   │                                      │        │  预览（宿主自己的播放+波形）  │
   │  [投射到编辑器]  ────── import ──────►│───────►│  按角色建轨 · 每个音一个点     │
   │                                      │        │  改拍位 / 删音 / 拖动/加音     │
   │  [收回编辑器改动] ◄──── project ──────│◄───────│  （宿主每次改动自动推全量）    │
   │  = 对账：留下/移动/删除/新增/换角色    │        │                              │
   │  → 用**改过的** onsets 继续 solve()   │        │                              │
   └──────────────────────────────────────┘        └──────────────────────────────┘
```

**BDG 就是这块的编辑器**（`docs/34` 方案 C）；我们**不写自己的泳道 UI**。

## 1. 三条硬约束（都是宿主源码逼出来的）

| # | 约束 | 依据 |
|---|---|---|
| 1 | **回读必须对账**：`addMarker` / `moveMarker` 都走 `snapped()`，**吸附开着就会挪点** | `store.ts:317`；实测 1/4 档 866 点全被挪、最坏 37ms（`docs/35` §6.2） |
| 2 | **吸附关掉就无损**（`round(b*1e6)/1e6`，1e-6 拍 ≈ 0.3µs）⇒ 所以我们**报偏移**并提示用户关吸附，而不是偷偷接受 | `store.ts:315`；宿主顶栏那个「吸附」按钮（`ProjectBar.vue:401` `toggleSnap()`） |
| 3 | **`attrs` 是逐点唯一的自由字段**，且写入是**合并**（`{...cur, ...patch}`）⇒ 用它挂对账标记**不会**破坏宿主/别家插件的字段 | `plugin-api.d.ts` + `store.ts:updateMarkerAttrs` |

**我们没有**（也不打算要）的宿主能力：

- ❌ `moveMarker` 的 `force` 参数没暴露给插件（`api.ts:315` 直接转发）——
  **不去求他改**（用户口径：不往他那边作修改）；
- ❌ 插件 API 看不到 `snapEnabled` ⇒ 我们**用「读回来的 beat」反推偏移**，不需要知道它开没开。

## 2. 对账标记（写进 `marker.attrs`）

| 键 | 值 | 作用 |
|---|---|---|
| `adbIdx` | 我们的 onset 序号（整数） | ★ **身份**：回来时靠它对上；**没了 = 用户删了** |
| `adbRun` | 本次投送的批次号（如 `"20261012-235501-7f3a"`） | 区分「上一批残留」 |
| `adbRole` | 投送时它属于哪个角色（`main/sub/dp/off`） | ★ 用户把它**拖到别的轨** = 改角色 |
| `adbSrc` | 来源（`midi` / `audio` / `manual`，可选） | 溯源 |

⇒ 四种编辑全部可判：

| 用户干了什么 | 我们怎么看 |
|---|---|
| 什么都没动 | `adbIdx` 在、beat 一样、角色一样 ⇒ **留下** |
| 拖了拍位 | `adbIdx` 在、beat 变了 ⇒ **移动**（`drift` 记偏移） |
| 删了一个音 | `adbIdx` **不在**回来的集合里 ⇒ **删除** |
| 加了一个音 | 回来的点**没有 `adbIdx`** ⇒ **新增**（角色取它所在轨的角色） |
| 把音拖到另一条角色轨 | `adbIdx` 在、但所在轨的角色 ≠ `adbRole` ⇒ **换角色** |

## 3. 报文（在 `docs/35` §3.5 的信封上扩）

### 3.1 我们 → BDG：`import`（投射）

```jsonc
{
  "v": 1, "type": "import", "seq": 12, "ts": 1789...
  "run": "20261012-235501-7f3a",       // ★ 批次号，写进每个点的 attrs
  "base_bpm": 192.0,                     // 只用于自检（我们不改他的 baseBpm / bpmPoints！）
  "tracks": [
    { "role": "main", "name": "ADO·主轨", "clear": true,
      "onsets": [ {"idx": 0, "beat": 0.0064}, {"idx": 1, "beat": 1.0064} ] },
    { "role": "dp",   "name": "ADO·双押轨", "clear": true, "onsets": [ … ] }
  ]
}
```

- `clear: true` = 先清空这条角色轨上**我们上一批**的点（识别方式：`attrs.adbIdx` 存在）——
  **不碰**用户自己在这条轨上手动加的点（那些没有 `adbIdx`）；
- **不写 `bpmPoints` / `baseBpm` / `offsetMs`**（`docs/36` §11.4：动它 = 与音频脱钩）；
- 速度/双押那些**音乐内容**仍然由我们算，但**不进编辑器**（编辑器只管拍点与角色）——
  将来若要可视化，走插件自己的类型化轨，不碰宿主 BPM 轨。

### 3.2 BDG → 我们：写回回执（`ack` 扩展）

```jsonc
{
  "type": "ack", "ok": true,
  "run": "20261012-235501-7f3a",
  "n_tracks": 4, "n_placed": 866,
  "n_off_grid": 23,          // ★ 被吸附挪过的点数
  "drift_max_ms": 37.06,     // ★ 最大偏移
  "drift_over": 23,          // ★ 超过 25ms（Δ 预算）的个数
  "advice": "在 BDG 顶栏关掉「吸附」再投射，才能逐点无损"
}
```

**这条回执就是我们「不许静默」的落点**：面板上直接写
「已投射 866 点 / **23 点被吸附偏移，最大 37ms** —— 请关掉吸附重投」。

### 3.3 收回：`pull` → `project`（已实现）

宿主每次改动都会自动推 `project`（插件已去抖 300ms），所以「收回」= **用最近一次快照做对账**。
我们这边一个按钮即可（`POST /api/bridge/adopt`）。

## 4. 对账结果（我们侧的数据形状）

```jsonc
{
  "run": "…", "n_sent": 866, "n_back": 858,
  "kept": 800, "moved": 48, "deleted": 8, "added": 2, "role_changed": 1,
  "drift_max_ms": 37.06, "drift_over": 23,          // 超 Δ 预算的个数
  "snap_suspect": true,                              // 偏移形态像「吸附」（整档位对齐）
  "onsets": [ {"idx":0,"beat":0.0064,"role":"main","status":"kept"}, … ],
  "unmatched": [ … ]                                 // 上一批残留 / 无标记的点
}
```

- **`onsets` 就是「返回来的进度」** —— 直接喂给我们的 `solve()`（移动过用新 beat、删除的不在、新增的补 idx=null）；
- `snap_suspect` 判据：`moved` 的点**都落在同一档网格**上（`|beat·div − round| < 1e-9`）⇒ 就是吸附干的；
- `unmatched` **报出来**（可能是上一个批次没清干净，或用户在别的轨上手动加点）。

## 5. 我们这侧的按键（UI）

| 按钮 | 做什么 | 端点 |
|---|---|---|
| **投射到编辑器** | 把当前 onsets 按角色推过去 | `POST /api/bridge/import` |
| **收回编辑器改动** | 拿最近快照做对账，把结果并回当前进度 | `POST /api/bridge/adopt` |
| 状态行 | ●已连接 / 已投射 N 点 / 收回：留下 X 移动 Y 删除 Z 新增 W / 上次错误 | `GET /api/bridge?full=1` |

**前提**：BDG 那边装了 `bridge_plugin/`（`docs/37` §5.7），面板里连一次。

***

## 6. 不做什么（免得越界）

- ❌ 不改宿主的 `baseBpm` / `offsetMs` / `bpmPoints`（时间锚以他为准，只读）；
- ❌ 不动宿主源码、不加他的参数（要不来 `force` 就绕：**靠关吸附 + 回读对账**）；
- ❌ 不做「自动修复写入」（`docs/36` §10）：偏移只**报**，不偷偷改用户的拍位；
- ❌ 不在编辑器里表达「速度/双押几何」—— 那里只管**拍点 + 角色**，几何回我们这边算。

## 8. ★★ 真机验证（2026-10，宿主 `vendor/beat_data_generator` 真跑）

`python tools\_bdg_roundtrip_e2e.py`（宿主带 `--remote-debugging-port=9222`）：

```
① 投射（吸附**开**，即多数人的默认状态）
   回执: n_placed=6  n_cleared=5  n_off_grid=4  drift_max_ms=62.5  drift_over=3  n_skipped=1
② 点掉顶栏「节拍网格」再投
   回执: n_placed=7  n_cleared=6  n_off_grid=0  drift_max_ms=0     drift_over=0  n_skipped=0   ← ★ 逐点无损
③ 在编辑器里改：删 idx=4 / 把 idx=0 挪 +0.07 拍 / 手加 1 个无标记点
④ 收回
   {n_sent:7, n_back:7, kept:5, moved:1, deleted:1, added:1, drift_max_ms:35.0, snap_suspect:false}
   idx=0     ms=35.0    role=main  moved      ← 用户拖的（0.07 拍 @120bpm = 35ms）
   idx=1     ms=312.5   role=main  kept
   …
   idx=None  ms=2750.0  role=main  added      ← 用户手加的
```

### 真机抓出来的两件事（都不是设计里想到的）

1. ★ **吸附不只挪点，还会「吃掉音」**：`store.ts:669` `if (trackHasBeat(trackId, beat)) return null`
   —— 两个音被吸到**同一拍**时，第二个**被宿主直接拒收**。
   ① 的 `n_skipped=1` 就是它。⇒ 所以回执里 `n_skipped` 必须和 `n_off_grid` 一起报，
   **丢音比挪点更严重**（挪点还能对账回来，丢音只能靠 `deleted` 发现）。
2. ★ **「用户拖的」和「吸附挪的」能分开**：④ 的 `snap_suspect=false`，
   因为 0.07 拍**不对齐任何吸附档**；而 ① 的偏移全都对齐 1/4 网格。
   ⇒ 判据（`roundtrip._snap_suspect`）是有效的：**能区分「该关吸附」和「用户就是这么拖的」**，
   两种情况的处置完全不同（前者提示关吸附重投，后者必须尊重用户的意图）。

## 9. `.bdg` 当**生成源**（`core/bdg/source.py`）

> 用户 2026-10：「是不是理论上可以使用已有的 bdg 文件作为生成源？」
> + 「1 音，大部分情况下当音」/「2 展示为音轨，让用户自己选择它做什么」

### 9.1 为什么能：**同一个 `parse()`，同一把时间锚**

| | |
|---|---|
| 文件 vs 面板 | `.bdg` 文件与插件快照走**同一个 `core.bdg.parse()`**（`docs/36` §9），只是来源不同 |
| beat ⇄ ms | 用**他自己的** `baseBpm/offsetMs/bpmPoints`（**只读**）；实测与他的 `tempo.ts` **逐点 0.000e+00 ms** |
| ⇒ | 文件里的拍位能**精确**还原成毫秒 ⇒ 当源是可靠的 |

### 9.2 怎么接：**把它做成一种 `MidiFile`**（所以下游一行都不用改）

```
.bdg ──parse──► Project ──source.to_midi_like──► MidiFile（每条 BDG 轨 = 一条音轨）
                                                    │
                    用户在**现有的**「主轨多选 / 次级轨 / 双押轨」UI 里勾（答案 2）
                                                    ▼
                          onsets.build_onsets_multi(...) ──► solve() ──► .adofai
```

- ★ **角色不由我们猜**：`role_hints()` 只给**建议** —— 插件角色轨 / `hidden` / 别家 typed 轨 → `off`；
  **普通踩点轨留空**，让用户在三条列表里勾（这就是「让用户自己选择它做什么」）。
- 音长：BDG 只有拍位 ⇒ **零长音**（`t_off_ms == t_on_ms`），**不假装**有 dur；
- `channel = 0` ⇒ `is_drum_only()` 为 False，列表里显示「旋律」而不是「架子鼓」；
- `bpm0` 取他的 `baseBpm`；**他的变速不写进 `tempo_map`**（音乐内容以我们为准）。

实测（真实工程 866 点 / 6 轨）：

```
MidiFile: ppqn=960 bpm0=192.0 tracks=6 length=133670.75ms
每轨点数 [413, 231, 29, 191, 2, 0]
勾前 4 条当主轨 → build_onsets_multi → 629 个 onset（多轨同刻合并）
只勾第 3 条轨   → 29 个 onset          ← 勾不同轨结果不同 ⇒ 用户的选择真的有效
```

### 9.3 「结合」他的变速（答案 3）：**能落进合法档就采，落不进就报**

我们的 SetSpeed 必须是 **2 的幂档**、且落在 `travel=180` 的平格上；他的变速在
**插件 BPM 轨**的 `attrs` 上（宿主 `bpmPoints` 是空转的 no-op）。所以「结合」的口径：

| 他的倍率 | 我们怎么办 |
|---|---|
| 是 2 的幂（`×2` / `×0.5`…） | **可以直接采纳**当目标档（他对着波形标的，比我们纯算的贴音乐） |
| 不是（如 `×1.7`） | **给最近的合法档 + 偏差百分比，并报出来**（不许静默、更不许照抄） |

`source.ladder_fit()` 就是这笔账。实测这份工程：**3 个变速点全部精确落在合法档上（偏差 0%）** ——
他用的 `multiplier 2` 正好是我们的档位。

> 落地顺序建议：**先只报（现在就能跑）→ 再作为「软约束/打分项」接进 `solve` 的选档**，
> 而不是当成硬性速度表（硬性会跟我们「落平格」的不变量打架）。

### 9.4 loop 子点算不算独立音（答案 4）

**算。** 三条依据：

1. **数据上它已经在那儿了**：他不是只存一个「循环」标记 —— `refreshChildren` **真的把每个子点建成了
   独立 marker**（带 `parentId`）。实测 92 个母点 → 391 个子点，`子点数 = count − 排除数` 92/92 全对。
   我们的 `expand` 默认**只补缺**，这份工程补出 **0 个**（全都在）⇒ **不会重复**。
2. **音乐上它就是要踩的音**：它画在时间轴上、播放会响。丢掉它 = 丢音。
3. ★ **量级**：这份工程 864 个 onset 里有 **391 个（45%）来自循环子点** ——
   把它们当「只是母点的附属」直接丢掉，等于**丢掉近一半的音**。

⇒ 默认：子点**算独立音**，`parentId` 只留作溯源；
真要「只留母点（把循环当节拍参考线）」的话给一个**开关**，但**不是默认**。

### 9.5 于是四种来源统一了

```
来源： MIDI 轨 │ 音频检测（xk base）│ **BDG 工程(.bdg / 桥快照)** │ 手工点
                       ↓ 都变成「音轨列表」
角色： 主 / 次 / 双押 / 关   ← 用户在现有三条列表里勾
                       ↓ onsets
                 solve()（BPM 表 · 双押 · 预留槽位 · Δ 预算）→ .adofai
```

- 状态走**同一条 SSE**（`kind: "bridge"`），不轮询；连接串可一键复制；
- **没连上时按「投射」会明确报错**，不静默、不崩（e2e 有断言）。

### 10.4 ★ 角色轨的第三个用途：**分段采音**

前面 §3.6 说 `track.type` 只用来承载**角色**。现在，角色轨上的**点**
也被用起来了 —— 每个点是一句「**从这一刻起，这条轨是什么角色**」：

```
BDG 里                     我们的工具里
─────────────────────      ─────────────────────────────────────
[主轨]轨  ·  ·  ·    →   「从 BDG 角色轨生成」→  分段采音（docs/39）
```

- 实现：`Bridge.role_points()` → `core.segments.from_roles()` → `state.segments`；
- 界面：② 音轨 →「分段采音」→ `从 BDG 角色轨生成`（`POST /api/bridge/segments`）；
- ★ **只认我们插件的角色轨**（`parse.role_track_role()` = `<pluginId>:<main|sub|dp|off>`）：
  **内置踩点轨不算**（项目里每条普通轨都是内置轨，拿它当指令会让每条轨凭空
  多出一批分段），**宿主 `bpm/twirl` 控制轨也不算**（那上面是**变速**，不是角色）；
- 语义是**累计快照**：后面没再出现的轨保持上一次的角色；只有**出现过**的维度才
  写成显式（其余留 `null` = 继续继承全局 ②）；净效果没变的点会被省掉；
- 生成的是 **`from`（从这点起）** 模式。想用「到这点为止」在面板下拉框里换。
