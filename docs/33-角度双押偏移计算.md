# 33 · 角度双押的偏移：算一下

> 用户 2026-10：「**理论上：角度双押 绝对存在偏移的。我们算一下**」
>
> **用户是对的。** 我上一轮说的「角度双押精确 0」只在**一个**口径下成立
> （主音 onset 的映射 / 整条谱面的净时长），**双押这一对内部**必然偏 ——
> 见 §2。算账工具：`tools/_dp_skew_calc.py`。

***

## 1. 先把两个「偏移」分开，别混

| 口径 | 角度双押 | 说明 |
|---|---|---|
| **A. 整条谱面的净时长** | **恒为 0** | 拆法 `[θ, T−θ]` 的 `Σtravel` 守恒 ⇒ 后面所有格一格不动 |
| **B. 主音 onset 的按下时刻** | **恒为 0** | `dp_old2new` 指薄格，薄格 entry = 原格起点（`tools/_dp_offset_audit.py` 实测 ±0.000ms） |
| **C. ★ 双押这一对** | **Δ = θ·m ≠ 0** | **一格只有一个 entry** ⇒ 两下必然错开 |

上一轮我只报了 A 和 B，说「精确 0」；**C 才是用户说的那个**。

***

## 2. 公式

设有效 BPM = `b`：

```
1 拍    B = 60000 / b                [ms]
每 1°    m = B / 180 = 60000 / (180·b)   [ms/度]
```

`dp_angle` 把一格 `travel = T` 拆成 `[θ, T−θ]`（**薄格在前**）。
「一格按下 = 该格的 entry」，于是这一对的两个音头是：

```
薄格 entry = t_k               ← 与原格起点重合（这就是 A/B 两个「0」的来源）
剩格 entry = t_k + θ·m
```

┌──────────────────────────────────────────────────────────────────┐
│ **★ Δ = θ·m = (θ/180) · B = (θ/180) · (60000 / cbpm)**          │
└──────────────────────────────────────────────────────────────────┘

**Δ ≠ 0 是几何上必然的**：一格只有**一个** entry，想让两下都落在同一个 `T` 上，
那就成了同一格 —— 所以必须劈开。能不能玩，只取决于 **Δ 是否落在同一判定窗口内**。

这正是用户口径「**斜向单元一般 360cbpm 以上就可以用**」的来源：
θ=30°、360cbpm ⇒ Δ = 27.8ms。

**Δ 不累积**（每个双押各偏各的，`Σtravel` 守恒）⇒
`docs/16` 那套「累计超 20ms → angleOffset/Pause 回正」**依然不需要启用**。
Δ 是**对内偏斜**，不是**时间轴漂移**，那套公式管不了它（也正因如此我才误判成 0）。

***

## 4. ★ 顺手发现的一个真问题：`choose_thin` 在 300cbpm 处**反向跳变**

当前口径：`cbpm < 300 → θ = 15°`，`≥ 300 → θ = 30°`。代入 Δ：

| cbpm | B(ms) | 自动 θ | **Δ** |
|---|---|---|---|
| 250 | 240 | 15° | 20.0ms |
| **300** | 200 | **30°** | **33.3ms** ← 比 250 还差！ |
| 360 | 167 | 30° | 27.8ms |
| 400 | 150 | 30° | 25.0ms |
| 500 | 120 | 30° | 20.0ms |

**速度越快，θ 反而翻倍，Δ 先恶化再改善** —— 300~400cbpm 这一带是整条曲线最差的地方，
而它恰好就是用户说的「360cbpm 以上才用」的边界附近。

***

## 5. 两个可选修法

### 选项 ①：θ 按 **Δ 预算**选，而不是按固定两档

```
θ_max(cbpm, 目标Δ) = 目标Δ × 180 × cbpm / 60000
θ = min(θ_max, 60°)     再吸附到 {15, 30, 60} 或直接取连续值
```

想让 Δ ≤ 20ms：250cbpm 以上都行（此时 θ 恰好 ≥ 15）；
300cbpm 应取 θ=15° 而不是 30°。**改动一行**，只动 `choose_thin`。

### 选项 ②：**对称写法** —— 把 θ 劈开跨过格界

```
前一格  P → P − θ/2          结束于 t_k − Δ/2
新 格  (无) → θ              entry t_k − Δ/2   ← 第一下
本 格  T → T − θ/2           entry t_k + Δ/2   ← 第二下
────────────────────────────────────────────
Σtravel 不变 ⇒ 净时长仍然精确 0
两下 = [t_k − Δ/2, t_k + Δ/2]  ⇒ **最大偏差从 |Δ| 降到 |Δ/2|（免费减半）**
```

| cbpm | θ | 当前 Δ | 对称后 ±Δ/2 |
|---|---|---|---|
| 125 | 15° | 40.0 | **20.0** |
| 180 | 15° | 27.8 | **13.9** |
| 250 | 15° | 20.0 | **10.0** |
| 300 | 30° | 33.3 | **16.7** |
| 360 | 30° | 27.8 | **13.9** |
| 1000 | 30° | 10.0 | **5.0** |

代价：多一格；前一格被削掉 θ/2（要保证它本身不是薄格 / 剩余格 —— 连押时要处理嵌套）。
**参考谱用的是「选项 ① 的一侧」写法**（`双押交互` 两下 = `[0, +10ms]`，不是 `[−5, +5]`），
所以选项 ② 会**偏离参考谱的写法**，但两下的最大偏差减半。

## 6. ✅ 已实施：**所有 bpm 下 Δ ≤ 25ms**（用户拍板）

用户口径 2026-10：「**力求 所有bpm下的双押产生的偏移时值降低到 25ms 以内**」。

### 6.1 口径

```
Δ = (θ / 180) × (60000 / bpm)           ⇒   θ ≤ Δ预算 × 180 × bpm / 60000
```

- `core/dp_angle.SKEW_MAX_MS = 25.0`（新参数 `SolveParams.dp_skew_max_ms`，
  UI ② 主轨分区「**偏移预算**」，`0` = 关掉预算退回固定 15°/30°）
- `choose_thin(bpm, skew_max_ms)`：在候选阶梯里挑**最大的、且 Δ 不超预算**的那一档

```
THIN_LADDER = (60, 45, 30, 22.5, 15, 12, 9, 7.5, 6, 4.5, 3, 2, 1.5, 1, 0.75, 0.5)
```

**★ 必须用「这一格自己的 bpm」**（`Floor.bpm = base_bpm / k`）—— 慢速档会把 Δ
放大 k 倍。以前用的是整谱 `base_bpm`，所以在慢速格上预算一直是假的。

### 6.3 配套的两处护栏

1. **θ < 15° 时退回「正常写法」**（`REVERSE_MIN_THETA`）：
   反向写法的**原始** travel 是 `360 − θ`，θ<15 会让它 > 345°，落在项目自己的
   「回头方块」区间里 ⇒ 那种情况改直写 `[θ, T−θ]`（计数 `fallback_normal`）。
2. **薄格豁免 `MIN_TRAVEL`**：`stats().bad_travel` 现在只卡**剩余格**
   （薄格就是要小，否则低 bpm 压不进预算）。

### 6.4 顺手抓到的一个 `a`（预留槽位）的 bug

压测样例 `all_Automaton_Waltz` 暴露出：预留槽位沿用上一格的档时，只检查了
`TRAVEL_HARD_MIN(2°)`，**没检查用户的「最小角度」**（默认 20°）⇒ 预留出来的那一格
自己成了 `travel=11.25°` 的违规格（`rules` 报 `turnaround` + `travel_below_min`）。
已加守卫：`max(TRAVEL_HARD_MIN, travel_min) ≤ travel ≤ TRAVEL_HARD_MAX`。
