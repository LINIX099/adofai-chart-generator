> - **`双押交互.adofai`**（bpm 250，101 格，单一 `SetSpeed ×4`，无注释）

>
> 1. **「中旋的双押是不用改的，就这样就行」** ⇒ 参考谱里的写法是给**角度双押**用的，
>    `dp_midspin` 的三格写法（`0.2 / 0.0 / 179.8`）**保持不动**。

> 3. 斜向单元 `30, 150, 330, 210` **一般 360cbpm 以上就可以用**，

>    砍掉几个成对的部分就能写 4 连 / 8 连*。
> 5. `双押交互.adofai` = **角度双押在满直线下的一般写法**（每 4 拍一个双押）。
> 6. **架构质疑**（见 §4）：求解器一轮定结果、不回头改。

## 2. 参考谱 B `双押交互.adofai`（角度双押 · 满直线）

> ⚠ **本节已按奇偶还原修正**（见 `docs/31` §2.2.1）。原来的解码直接用文件里的
> `angleData` 差分算 travel，**漏了 Twirl 的累积奇偶**，于是把反向编码的补角
> 当成了真角度，得出「第二组双押 = 3 拍」的错误结论。

101 格，全程 `SetSpeed ×4`（有效 1000 BPM），无注释。**有效重复单元 5 格**：

```
有效 travel: 30, 150, 180, 180, 180        （Σ = 720 = 4 拍 ✓）
文件 raw   : 330, 210, 180, 180, 180 → 30, 150, 180, 180, 180   ← 每单元变一次写法
dt(ms)     : 10,  50,  60,  60,  60
```

- 全程 100 格 = 20 个单元，**完全同构**；
- `Twirl` 每 5 格一个（第 6、11、16… 格）⇒ **奇偶每单元翻一次**，
  于是相邻单元交替使用正常 / 反向编码 —— 这就是用户说的「**为了不叠起来**」；
- 双押 = 单元开头 `30 → 150` 那一对（两下相差 **10ms**），
  `30 + 150 = 180° = 1 拍` = **和单个格子等时值** ✓；
- 用户口径：**每 4 拍一个双押** ✓（单元 = 4 拍）。

## 3. 我提炼出的规则（举一反三）

> ★ **统一公式**（奇偶还原后，`docs/31` §2.2.2 定稿）：
>
> ```
> 一个双押 = 两格 [θ, 180·W − θ]        θ = 薄角，W = 这个双押占几拍
> ```
>
> 塔 / 斜向 / 交互 / 强弱**全都是它**，只差 `W` 和「上下文里垫几个 `180`」。

### 3.1 双押塔 = `W = 2`：一对 `θ / (360 − θ)`，**自闭合**

```
30 + 330 = 360 = 2 × 180
```

- **两格一对**，第二至约 **20ms**（`30° @ 有效 500BPM`）；
- 没有间隔，塔本身就是循环（「多次循环，中间带有间隔」）；
- `θ` 可替换（段 D 里出现过 60°）。

### 3.2 斜向单元 = `W = 1` **背靠背**（→ 高速长连，**≥360cbpm**）

```
有效: 30, 150, 30, 150        Σ = 360 = 2 拍
文件: 30, 150, 330, 210       （同一对、交替写法 ⇒ 不叠）
```

即「薄格 → 斜着推进 → 回位 → 斜着回来」。**不要原地连抖**，让路径沿斜线走。
用户口径：这是「**非常好用的连续双押手段**」。

### 3.3 交互 / 强弱：`W = 1` 或 `0.5` + 垫平格

- **交互**（`双押交互`）：`W=1`、`spacing=4` ⇒ `[30,150] + 180,180,180`，**每 4 拍一个**；
- **强弱强**：`W=0.5` ⇒ `[30, 60]`；
- **5 连**：`spacing=0.5` 连放 9 对。

**用户口径**：这是**举一反三**的提示 —— *能写 5 连就能写 10 连；
砍掉几个成对的部分就能写 4 连 / 8 连*。
⇒ 所以实现上应当是**「连数 N 决定重复几次单元」**的**参数化生成**，
而不是给 4/5/8/10 各写一份模板。

### 3.4 速度规则（两条硬约束）

> ★★★ **2026-10 用户更正**：下面第 1 条被我们**误读成全局规矩**。用户原话：
> 「这个是**针对于双押的**，大多数时候不适用。完整的说法：**（当双押使用变速）
> 调速必须不和旋转重叠，必须位于双押的第一格**。」
> ⇒ 正确版 = **不与 Twirl 同格（`rules.py` ①）+ 落在双押第一格**；
> 不是「必须落在 180 平格上」。详见 `docs/49` §9.4 / `docs/31` §5.2.2。原文保留：

1. **调速（SetSpeed）必须落在 `travel = 180` 的平格上**，否则判定不合规；
2. **要调速就提前调好**，不能在双押段中间临时调。

## 4. ★ 架构质疑：求解器一轮定结果、不回头改

用户原话：「**求解器目前是单次生成定结果？这是否……指望程序一轮抽卡只出、不回头改，
可能会有大问题吧**」

**先把现状说准（比用户担心的要好一点，但确有硬伤）**：

| 环节 | 现在是不是「前向贪心、不回头」 |
|---|---|
| 基准 BPM | 全局遍历候选再打分 —— **是全局的** |
| 速度档 `_dp_tiers` | **全局 DP**（整条序列一起解）—— 不是贪心 |
| 模板 `match_dp` | 时间戳窗口 DP —— 近似全局 |
| 自然段 / 引擎 / 雪花 | **前向贪心**（`figures.choose` 走一遍 `Walk`） |
| **对音阶梯 `aggressive_pick`** | ★ **纯逐音贪心**（`docs/25` §9.0 Q9-A「先纯贪心」） |
| **双押插入 `dp_midspin` / `dp_angle`** | ★ **纯后置**，改不了已经定死的几何与 SetSpeed |

**三条硬伤**（都是「不回头」直接造成的）：

1. **角度双押在满直线谱上静默失效**：`dp_angle` 跑在 `solve()` 之后，
   目标格被图形（自然段）拥有就 `continue`，实测 `owned == dp_onsets`，
   **一格都插不进去，半边音直接丢，还不报错**。
2. **「调速落在 180 平格上」做不到**：SetSpeed 位置在插入时早已定死。
3. **阶梯把坏决定一路带到底**：第 i 格为了对音换了个档，后面 20 格跟着歪，没有回退。

**可选方案**（我倾向 a + b，c 作为可选增强）：

| | 方案 | 说明 | 代价 |
|---|---|---|---|
| **a** | **预留槽位**（pre-reserve） | 求解**开始前**就把「这些 onset 要出双押、连数 N、用塔还是斜向」作为**输入**交给 `solve()`，让图形/DP 在那些格上**主动让位**并按人类形状预留 travel | 要在 `solve()` 里加一层「双押需求」；改动面最大，但**唯一能真正满足 §3.4 两条硬约束**的做法 |
| **b** | **后置插入 + 局部重排** | 撞到 `owned` 时不丢弃，在 ±K 格窗口内做局部 DP 重排（把闭合段拆开再重新闭合） | 中等；能救回「静默失效」，但改不了 SetSpeed 位置 |
| **c** | **多轮抽卡** | 换种子/参数跑 N 轮，按指标（直线率、双押命中率、偏轴…）选最好的一轮 | 最省事；**只是缓解**，不解决耦合，且与「确定性可复现」冲突（现在整套测试都靠可复现） |

> 我的建议：**a 是正解**（把双押当成求解的**约束**而不是事后补丁），
> **b 做兜底**（防止静默丢音），**c 只在用户显式要多试几轮时开**，并且固定种子保证可复现。
