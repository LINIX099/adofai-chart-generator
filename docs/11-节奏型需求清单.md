## 一、记谱约定（关键：X 和角度一一对应）

```
1 个字符 = 15° = 1/12 拍          （一拍 = 12 个字符）
X        = 按一下
空格 / · = 空拍
```

因为 `travel = 180° × 音值 × 速度档`，而在 **speed 1** 下：

| 音值（拍） | travel | 乐理名 |
|---|---|---|
| 1 | 180° | 四分 |
| 1/2 | 90° | 八分 |
| 1/4 | 45° | 十六分 |
| 1/3 | 60° | 八分三连 |
| 1/6 | 30° | 十六分三连 |
| 1/12 | 15° | 三十二分三连 |
| 3/4 | 135° | 附点八分 |
| 3/2 | 270° | 附点四分 |
| 5/6 | 150° | — |
| 7/6 | 210° | — |
| 11/6 | 330° | — |

**两个 X 之间隔 k 个字符 → 这一格 travel = k × 15°。**

## 四、我要的 `.adofai` 格式

1. **一个节奏型一张谱**，文件名 = 编号，例如 `patterns/E1_30-150.adofai`
2. `settings.bpm` 固定写 **120**（好读；我按比例缩放）
3. **不写 SetSpeed**（全 speed 1）。除非这个节奏型非换档不可 —— 那就另存一份
4. `angleData[0] = 0`（起点必须是直线）
5. 一个 cell 摆完，**末尾留一格 180° 收尾**，我靠它判断边界
6. **Twirl 你来摆** —— 这是模板里唯一需要设计的东西
   （同一个节奏型有几种经典摆法，就存几份，文件名加 `_tw1` / `_tw2`）

> 参考格式见你自己那份 `samples/三种三连音写法.adofai`（`EditorComment` 标名字那套）。

## 五、可选：先摆骨架再摆 Twirl

## 7.5 ⭐ 模板的第三个维度：`PositionTrack`

**用户原话**：「变体写法是在第二轮的格子加位置轨道事件。你去看事件那边」

反解 `F_三连家族_待定.adofai` 的 events（`tools/read_patterns.py` 已升级支持），
F07 段（floor 27，travel `60`×6）里多了 3 个手工 `PositionTrack`：

```
floor 27  整轨  +(+3.00,+0.00)                    ← 生成器加的（整段错开）
floor 30  单格  +(+0.50,-0.50)  基准 (0.00,0.00)  ← ★ 手改
floor 31  单格  +(+0.00,+0.50)  基准 (0.00,1.00)  ← ★ 手改
floor 32  整轨  +(-0.50,-0.50)  基准 (0.87,0.50)  ← ★ 手改（此后整轨也被平移）
```

**结论：模板数据结构要从 `{travel, Twirl}` 扩成 `{travel, Twirl, PositionTrack}`。**

```json
{"floor": 30, "eventType": "PositionTrack",
 "positionOffset": [0.5, -0.5],
 "relativeTo": [0, "ThisTile"],
 "justThisTile": true,
 "editorOnly": false}
```

- `justThisTile: true`  → 只挪这一格
- `justThisTile: false` → 从这一格起后面全部平移，**会累加**
- 偏移可以是**半格**（`0.5`），不是整数

这也解释了之前那条重叠规则：**「只要重叠的块在 2~4 拍以外就可以设置轨道特效来规避」**
—— 轨道特效能改单格视觉位置，所以是「变形」和「避重叠」的同一个工具。

# 十、⭐ Twirl 的判据：该快没快就 Twirl

**用户原话**：「所以 只要它在自己该快的时候没有快，就该 twirl 了」

## 10.1 原理

`travel = GetAngleMoved(entry, exit, isCCW)` —— **Twirl 把 travel 从 `θ` 翻成 `360−θ`**，
所以 Twirl **同时改时值**（不只是改转向）。

```
一格只有两个可取值：  θ   和   360 − θ        ← Twirl 切换
θ > 180°  →  走的是「慢的那一支」
θ < 180°  →  走的是「快的那一支」
```

**判据：算出 ms，哪一格该快却没快 → 给那一格加 Twirl。**

## 10.2 这正好解释了 F02

`F02 = 300 · 300 · 300`（`bpm=120`）：

| | travel | ms |
|---|---|---|
| 原样 | `300°` | 833 ms（巨慢） |
| **加 Twirl** | `60°` | **167 ms（快）** |

用户早先说「F2 一般情况下在第一格会有旋转事件，除非确定了它就是走外圈的」
—— 原因就是：`300·300·300` 是**慢的那一支**，必须靠 Twirl 翻成 `60·60·60` 才快。

## 10.4 对生成器的影响

**不能只为「朝向规划」挑 Twirl，必须每格按目标时值挑 `θ` 还是 `360−θ`。**

这也统一了之前几条分散的说法：
- 「F02 第一格一般有旋转事件」→ 10.2
- 「朝向规划」→ 就是同一批 Twirl 的自由度
- 模板的 `{travel, Twirl}` 里，**Twirl 决定了这一格是快支还是慢支**
