# 20 · UI 布局整理 · 全曲预览条 · 区间采音

> 用户口径：①「改一下 UI 的布局，让它更整洁一些」②「增加一个预览全曲（从左到右可以
> 滑动的预览）」③「对于某一段框出来，使用不一样的音轨采音」。
> 前置：`docs/19`（Electron 重写）。本篇记录这三件事的实现与验收。

---

## 1. 布局整理

原来一屏里塞了：5 个分区（全展开，纵向一条长滚动）＋ 页签行 ＋ 视图控制条 ＋
播放条 ＋ 3 行常驻状态。改成：

| 改动 | 做法 | 效果 |
|---|---|---|
| **分区可折叠** | 分区标题变成开关（▾/▸），**③ 采音 / ④ 求解默认收起**，① 文件 / ② 音轨 / ⑤ 时序默认展开 | 首屏只剩真正常用的东西；参数还在，点一下就有 |
| **状态区分层** | 只留一行状态 + 一个可展开的 `▸ 时序 / 警告`（带警告计数徽标，有警告自动展开） | 底部从 3 行常驻降到 1 行 |
| **全曲预览条**（新） | 单独一条 76px 横条（见 §2） | 取代"没有全局视角"这件事 |
| **页签提示/音频路径省略** | `#tab-hint` 限宽 42% + 省略号；播放条只显示音频**文件名**（完整路径进 title） | 长路径不再顶变形；文字不再被裁一半 |
| **轨道列表文字省略** | `.list .t` 单行省略号 | 长轨名/统计不再撑破面板 |
| **长路径换行** | `.info{overflow-wrap:anywhere}` | 文件信息里的绝对路径不再溢出被裁 |
| **下落式轨道不再拉长条** | 单轨最宽 **150px** 并整体居中（旧 UI 是 `laneW = w/lanes`，宽窗口下单轨 286px，音符变长条） | e2e 实测：边距 272/273（居中）、单轨 150px |

**布局体检进回归**（`app/e2e.js` §13/§14，用几何量代替肉眼）：
页面横向溢出 = 0、无文本被截断、无控件被压扁、面板内元素不越过右边界、
主画布区仍有 ≥300px 高（实测 615）、全曲条高 76px、5 个分区都在、展开后可见控件 ≥60（实测 179）。
文本截断用 `Range.getBoundingClientRect()` 量**文本真实宽度**（行内元素的
`clientWidth` 恒为 0，只看它必然漏检）。

## 2. 全曲预览条（`app/renderer/views/overview.js`）

一条 1124×76 的横条，从上到下：

```
时间刻度（自动选步长：0.5s…5min，按 span/8 取整档）
选中格高亮 + 左侧绿线 + 顶部小三角 + 格号（见 docs/21）
采音点密度条（每个像素列统计落进来的 onset 数，归一化高度）
层位置细线（每一层一根浅色竖线）
区间色带（每个区间一条，选中态高亮，带名字）
播放头（黄线 + 顶部箭头）
底部独立一行：全曲时长 / 视窗 / 采音点数 / 区间数 / 选中格  +  操作提示
```

交互（★ 拖动语义已在 `docs/21` 改成 **Re_ADOJAS 的「格」导航**）：

| 操作 | 行为 |
|---|---|
| **左键按下 / 拖动** | **定位 + 选中该处的格**（连续 seek；`seek` 后 `floorAt` 反查格号） |
| **Shift + 拖动** | **框选一段** → 直接生成一个区间（实时显示 `a → b`；不会动到选中的格） |
| 点击色带 | 选中该区间（面板滚到它、预览条高亮） |
| 滚轮 / Shift+滚轮 | 以鼠标处为锚点缩放 / 平移 |
| 中键拖动 | 平移（缩放后看局部） |
| 双击 | 复位成"全曲" |

> 区间色带的命中测试用 `draw()` 里存下的 `this._bandRect`。**别在事件里重算**
> —— 原来两处公式不一致（`clamp(h*0.2,12,18)` vs `clamp(h*0.22,12,20)`），
> 点色带选中区间时灵时不灵，`docs/21` §3.1 里修掉了。

★ 时间轴口径：**这里是音频毫秒轴**（区间采音用的是 MIDI/音源时间），
而谱面视图用的是 entryTime 轴 —— 两者**不要混**。所以拖动定位走的是 `seek(ms)`
（`<audio>.currentTime`），跟四个谱面视图的播放头是同一根时钟。

## 3. 区间采音（★ 新功能）

### 3.1 语义

> **框出来的那一段时间，改用你指定的音轨采音；区间外仍走全局「② 音轨」的选择。**

它**只改「采哪些音」**，不动几何/时序逻辑 —— 所以求解器、模板、雪花、双押全部无感，
不需要为它改任何一条已验证的规则。

### 3.2 数据模型

```jsonc
state.regions = [
  { "start_ms": 19155, "end_ms": 35127,
    "tracks": [3],              // 用哪几条轨（可多选，取并集）
    "label": "B段" }            // 预览条色带上的名字
]
```

> **`mode` / `fill_gap_ms` 已在 `docs/23` 里删除**：主轨改成多选之后，
> 区间也统一成「这几条轨取并集」，不再有 主轨+补空白 / 单轨 / 多轨 的分流。

### 3.3 实现（`sidecar/session.py`）

在旧流水线的 **步骤 4 与步骤 5 之间**插了一步 4b：

```
全局 onset（步骤 4）
      │
      ├─ 对每个区间（按开始时间排序）：
      │    ① 用区间自己的 tracks + mode 采一遍（复用 build_onsets / _multi / _fill）
      │    ② 只留落在 [start, end) 里的
      │    ③ 把 out 里落在该区间的**全部**丢掉的 + 放进区间自己的
      │    ④ 区间重叠时「后写的赢」（因为 ③ 是"整段丢掉"）
      ▼
按 merge_ms 去重（区间边界两侧各有一个 onset 时只留最早 → 与 build_onsets 的合并语义一致）
      ▼
步骤 5 之后照旧（求解 / 双押 / 导出）
```

边界与特例：

- **允许全局一条都不勾、只用区间**（`used` 为空但区间非空 ⇒ 只从区间采）。
- 区间里的轨号若无效/没音 → 该区间记 `skipped`，不生效，不影响其它区间。
- 换文件后**区间作废**（时间是针对上一首的，留着没意义）—— 前端在 `doLoad` 里清空。
- `merged_notes`（钢琴卷帘的数据源）= 全局选中轨 ∪ 所有区间用到的轨，卷帘能同时看到两边。

### 3.4 前端

- ② 音轨分区里加了「区间采音」块：`＋ 加区间`（用当前勾选的轨，在播放头附近开一段）、
  `清空`、以及每个区间的编辑器：
  **名字** / **起止毫秒**（可手改，带时长）/ **用轨 chips**（点一下开关，按轨号+音符数显示，
  鼓轨虚线框）/ **模式下拉** / **✕ 删除**。
- 全曲条上 `Shift+拖动` 直接框出一段（默认用「当前勾选的轨」）。
- 状态栏报告「区间 N 段（M 段生效 / 共采 K 点）」。

区间采音的**精确断言**（`tests/test_sidecar.py` §7e/§7f）：

- 区间内的 onset **恰好等于**「该轨单独采、再按区间裁剪」的结果（逐点比对时间）
- 区间外仍是全局采音（没被清空）
- 回传的 `regions` 元信息带上实际生效的轨与采到的点数（预览条画色带要用）
- 全局不勾 + 有区间 ⇒ 仍能出谱，且**区间外一个 onset 都没有**

## 5. 取舍

- 区间是**时间窗 + 音轨集合**，不做「按层号框选」——层号在插双押后会整体后移，
  用它当锚点不稳定；时间窗跟预览条/播放头天然一致。
- 区间**不覆盖** `OnsetParams` 的其它项（合并窗口/音高范围…）——那些是整曲一致的
  检测参数，逐区间改会让"这一段为什么少了个音"变得难以归因。真要改，先改全局。
- `+ 加区间` 用播放头附近 ±2s/6s 开一段，是给"不想拖鼠标"的快捷入口；
  精确的就用 `Shift+拖动` 或直接改毫秒框。
