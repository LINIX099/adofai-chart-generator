## 1. 双押的本质

- ADOFAI **没有真双押**，所有双押都是**伪双押**
- 它是**几何**手法：用**极小的转角**制造"两下压在一起"的手感
- 判据不在行星，在**角度**

---

## 2. 速度决定角度（感知阈值）

| 速度 | 角度 |
|---|---|
| < 300 bpm | **15°** |
| ≥ 300 bpm | **30°** |

速度越快，15° 的偏折在同一时间窗里太"薄"，玩家分辨不出 → 要用 30° 补足感知。

### BPM 口径（**已统一，替代旧口径**）

旧口径（"行话 BPM = base_bpm ÷ 4"）是**为了效率做过的取舍**，现在统一为：

- **直接说「xxx bpm」→ 指 cbpm** = **我们代码里的 `base_bpm`**（写进 `settings.bpm`、编辑器显示的那个）
- **说「xxx bpm 的 xxx 分音」→ 指 tbpm** 带音符时值
- **tbpm = cbpm ÷ 4**

所以 **"300 bpm" 就是 cbpm 300，即我们的 `base_bpm = 300`**（已确认）。

> 交叉验证：旧口径下"拉链适用于 360bpm 以上" ⇒ base_bpm ≥ 1440。
> 新口径下等价表述是「**360bpm 的 16 分音**」⇒ tbpm 360 ⇒ cbpm 1440 ✓ 完全一致。
> 也就是说旧笔记里那句本来就是 tbpm 写法，只是当时被简化记成了"行话 BPM"。

### ⚠ 由此暴露的架构问题（**动工前必须定**）

`base_bpm` 是**求解器自己挑的**，同一首曲子在不同设置/不同路径下会落到不同八度：

- 实测 FallenEra 出现过 `119.84 / 180 / 359.5`
- 实测 Automaton_Waltz 出现过 `185 / 359.5 / 370`

如果 15°/30° 的判据是 **cbpm ≥ 300**，那**阈值会随求解器的任意选择而翻转**（同一段音乐，base 选 180 → 15°，选 359.5 → 30°）。

但物理上**按键速度由音乐决定，跟我们把 base_bpm 定在哪个八度无关**。

**需要定：判据用哪个量？**

| 选项 | 说明 |
|---|---|
| (a) cbpm（=`base_bpm`） | 实现简单，但受求解器选八度影响，阈值不稳定 |
| (b) 换算成与八度无关的物理速度 | 需要先定义"物理速度"是 tbpm 还是某段落的实际音值密度 |

这条直接决定架构形态，**动工前要定**。

## 3. 角度 ↔ 时值（近似，且差异本身就是偏移）

由 `travel = 180·r/k`（本项目已确认，`travel` 是角行程、`r` 是基准 BPM 的拍数）：

| travel | r（拍） | 45° 网格 | 15° 网格 |
|---|---|---|---|
| 180° | 1 | ✓ | ✓ |
| 90° | 1/2 | ✓ | ✓ |
| 60° | 1/3 | ✗ | ✓（三连音族） |
| 45° | 1/4 | ✓ | ✓ |
| **30°** | ≈1/6 | ✗ | ✓ |
| **15°** | ≈1/12 | ✗ | ✓ |

**15° 与 30° 都不在 45° 网格上，但在 15° 网格上。**

用户口径：*"可以这样理解，但是本质上不完全一样（会产生偏移）"* ——
所以 1/12、1/6 只是近似，**这个不一致本身就是双押时值偏移的来源**。

### 推论

- 双押 = 插入一个 **≈1/12 拍** 或 **≈1/6 拍**的"薄格"
- **1/6 拍 = 三连音十六分** ⇒ 与三连音连用不引入新音值，**"更省"**
- 与强弱拍连用同理：切在已有的八分/十六分边界上

## 7. 设计草案（口径已定）

### 7.1 已定参数

| 项 | 值 |
|---|---|
| 判据速度 | **cbpm**（= `base_bpm`）——"就用 cbpm，先把逻辑跑通" |
| 判据角度 | **转角 Δa**（不是 travel 相对 180° 的偏差） |
| < 300 cbpm | **15°** |
| ≥ 300 cbpm | **30°** |
| 时值近似 | **1/12、1/6 拍可直接用** |

### 7.2 几何对应

由 `_apply()`（唯一真源）：`turn = (180 - travel)` if ccw else `(travel + 180)`

| 转角 | travel | r（拍） | 相对一条直线格的差 |
|---|---|---|---|
| 0°（直线） | 180 | 1 | — |
| **±15°** | **165 / 195** | 11/12 | **∓1/12 拍** |
| **±30°** | **150 / 210** | 5/6 | **∓1/6 拍** |

所以"双押吃掉 ≈1/12 拍"指的是**相对一条直线格少 1/12 拍** ——
与"≈1/12 拍"的说法一致，不矛盾。

### 7.3 关键：插入双押会破坏闭合

README 不变量：`Σtravel ≡ 180n (mod 360)`

插入一个 15° 双押 → Σ 偏移 **∓15°** → **必须配一个反向的 ±15°** 才能回正。
30° 同理（∓30°）。

**这就是"双押写法非常多"的根源**：配对方式不同，落成谱面就是不同写法；
而**配对位置决定了它怎么和三连音、强弱拍咬合**（也决定了"更省"的程度）。

### 7.4 与"斜线"结论的关系 —— **要翻案**

我们早先量到：所有 off-45 网格的格子都停在 `a ∈ {30, 210, 330}`，
而且**偏角永不累积超过 ±15°**。

按新口径，这**正是 15° 双押成对出现的痕迹** —— 大概率不是 bug，是特征。
（原先我把它诊断成"漂移/斜线"，方向错了。）

- `travel = 180·r/speed_k`，`speed_k` 是 **BPM 除数**（`bpm = base_bpm / speed_k`）
- 项目实测：所有 off-45 网格的直线段都停在 `a ∈ {30, 210, 330}`，偏角**永不累积超过 ±15°**
